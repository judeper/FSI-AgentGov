# Plan 02-03: Wire Phase 1 PowerShell to Dataverse

## Objective

Implement the 8 CAAClient.psm1 function stubs with actual Dataverse Web API CRUD operations, wire Test-PolicyCompliance.ps1 to persist results and violations to Dataverse, and enable reading operational parameters from Dataverse environment variables. This connects the Phase 1 PowerShell scripts to Phase 2's Dataverse infrastructure.

## Tasks

### Task 1: Implement CAAClient.psm1 Functions

**Modify** `scripts/private/CAAClient.psm1`

Replace all 8 `throw "Not implemented"` stubs with working Dataverse Web API implementations using `Invoke-RestMethod`:

**Module-scoped state:**
```powershell
$script:DataverseUrl = $null
$script:AccessToken = $null
$script:Headers = $null
```

| # | Function | Implementation |

| 3 | `Get-CAAEnvironmentVariable -Name` | `GET /api/data/v9.2/environmentvariabledefinitions?$filter=schemaname eq 'fsi_CAA_{Name}'&$expand=environmentvariablevalues`. Return current value (from `environmentvariablevalues[0].value`) or default value if no override. |
| 4 | `Get-CAAActiveBaseline [-PolicyId] [-TenantId]` | `GET /api/data/v9.2/fsi_capolicybaselines?$filter=fsi_is_active eq true` with optional `fsi_policy_id` and `fsi_tenant_id` filters. Return array of baseline objects. |

| 8 | `Get-CAALastValidation [-TenantId]` | `GET /api/data/v9.2/fsi_capolicyvalidationhistory?$orderby=fsi_validation_time desc&$top=1` with optional tenant filter. Return single validation record or `$null`. |

**Error handling pattern:**
```powershell
try {
    $response = Invoke-RestMethod -Uri $uri -Headers $script:Headers -Method Get
    return $response.value
}
catch {
    Write-Warning "CAAClient: Failed to query $entitySet — $($_.Exception.Message)"
    return $null
}
```

**ShouldProcess pattern (write operations):**
```powershell
if ($PSCmdlet.ShouldProcess("fsi_capolicyvalidationhistory", "Create validation record $RunId")) {
    $response = Invoke-RestMethod -Uri $uri -Headers $script:Headers -Method Post -Body ($body | ConvertTo-Json -Depth 10) -ContentType 'application/json'
}
```

**Acceptance criteria:**
- All 8 functions implemented with Dataverse Web API calls
- Module-scoped connection state works across function calls
- Write operations gated by `ShouldProcess` (supports `-WhatIf`)
- Graceful error handling — warns and returns `$null` instead of terminating
- `Save-CAABaseline` deactivates previous baselines before creating new one
- `Get-CAAEnvironmentVariable` returns default value when no override exists
- OData filter/select/orderby correctly built for each query

### Task 2: Wire Test-PolicyCompliance.ps1 to Dataverse

**Modify** `scripts/Test-PolicyCompliance.ps1`

Add optional Dataverse persistence parameters and logic:

**New parameters:**
- `-DataverseUrl [string]` — Dataverse environment URL (enables persistence)
- `-DataverseToken [string]` — Access token for Dataverse auth
- `-PersistResults [switch]` — Write validation results and violations to Dataverse

**New logic (after all compliance checks complete):**

```
IF -DataverseUrl AND -PersistResults:
  1. Import CAAClient.psm1 (if not already)
  2. Connect-CAADataverse with provided URL and token
  3. Read operational parameters:
     - GracePeriodHours from Get-CAAEnvironmentVariable
     - BaselineMaxAgeDays from Get-CAAEnvironmentVariable
     - DriftSeverityEscalation from Get-CAAEnvironmentVariable
     - IncludeReportOnlyPolicies from Get-CAAEnvironmentVariable
  4. Generate RunId (New-Guid)
  5. Write-CAAValidationHistory with aggregated results
  6. FOR EACH violation in complianceResults:
     Write-CAAViolation with details
  7. Write-Verbose "Persisted {N} results and {M} violations to Dataverse (RunId: {guid})"

IF -DataverseUrl AND NOT -PersistResults:
  Write-Verbose "Dataverse URL provided but -PersistResults not specified. Results not persisted."

IF NOT -DataverseUrl AND -PersistResults:
  Write-Warning "Cannot persist results: -DataverseUrl is required with -PersistResults"
```

**Graceful fallback:** If Dataverse connection fails, warn and continue — compliance check results are still returned to the console/pipeline. Dataverse persistence is best-effort.

**Acceptance criteria:**
- New parameters added without breaking existing functionality
- Dataverse persistence is opt-in (requires both `-DataverseUrl` and `-PersistResults`)
- Operational parameters read from Dataverse environment variables when connected
- RunId correlation links validation history to violations
- Graceful degradation — Dataverse failures don't block compliance results
- All existing tests/behaviors unchanged when new parameters not provided
- Help block updated with new parameters and examples
