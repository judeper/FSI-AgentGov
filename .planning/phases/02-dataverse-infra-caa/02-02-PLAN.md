# Plan 02-02: Environment Variables, Connection References, and Deploy Orchestrator

## Objective

Create the environment variable deployment script (`fsi_CAA_*` prefix), connection reference deployment script (`fsi_cr_*` naming), and the `deploy.py` orchestrator that sequences all Phase 2 deployment steps with selective execution modes and post-deployment guidance.

## Tasks

### Task 1: Create `create_environment_variables.py`

**Create** `scripts/create_environment_variables.py`

Define 7 environment variables with the `fsi_CAA_*` prefix:

| Schema Name | Display Name | Type | Default | Purpose |
|-------------|-------------|------|---------|---------|
| `fsi_CAA_GracePeriodHours` | CAA - Grace Period (Hours) | Decimal (100000001) | 48 | Hours before newly deployed policies are included in validation |
| `fsi_CAA_ScanFrequencyHours` | CAA - Scan Frequency (Hours) | Decimal (100000001) | 24 | Automated compliance scan interval for Phase 3 flow |
| `fsi_CAA_BaselineMaxAgeDays` | CAA - Maximum Baseline Age (Days) | Decimal (100000001) | 30 | Alert threshold for stale baselines requiring refresh |
| `fsi_CAA_DriftSeverityEscalation` | CAA - Drift Severity Escalation | String (100000000) | true | Whether Zone 3 drift violations receive severity +1 |
| `fsi_CAA_IncludeReportOnlyPolicies` | CAA - Include Report-Only Policies | String (100000000) | true | Whether report-only CA policies are included in validation scans |
| `fsi_CAA_TeamsGroupId` | CAA - Teams Alert Group ID | String (100000000) | (empty) | Microsoft Teams group GUID for violation alert delivery |
| `fsi_CAA_TeamsChannelId` | CAA - Teams Alert Channel ID | String (100000000) | (empty) | Microsoft Teams channel GUID for violation alert delivery |

**Functions:**
- `ENVIRONMENT_VARIABLES` — List of dicts with `schema_name`, `display_name`, `type`, `default_value`, `description`
- `create_environment_variable(client, var_def, dry_run)` — Idempotent: query by schema name → skip if exists → create with default value if not
- `create_environment_variables(client, dry_run)` — Iterate all 7, report status
- `main()` — CLI with `--dry-run`, `--verbose`, auth args

**Idempotent pattern:**
```python
existing = client.query(
    "environmentvariabledefinitions",
    filter=f"schemaname eq '{var_def['schema_name']}'"
)
if existing["value"]:
    print(f"  {var_def['schema_name']}: already exists, skipping")
    return
```

**Acceptance criteria:**
- All 7 variables defined with correct types (Decimal vs String)
- Default values match the table above
- Idempotent — re-running skips existing variables
- `--dry-run` reports what would be created
- Empty string defaults for TeamsGroupId/TeamsChannelId (operator configures post-deployment)

### Task 2: Create `create_connection_references.py`

**Create** `scripts/create_connection_references.py`

Define 4 connection references with `fsi_cr_*` naming:

| Logical Name | Display Name | Connector ID | Purpose |
|-------------|-------------|-------------|---------|
| `fsi_cr_dataverse_conditionalaccessautomation` | Dataverse - Conditional Access Automation | `shared_commondataserviceforapps` | Table CRUD for baselines, history, violations |
| `fsi_cr_office365_conditionalaccessautomation` | Office 365 - Conditional Access Automation | `shared_office365` | Email notification delivery |
| `fsi_cr_teams_conditionalaccessautomation` | Teams - Conditional Access Automation | `shared_teams` | Adaptive card alert delivery |
| `fsi_cr_graph_conditionalaccessautomation` | Microsoft Graph - Conditional Access Automation | `shared_microsoftgraphconnector` | CA policy reads from Power Automate flows |

**Functions:**
- `CONNECTION_REFERENCES` — List of dicts with `logical_name`, `display_name`, `connector_id`, `description`
- `create_connection_reference(client, ref_def, dry_run)` — Idempotent: query by `connectionreferencelogicalname` → skip if exists → create if not
- `create_connection_references(client, dry_run)` — Iterate all 4, report status
- `main()` — CLI with `--dry-run`, `--verbose`, auth args

**Note on Graph connector:** The `shared_microsoftgraphconnector` connector ID is used per the requirement specification. This is new to the Tier 2 pattern (all prior solutions used only 3 connectors). If the connector ID is incorrect, deployment will fail cleanly with an error message — the script should catch this and advise the operator to verify the connector ID in Power Automate → Connections.

**Acceptance criteria:**
- All 4 connection references defined
- Idempotent — re-running skips existing references
- `--dry-run` reports what would be created
- Error handling for invalid connector IDs (catch 400/404 and print guidance)

### Task 3: Create `deploy.py` — Deployment Orchestrator

**Create** `scripts/deploy.py`

Sequences all Phase 2 deployment steps with selective execution:

**Steps:**
1. Test connection (`GET /api/data/v9.2/organizations`)
2. Deploy Dataverse schema (calls `create_dataverse_schema.create_schema`)
3. Deploy environment variables (calls `create_environment_variables.create_environment_variables`)
4. Deploy connection references (calls `create_connection_references.create_connection_references`)
5. Print post-deployment guidance

**CLI arguments:**
- `--tenant-id` | env `CAA_TENANT_ID`
- `--client-id` | env `CAA_CLIENT_ID`
- `--client-secret` | env `CAA_CLIENT_SECRET`
- `--environment-url` | env `CAA_ENVIRONMENT_URL`
- `--interactive` — Use interactive (delegated) auth instead of service principal
- `--dry-run` — Preview all changes without executing
- `--tables-only` — Deploy only Dataverse schema
- `--vars-only` — Deploy only environment variables
- `--refs-only` — Deploy only connection references
- `--verbose` — Detailed output

**Post-deployment guidance (printed to console):**
```
═══════════════════════════════════════════════════════════
 Post-Deployment Steps
═══════════════════════════════════════════════════════════

 1. SECURITY: Remove Write/Delete permissions on
    fsi_CAPolicyValidationHistory for non-system users
    (immutable audit trail)

 2. CONNECTIONS: Open Power Automate → Solutions →
    Bind each connection reference to an authenticated connection:
    - fsi_cr_dataverse_conditionalaccessautomation
    - fsi_cr_office365_conditionalaccessautomation
    - fsi_cr_teams_conditionalaccessautomation
    - fsi_cr_graph_conditionalaccessautomation

 3. TEAMS: Configure fsi_CAA_TeamsGroupId and
    fsi_CAA_TeamsChannelId environment variables with
    your target Teams group/channel GUIDs

 4. VERIFY: Re-run with --dry-run to confirm all
    artifacts exist:
    python deploy.py --dry-run

═══════════════════════════════════════════════════════════
```

**Acceptance criteria:**
- All 4 steps execute in sequence
- Selective flags (`--tables-only`, `--vars-only`, `--refs-only`) work correctly
- `--dry-run` mode propagated to all sub-modules
- Post-deployment guidance printed on successful completion
- Connection test runs first and blocks deployment if it fails
- Exit code 0 on success, 1 on failure
