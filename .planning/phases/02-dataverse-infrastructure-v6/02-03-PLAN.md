# Plan 02-03: Wire Phase 1 PowerShell Scripts to Dataverse

## Goal

Connect the Phase 1 PowerShell validation pipeline to the Dataverse infrastructure from Plans 02-01 and 02-02. When operators provide `-DataverseUrl`, the orchestrator reads operational parameters from Dataverse environment variables, persists validation results, and writes individual violations — while gracefully falling back to standalone mode when Dataverse is unavailable.

## Tasks

### Task 1: Add Dataverse parameters to Test-AgentAccessCompliance.ps1

Add optional Dataverse integration parameters to the validation orchestrator:

**New parameters:**
```powershell
[Parameter(Mandatory = $false)]
[string]$DataverseUrl,

[Parameter(Mandatory = $false)]
[string]$DataverseToken,

[Parameter(Mandatory = $false)]

```

**Behavior matrix:**

| Parameters | Behavior |
|-----------|----------|
| No Dataverse params | Standalone mode (unchanged from Phase 1) |
| `-DataverseUrl` only | Read env vars from Dataverse, no persistence |
| `-DataverseUrl -PersistResults` | Full integration: read env vars + persist results |
| `-DataverseUrl -PersistResults -WhatIf` | Preview what would be persisted without writing |

**Acceptance Criteria:**
- [ ] New parameters added without breaking existing parameter sets
- [ ] Standalone mode (no -DataverseUrl) works exactly as Phase 1
- [ ] -WhatIf preview shows Dataverse write operations

### Task 2: Wire Dataverse environment variable reads

When `-DataverseUrl` is provided, import AAMClient.psm1 and read operational parameters:

```powershell
if ($DataverseUrl) {
    Import-Module "$PSScriptRoot/private/AAMClient.psm1" -Force
    Connect-AAMDataverse -DataverseUrl $DataverseUrl -AccessToken $DataverseToken

    # Read operational parameters from Dataverse env vars
    $gracePeriod = Get-AAMEnvironmentVariable -Name "GracePeriodHours" -DefaultValue 48
    $scanFrequency = Get-AAMEnvironmentVariable -Name "ScanFrequencyHours" -DefaultValue 24
    $includeSandbox = Get-AAMEnvironmentVariable -Name "IncludeSandbox" -DefaultValue "false"
    $baselineMaxAge = Get-AAMEnvironmentVariable -Name "BaselineMaxAgeDays" -DefaultValue 30

    Write-Verbose "Dataverse parameters loaded: GracePeriod=$gracePeriod, ScanFrequency=$scanFrequency"
}
```

**Graceful fallback:** If Dataverse query fails, log a warning and use defaults from zone-settings-baseline.json:
```powershell
try {
    $gracePeriod = Get-AAMEnvironmentVariable -Name "GracePeriodHours" -DefaultValue 48
} catch {
    Write-Warning "Cannot read from Dataverse: $_. Using default grace period (48 hours)."
    $gracePeriod = 48
}
```

**Acceptance Criteria:**
- [ ] Reads GracePeriodHours, ScanFrequencyHours, IncludeSandbox, BaselineMaxAgeDays from Dataverse
- [ ] Falls back to defaults when Dataverse is unavailable
- [ ] Parameters are used by Get-EnvironmentAccessSettings (grace period, sandbox inclusion)

**File:** `agent-access-monitor/scripts/Test-AgentAccessCompliance.ps1` (MODIFY)

### Task 3: Update AAMClient.psm1 function signatures

The existing `Write-AAMValidationHistory` and `Write-AAMViolation` functions need updates to accept a `-RunId` parameter and populate required Dataverse columns (`fsi_name` and `fsi_run_id`).

**Write-AAMValidationHistory updates:**
- Add `-RunId [string]` parameter (mandatory)
- Set `fsi_run_id = $RunId` in record body
- Set `fsi_name = "$($ValidationResult.OverallStatus)-$(Get-Date -Format 'yyyy-MM-ddTHH:mm:ssZ')"` in record body

```powershell
function Write-AAMValidationHistory {
    param(
        [Parameter(Mandatory)]
        [hashtable]$ValidationResult,

        [Parameter(Mandatory)]
        [string]$RunId
    )
    # ... existing connection check ...
    $record = @{
        fsi_name              = "$($ValidationResult.OverallStatus)-$(Get-Date -Format 'yyyy-MM-ddTHH:mm:ssZ')"
        fsi_run_id            = $RunId
        fsi_validation_time   = (Get-Date).ToUniversalTime().ToString('o')
        fsi_total_environments = $ValidationResult.TotalEnvironments
        fsi_compliant_count   = $ValidationResult.CompliantCount
        fsi_violation_count   = $ValidationResult.ViolationCount
        fsi_overall_status    = $ValidationResult.OverallStatus
        fsi_summary_json      = $ValidationResult | ConvertTo-Json -Depth 10 -Compress
    }
}
```

**Write-AAMViolation updates:**
- Add `-RunId [string]` parameter (optional)
- Set `fsi_name = "$($Violation.Zone)-$($Violation.ViolationType)-$(Get-Date -Format 'yyyy-MM-dd')"` in record body
- If RunId provided, set `fsi_run_id = $RunId`

```powershell
function Write-AAMViolation {
    param(
        [Parameter(Mandatory)]
        [hashtable]$Violation,

        [Parameter()]
        [string]$RunId
    )
    # ... existing record body ...
    $record['fsi_name'] = "$($Violation.Zone)-$($Violation.ViolationType)-$(Get-Date -Format 'yyyy-MM-dd')"
    if ($RunId) { $record['fsi_run_id'] = $RunId }
}
```

**Acceptance Criteria:**
- [ ] Write-AAMValidationHistory accepts -RunId and sets fsi_run_id and fsi_name
- [ ] Write-AAMViolation accepts -RunId and sets fsi_name
- [ ] Existing callers (none yet — Phase 1 doesn't call these) are unaffected
- [ ] Both functions still export via Export-ModuleMember

**File:** `agent-access-monitor/scripts/private/AAMClient.psm1` (MODIFY)

### Task 4: Wire validation result persistence

After the validation pipeline completes, persist results to Dataverse when `-PersistResults` is provided:

```powershell
if ($DataverseUrl -and $PersistResults) {
    $runId = [guid]::NewGuid().ToString()

    # Write summary to validation history (immutable)
    if ($PSCmdlet.ShouldProcess("fsi_accessvalidationhistory", "Write validation summary")) {
        try {
            Write-AAMValidationHistory -ValidationResult $validationResults -RunId $runId
            Write-Verbose "Validation history written: RunId=$runId"
        } catch {
            Write-Warning "Failed to write validation history: $_"
        }
    }

    # Write individual violations
    foreach ($violation in $violations) {
        if ($PSCmdlet.ShouldProcess("fsi_accessviolations", "Write violation: $($violation.Environment)")) {
            try {
                Write-AAMViolation -Violation $violation -RunId $runId
            } catch {
                Write-Warning "Failed to write violation for $($violation.Environment): $_"
            }
        }
    }
}
```

**Critical design decisions:**
- Each Dataverse write is wrapped in try/catch — failures write warnings, never abort
- WhatIf/ShouldProcess gates all write operations
- RunId correlates all records from a single scan
- Validation history uses the summary metrics from Test-AgentAccessCompliance output

**Acceptance Criteria:**
- [ ] Validation results written to fsi_accessvalidationhistory with RunId correlation
- [ ] Individual violations written to fsi_accessviolations with RunId correlation
- [ ] ShouldProcess/-WhatIf gates all Dataverse writes
- [ ] Failures write warnings, never abort the script
- [ ] No writes occur when -PersistResults is not specified

**File:** `agent-access-monitor/scripts/Test-AgentAccessCompliance.ps1` (MODIFY)
