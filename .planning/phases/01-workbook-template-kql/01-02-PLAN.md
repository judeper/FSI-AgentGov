## Tasks

### Task 1: Build Tab 3 — Operational Health

**Action:** Add 7 visualization items to the workbook JSON under the Tab 3 group in `src/agent-usage-workbook.json`.

**Visualizations:**

| # | Title | Type | KQL Summary |
|---|-------|------|-------------|
| 1 | Session Volume Anomaly Detection | Anomaly chart | `series_decompose_anomalies()` on hourly `dcount(session_Id)` over 14-day lookback |
| 2 | Availability (Uptime Trend) | Timechart (area) | Hourly session count — gaps indicate downtime periods |
| 3 | Exception Spike Detection | Anomaly chart | `series_decompose_anomalies()` on hourly `exceptions` count |
| 4 | Generative Answers Quality | Tiles (KPI) | GenAI event volume, proportion of total interactions |
| 5 | Dependency Health | Table (grid) | External dependency success rates and latency from `dependencies` table |
| 6 | DLP / Security Events | Tiles + table | Security-relevant event patterns (requires custom telemetry; show placeholder with guidance) |
| 7 | Agent Health Summary | Tiles (per-agent, conditional formatting) | Composite per-agent: sessions, errors, est. latency with red/yellow/green thresholds |

**Special handling:**
- Anomaly detection: Use `make-series` → `series_decompose_anomalies(metric, 1.5)` with `render anomalychart` (14-day default lookback, adjustable via parameter)
- Dependency health: Target `dependencies` table — this is populated when Copilot Studio calls external connectors/APIs
- DLP events: Native Copilot Studio telemetry does NOT include DLP details. Add a markdown explanation noting that DLP event visibility requires either custom telemetry or Purview Audit Log integration. Include placeholder query structure for organizations that implement custom DLP logging.
- Agent health summary: Composite query joining session count, error count, and estimated latency per agent with threshold-based conditional formatting (green >99% success, yellow 95-99%, red <95%)

**Acceptance criteria:**
- [ ] 7 visualization items in Tab 3 group
- [ ] Anomaly detection queries use `series_decompose_anomalies()` with configurable sensitivity
- [ ] Dependency health query targets `dependencies` table
- [ ] DLP section includes markdown explanation of telemetry limitations
- [ ] Agent health summary uses conditional formatting with threshold values
- [ ] All queries respect global parameters (TimeRange, AgentFilter, ChannelFilter)

### Task 3: Comprehensive KQL query validation

**Action:** Validate all 23 visualization queries + 2 parameter population queries (25 total) against the documented Copilot Studio Application Insights schema.

**Validation dimensions:**

| Dimension | Check | Pass Criteria |
|-----------|-------|---------------|
| **Table references** | Every `from` clause references a valid table | Only `customEvents`, `exceptions`, `dependencies`, `pageViews` used |
| **Field references** | All `customDimensions.*` fields match schema | Only fields from research §4.3 used: `session_Id`, `channelId`, `fromId`, `recipientName`, `designMode`, `TopicName`, `type`, `Kind`, `text`, `locale` |
| **Event name filters** | All `name ==` filters use valid event names | Only: `BotMessageReceived`, `BotMessageSend`, `TopicStart`, `TopicEnd`, `Action`, `GenerativeAnswers` |
| **Parameter references** | All `{Param}` tokens resolve to global parameters | `{TimeRange}`, `{AgentFilter}`, `{ChannelFilter}`, `{MinutesSaved}`, `{HourlyRate}` only |
| **KQL syntax** | Valid operator chains | Proper pipe `\|` usage, valid function calls, correct `summarize`/`extend`/`project` syntax |
| **Visualization alignment** | Chart type matches data shape | Timechart = time-binned, piechart = categorical, tiles = scalar, table = multi-column |
| **Design mode filter** | Test data excluded | All queries contain `designMode == "False"` |
| **No traces table** | Not using Agent 365 SDK schema | Zero references to `traces` table |

**Validation output format:**
```
## Validation Results

Total queries: 25
Passed: XX
Failed: XX

### Failures (if any)
| Query | Tab | Issue | Fix |
|-------|-----|-------|-----|
```

**Acceptance criteria:**
- [ ] All 25 queries validated across all 8 dimensions
- [ ] Zero failures (or all failures resolved before plan completion)
- [ ] Validation results documented in plan summary
