## Objective

Build the Azure Monitor Workbook JSON template with global parameters, Tab 1 (Usage & Business Value), and Tab 2 (Performance & Errors). This plan delivers 16 KQL queries across two tabs plus 5 parameter declarations targeting native Copilot Studio Application Insights telemetry.

## Context

- **Phase goal:** Build the core Azure Monitor Workbook JSON template with validated KQL queries
- **This plan delivers:** Tabs 1 and 2 of 3, plus the complete workbook shell (parameters, fallbackResourceIds, metadata)
- **Telemetry source:** Native Copilot Studio `customEvents` table (NOT Agent 365 SDK `traces` table)
- **Research:** See 01-RESEARCH.md §3 (Technical Approach), §4 (Telemetry Schema), §7 (Tab Structure)

## Tasks

### Task 1: Create workbook JSON shell with global parameters

**Action:** Create `src/agent-usage-workbook.json` with the top-level workbook structure and global parameter group.

**Details:**
- Root structure: `$schema`, `version: "Notebook/1.0"`, `items[]`, `fallbackResourceIds[]`, `isLocked: false`
- Global parameters (type 9): TimeRange (type 4, default 24h), AgentFilter (type 2, KQL-populated), ChannelFilter (type 2, KQL-populated), MinutesSaved (type 1, default 5), HourlyRate (type 1, default 75)
- Tab selector parameter (type 2, static values: "Usage & Business Value", "Performance & Errors", "Operational Health")
- All parameter population queries follow KQL design principles from research (filter `designMode == "False"`, time-scoped)

**Acceptance criteria:**
- [ ] Valid JSON file at `src/agent-usage-workbook.json`
- [ ] 5 global parameters declared with correct types and defaults
- [ ] Tab selector parameter with 3 tab options
- [ ] `fallbackResourceIds` contains parameterized subscription/resource-group/app-insights path
- [ ] Agent filter population query uses `dcount(recipientName)` from `customEvents`
- [ ] Channel filter population query uses `distinct(channelId)` from `customEvents`

### Task 2: Build Tab 1 — Usage & Business Value

**Action:** Add 8 visualization items to the workbook JSON under the Tab 1 group.

**Visualizations:**

| # | Title | Type | KQL Summary |
|---|-------|------|-------------|
| 1 | Session Volume Trend | Timechart (area) | `dcount(session_Id)` by `bin(timestamp, 1d)` from `customEvents` |
| 2 | Daily / Monthly Active Users | Timechart (dual-axis) | `dcount(fromId)` daily + monthly from `customEvents` |
| 3 | Channel Breakdown | Piechart | `count()` by `channelId` from `customEvents` |
| 4 | Top Topics by Engagement | Barchart (horizontal) | `count()` by `TopicName` where `name == "TopicStart"`, top 10 |
| 5 | Resolution Rate | Tiles (KPI) | Sessions with `TopicEnd` ÷ total sessions |
| 6 | Avg Messages per Session | Tiles (KPI) | `count(BotMessageReceived)` ÷ `dcount(session_Id)` |
| 7 | Assisted Hours Estimate | Tiles (KPI) | `dcount(session_Id)` × `{MinutesSaved}` ÷ 60 |
| 8 | Business Value Summary | Tiles (4-wide) | Sessions, est. hours saved, FTE equivalent, cost avoidance |

**KQL design rules:**
- All queries start with time filter: `| where timestamp {TimeRange}`
- Filter test conversations: `| where customDimensions.designMode == "False"`
- Apply agent/channel filters using `{AgentFilter}` / `{ChannelFilter}` parameters
- Include regulatory reference comments (e.g., `// FINRA 4511: Agent usage volume`)
- Use `tostring(customDimensions.session_Id)` for session grouping

**Acceptance criteria:**
- [ ] 8 visualization items in Tab 1 group
- [ ] All queries filter `designMode == "False"`
- [ ] All queries respect TimeRange, AgentFilter, ChannelFilter parameters
- [ ] Business value calculations use MinutesSaved and HourlyRate parameters
- [ ] Resolution rate documented as estimate (based on topic completion proxy)
- [ ] Each query includes regulatory reference comment

### Task 3: Build Tab 2 — Performance & Errors

**Action:** Add 8 visualization items to the workbook JSON under the Tab 2 group.

**Visualizations:**

| # | Title | Type | KQL Summary |
|---|-------|------|-------------|
| 1 | Response Latency (P50/P95/P99) | Timechart (multi-line) | Timestamp delta between sequential `BotMessageReceived` → `BotMessageSend` pairs |
| 2 | Error Rate Trend | Timechart (area) | `count()` on `exceptions` by `bin(timestamp, 1h)` |
| 3 | Error Types Breakdown | Barchart (stacked) | `count()` by error `type` from `exceptions` |
| 4 | Connector/Action Success Rate | Table (grid) | Success/failure ratio per action from `customEvents` where `name == "Action"` |
| 5 | Generative AI Usage | Timechart | `count()` from `customEvents` where `name == "GenerativeAnswers"` |
| 6 | Topic Completion Rate | Table (grid) | `TopicEnd` ÷ `TopicStart` ratio per topic |
| 7 | RAI Content Filtering | Tiles + trend | Content filter event volume (estimated from `GenerativeAnswers` events with filtered indicators) |
| 8 | Fallback/Escalation Volume | Timechart | Sessions containing escalation-related topic names |

**Special handling:**
- Latency estimation: Use `serialize` + `prev()` pattern per research §7 — pair `BotMessageReceived` → `BotMessageSend` within same session, filter outliers >2min
- RAI filtering: Note that native Copilot Studio telemetry has limited RAI detail — document this as "requires custom telemetry for full RAI visibility" 
- Fallback detection: Use heuristic (topic names containing "Escalate", "Transfer", "Handoff")

**Acceptance criteria:**
- [ ] 8 visualization items in Tab 2 group
- [ ] Latency estimation query uses `serialize`/`prev()` pattern with outlier filtering
- [ ] Error queries target `exceptions` table (not `customEvents`)
- [ ] Connector success query targets `customEvents` where `name == "Action"`
- [ ] All queries respect global parameters
- [ ] RAI limitation documented as JSON comment in visualization title/subtitle
