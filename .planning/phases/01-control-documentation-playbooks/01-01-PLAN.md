## Tasks

### Task 1: Create Control 2.22 document

**File:** `docs/controls/pillar-2-management/2.22-inactivity-timeout-enforcement.md`

**Acceptance criteria:**

1. **Header metadata** contains all required fields:
   - Control ID: 2.22
   - Pillar: Management
   - Regulatory Reference: GLBA 501(b), SOX 302, FINRA 4511, NIST 800-53 AC-11/AC-12
   - Last UI Verified: February 2026
   - Governance Levels: Baseline / Recommended / Regulated
   - Last Verified: 2026-02-12

2. **Section 1 — Objective:** Single paragraph stating purpose of inactivity timeout enforcement for Power Platform environments with policy-driven maximum duration requirements

3. **Section 2 — Why This Matters for FSI:** Bulleted list with hedged language for:
   - **GLBA 501(b):** Information safeguards — automatic session termination after inactivity supports protection of customer financial data
   - **SOX 302:** Management responsibility — timeout enforcement aids in maintaining internal controls over financial reporting systems
   - **FINRA 4511:** Record-keeping — session timeout configuration contributes to supervisory record integrity
   - **NIST 800-53 AC-11:** Session lock — supports automatic session lock after defined inactivity period
   - **NIST 800-53 AC-12:** Session termination — supports automatic termination of user sessions after inactivity

4. **Section 3 — Control Description:** Multi-paragraph technical explanation including:
   - Purpose: Governance of Power Platform user inactivity timeout settings
   - Mechanism: BAP Admin API privacy settings endpoint for per-environment configuration
   - Policy-driven approach: Zone requirements stored in `fsi_environmentpolicy` Dataverse table
   - Compliance evaluation: Automated scan comparing actual timeout against policy maximum
   - Missing policy handling: Environments without policy → Unknown status (no silent defaults)
   - Capability table:

     | Capability | Description | Implementation |
     |------------|-------------|----------------|
     | **Policy Management** | Zone-based maximum timeout duration | Dataverse `fsi_environmentpolicy` table |
     | **Compliance Detection** | Automated per-environment timeout evaluation | Cloud Flow with BAP Admin API |
     | **Remediation** | PowerShell script for BAP Admin API PATCH | `Set-InactivityTimeout.ps1` |
     | **Audit Trail** | Immutable compliance records per scan | Dataverse `fsi_inactivitytimeout_compliance` table |
     | **Error Logging** | API and policy errors tracked | Dataverse `fsi_inactivitytimeout_errorlog` table |

   - `!!! info "System Configuration Control"` admonition:
     This control governs an actual Power Platform environment setting (Privacy + Security → Inactivity Timeout). Unlike process-based controls, this setting is configurable through the BAP Admin API and the Power Platform Admin Center, enabling automated validation and remediation.

   - SSC scope distinction:
     `!!! tip "Relationship to Session Security Configurator (Control 1.23)"` —
     Control 1.23 governs Conditional Access policies and session authentication controls (sign-in frequency, persistent browser sessions). Control 2.22 governs Power Platform inactivity timeout duration — a separate setting managed through the BAP Admin API privacy endpoint, not through Entra ID/Graph API.

5. **Section 4 — Key Configuration Points:** Grouped by category:

   **PPAC Environment Settings:**
   - Enable inactivity timeout for each environment in PPAC → Privacy + Security
   - Set timeout duration value (minutes) per environment
   - Configure warning duration before session timeout (user prompt)

   **Policy Configuration (Dataverse):**
   - Define per-environment zone classification in `fsi_environmentpolicy` table
   - Set `fsi_requiredmaxduration` (minutes) per environment per zone requirements
   - Zone 2 environments: maximum 120 minutes
   - Zone 3 environments: maximum 60 minutes

   **Automated Compliance:**
   - Deploy Detect-InactivityTimeout-NonCompliance flow for daily scanning
   - Configure concurrency limit for parallel environment evaluation (default 5)
   - Set notification recipients for non-compliant environment alerts

6. **Section 5 — Zone-Specific Requirements:**

   | Zone | Requirement | Rationale |
   |------|-------------|-----------|
   | **Zone 1** (Personal) | Inactivity timeout optional; recommended ≤120 minutes if enabled | Personal productivity agents have lower risk; timeout enhances baseline security posture |
   | **Zone 2** (Team) | Inactivity timeout required; maximum 120 minutes | Team collaboration environments process shared data requiring session timeout controls |
   | **Zone 3** (Enterprise) | Inactivity timeout required; maximum 60 minutes | Customer-facing and enterprise agents require stricter session controls per NIST AC-11/AC-12 |

7. **Section 6 — Roles & Responsibilities:**

   | Role | Responsibility |
   |------|----------------|
   | Power Platform Admin | Configure inactivity timeout settings in PPAC; execute remediation scripts |
   | Environment Admin | Manage environment-level timeout configuration |
   | AI Governance Lead | Define zone policy requirements; review compliance scan results |
   | Compliance Officer | Review compliance reports; provide audit attestation |
