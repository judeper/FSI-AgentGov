## Tasks

### Task 1: Create portal-walkthrough playbook

**File:** `docs/playbooks/control-implementations/2.22/portal-walkthrough.md`

**Acceptance criteria:**

1. Title: `# Portal Walkthrough: Control 2.22 - Inactivity Timeout Enforcement`
2. Metadata: Last Updated (February 2026), Portal (Power Platform Admin Center), Estimated Time (15-20 minutes per environment)
3. Prerequisites checkbox list:
   - Power Platform Admin or Environment Admin role
   - Access to Power Platform Admin Center (admin.powerplatform.microsoft.com)
   - Knowledge of organizational zone classification for target environments
   - Zone policy requirements documented (Zone 2 ≤120 min, Zone 3 ≤60 min)
4. Step-by-step sections (`### Step N:`) covering:
   - Step 1: Navigate to PPAC environment list
   - Step 2: Select target environment → Settings → Privacy + Security
   - Step 3: Locate Inactivity Timeout section
   - Step 4: Enable inactivity timeout toggle
   - Step 5: Set timeout duration (minutes) per zone requirements
   - Step 6: Configure warning duration (minutes before timeout prompt)
   - Step 7: Save settings and verify
5. Governance settings table by zone:

   | Setting | Zone 1 (Personal) | Zone 2 (Team) | Zone 3 (Enterprise) |
   |---------|-------------------|---------------|---------------------|
   | Inactivity Timeout | Optional | Required | Required |
   | Maximum Duration | ≤120 min (if enabled) | ≤120 min | ≤60 min |
   | Warning Duration | 5 min (recommended) | 5 min | 5 min |

6. Validation checklist at bottom:
   - [ ] Inactivity timeout is enabled
   - [ ] Duration does not exceed zone maximum
   - [ ] Warning duration is configured
   - [ ] Settings saved successfully
7. Footer navigation links to other playbooks
8. FSI-safe language throughout

### Task 2: Create powershell-setup playbook

**File:** `docs/playbooks/control-implementations/2.22/powershell-setup.md`

**Acceptance criteria:**

1. Title: `# PowerShell Setup: Control 2.22 - Inactivity Timeout Enforcement`
2. Metadata: Last Updated (February 2026), Modules Required (none — standalone script)
3. Prerequisites checkbox list:
   - PowerShell 7.0 or later
   - Service principal with BAP Admin API permissions (`https://api.bap.microsoft.com/.default`)
   - `Set-InactivityTimeout.ps1` script (from solution deployment)
   - Target environment EnvironmentName (canonical Power Platform identifier)
4. Script usage section with:
   - Parameter reference table:

     | Parameter | Type | Required | Default | Description |
     |-----------|------|----------|---------|-------------|
     | `-EnvironmentName` | String | Yes | — | Power Platform Environment Name (canonical ID) |
     | `-TimeoutDuration` | Int | No | 120 | Timeout in minutes (ValidateRange 5-120) |
     | `-WarningDuration` | Int | No | 5 | Warning before timeout in minutes (ValidateRange 1-30) |
     | `-WhatIf` | Switch | No | — | Preview changes without applying |

   - Example commands:
     ```powershell
     # Check what would change (dry run)
     .\Set-InactivityTimeout.ps1 -EnvironmentName "00000000-0000-0000-0000-000000000000" -TimeoutDuration 60 -WhatIf

     # Apply 60-minute timeout for Zone 3 environment
     .\Set-InactivityTimeout.ps1 -EnvironmentName "00000000-0000-0000-0000-000000000000" -TimeoutDuration 60

     # Apply 120-minute timeout for Zone 2 environment
     .\Set-InactivityTimeout.ps1 -EnvironmentName "00000000-0000-0000-0000-000000000000" -TimeoutDuration 120
     ```
5. Validation section: How to verify PATCH was applied by re-reading API response
6. Bulk remediation guidance: Loop pattern for multiple environments from Dataverse query
7. Footer navigation links
8. FSI-safe language throughout

### Task 4: Create troubleshooting playbook

**File:** `docs/playbooks/control-implementations/2.22/troubleshooting.md`

**Acceptance criteria:**

1. Title: `# Troubleshooting: Control 2.22 - Inactivity Timeout Enforcement`
2. Metadata: Last Updated (February 2026)
3. Common issues summary table:

   | Issue | Cause | Resolution |
   |-------|-------|------------|
   | MissingPolicy error in error log | Environment has no `fsi_environmentpolicy` record | Add policy record with zone and required max duration |
   | 401 Unauthorized from BAP Admin API | Service principal token expired or invalid | Re-authenticate; verify app registration and secret |
   | 403 Forbidden from BAP Admin API | Insufficient permissions on service principal | Grant Power Platform Admin role or API permissions |
   | 404 Not Found from BAP Admin API | Invalid EnvironmentName (not canonical ID) | Use Power Platform Environment Name, not display name |
   | 429 Too Many Requests from BAP Admin API | Rate limiting on concurrent API calls | Reduce concurrency limit; implement exponential backoff |
   | Compliance status shows Unknown | Multiple causes (missing policy, API error, parse error) | Check error log table for specific error type |
   | Flow fails silently | Connection reference not configured | Verify Dataverse and BAP Admin API connection references |
   | Notification not sent | No non-compliant environments found | Expected behavior if all environments are compliant |

4. Detailed `### Issue:` sections for each error with:
   - Symptoms
   - Root cause
   - Resolution steps (numbered)
   - Portal path (where applicable)
   - Prevention guidance
5. Escalation path:
   - L1: Environment Admin (basic configuration issues)
   - L2: Power Platform Admin (API and permission issues)
   - L3: AI Governance Lead (policy and compliance questions)
   - L4: Microsoft Support (platform-level issues)
6. Known limitations table:
   - BAP Admin API rate limits apply to bulk operations
   - Inactivity timeout is per-environment, not per-agent
   - Policy table requires manual zone assignment (no auto-classification)
   - Warning duration has platform minimum/maximum constraints
7. Diagnostic commands for BAP Admin API connectivity testing
8. Footer navigation links
9. FSI-safe language throughout
