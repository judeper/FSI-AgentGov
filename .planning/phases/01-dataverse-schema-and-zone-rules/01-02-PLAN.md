# Phase 1 Plan 02: Zone Rules & Classification Logic

## Goal

Define zone-based sharing rules and create zone classification logic. Zone rules determine what sharing patterns are permitted in each governance zone (Zone 1: individual user sharing only; Zone 2: named security groups, no Everyone/Public; Zone 3: pre-approved security groups only). Zone classification logic determines an agent's governance zone from environment metadata or policy records. Zone evaluation logic determines compliance by comparing an agent's sharing principals against its zone's rules.

This plan delivers **ZON-01** (zone-based sharing rule definitions) and **ZON-02** (zone classification logic) from ROADMAP.md.

### Task 2: Create Zone Classification Function
**Acceptance criteria:**
- [ ] Function signature: `classify_environment_zone(environment_id: str, environment_name: str, client: CAAClient = None, default_zone: int = 0) -> int`
- [ ] Returns zone integer (0–3)
- [ ] Classification logic cascade (first match wins):
  1. **Environment policy lookup:** If `client` provided, query `fsi_EnvironmentPolicy` table (from ITE v19) for environment. If policy record exists with `fsi_governance_zone`, return that zone.
  2. **Naming convention:** Check environment name against patterns:
     - "prod", "production", "enterprise" → Zone 3
     - "test", "qa", "staging", "uat" → Zone 2
     - "dev", "sandbox", "personal" → Zone 1
  3. **Fallback:** Return `default_zone` (0 by default)
- [ ] Case-insensitive name matching
- [ ] Handles missing client gracefully (skips Dataverse lookup)
- [ ] Logs classification decision at INFO level
- [ ] Docstring with examples and logic cascade explanation

**Files:**
- `scripts/asard_zone_rules.py` — Modify: Add `classify_environment_zone()` function

### Task 4: Create Zone Sharing Rule Evaluation Function
**Acceptance criteria:**
- [ ] Function signature: `evaluate_zone_compliance(zone: int, parsed_principals: dict, approved_groups: list[str] = None) -> dict`
- [ ] Returns dictionary:
  ```python
  {
      "compliant": True/False,
      "violation_type": None or "Everyone" or "Public" or "UnapprovedGroup" or "ExcessiveIndividual" or "CrossTenant",
      "details": "Human-readable explanation"
  }
  ```
- [ ] Evaluation logic per zone:
  - **Zone 1:** Violation if `has_everyone`, `has_public`, or `len(security_groups) > 0`
  - **Zone 2:** Violation if `has_everyone` or `has_public`
  - **Zone 3:** Violation if `has_everyone`, `has_public`, OR any group in `security_groups` not in `approved_groups`
  - **Zone 0:** Violation if `has_everyone` or `has_public` (same as Zone 2)
- [ ] Approved groups check for Zone 3:
  - If `approved_groups` is None, skip check (log warning)
  - If `approved_groups` provided, verify all `security_groups` are in `approved_groups`
- [ ] Violation type mapping:
  - `has_everyone` → "Everyone"
  - `has_public` → "Public"
  - Group sharing in Zone 1 → "UnapprovedGroup"
  - Group not in approved list (Zone 3) → "UnapprovedGroup"
- [ ] Details string provides actionable explanation
- [ ] Docstring with examples for each zone
