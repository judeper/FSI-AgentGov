# Plan 04-01: Export-DenyEventEvidence.ps1 with SHA-256 Hashing and Regulatory Alignment

## Objective

Create the DEC evidence export pipeline: main export script, private Dataverse query helper, and integrity verification utility. The export produces timestamped, SHA-256 hashed examination packages with deny events, correlation summaries, alert history, and a regulatory alignment mapping for examiner self-service.

## Must-Haves Addressed

| # | Must-Have | Requirement |
|---|----------|-------------|
| 1 | `Export-DenyEventEvidence.ps1` produces timestamped packages with SHA-256 hashes | EVI-01 |
| 2 | Evidence packages include regulatory alignment mapping | EVI-02 |

## Context

- **Pattern source:** v4-v8 evidence export scripts (3-script pattern: Export, Get-Results, Test-Integrity)
- **Data access:** DECClient.psm1 provides `Read-DECDenyEvents`, `Read-DECCorrelations`, `Read-DECAlerts` with OData pagination
- **JSON format:** 6-section structure (metadata, summary, regulatoryAlignment, correlations, alerts, denyEvents)
- **Naming:** `dec-evidence-{zone}-{yyyyMMdd-HHmmss}.json`

## Tasks

### Task 1: Create Get-DECValidationResults.ps1 (Private Helper)

**File:** `maintainers-local/solutions-staging/deny-event-correlation-report/scripts/private/Get-DECValidationResults.ps1`

**Action:** CREATE

**Details:**
- `#Requires -Version 7.0`
- Import DECClient.psm1 from same `private/` directory
- Parameters: `$DataverseUrl`, `$TenantId`, `$Zone`, `$FromDate`, `$ToDate`, `$RunId`, `$IncludeRawEvents`, `$Interactive`, `$CertificateThumbprint`, `$ClientId`
- Connect to Dataverse via `Connect-DECDataverse`
- Build OData filter strings from date range and zone parameters
- Query 3 tables using DECClient functions:
  - `Read-DECCorrelations` — always included (primary evidence)
  - `Read-DECAlerts` — always included (compliance status evidence)
  - `Read-DECDenyEvents` — only when `-IncludeRawEvents` (can be large)
- Return `[PSCustomObject]@{ Correlations; Alerts; DenyEvents; QueryTimestamp }`
- Structured error handling with `Write-Error` on connection/query failures

**Acceptance criteria:**
- [ ] Calls DECClient functions for all 3 tables
- [ ] Supports zone filtering (All, 1, 2, 3)
- [ ] Date range filtering works on `fsi_correlation_date`, `fsi_alert_timestamp`, `fsi_timestamp`
- [ ] Raw events gated behind `-IncludeRawEvents` switch

### Task 2: Create Export-DenyEventEvidence.ps1 (Main Export)

**File:** `maintainers-local/solutions-staging/deny-event-correlation-report/scripts/Export-DenyEventEvidence.ps1`

**Action:** CREATE

**Details:**
- `#Requires -Version 7.0`
- `#Requires -Modules @{ ModuleName = 'MSAL.PS'; RequiredVersion = '4.37.0.0' }`
- Function `Export-DenyEventEvidence` with CmdletBinding
- Parameters matching v4-v8 pattern:
  - `[Parameter(Mandatory)] [string]$DataverseUrl`
  - `[Parameter(Mandatory)] [string]$TenantId`
  - `[Parameter(Mandatory)] [string]$OutputDirectory`
  - `[ValidateSet('All','1','2','3')] [string]$Zone = 'All'`
  - `[datetime]$FromDate = (Get-Date).AddDays(-30)`
  - `[datetime]$ToDate = (Get-Date)`
  - `[string]$RunId`
  - `[switch]$IncludeRawEvents`
  - `[switch]$Interactive`
  - `[string]$CertificateThumbprint`
  - `[string]$ClientId`
- Step 1: Create output directory if not exists
- Step 2: Call `Get-DECValidationResults.ps1` to fetch data
- Step 3: Compute summary statistics:
  - `totalDenyEvents` — count of raw events in range
  - `totalCorrelations` — count of daily summaries
  - `totalAlerts` — count of alerts
  - `alertsBySeverity` — `@{ Critical=0; High=0; Warning=0; Info=0 }` from alerts
  - `eventsBySource` — `@{ RaiTelemetry=0; PurviewAudit=0; PurviewDlp=0 }` from events
  - `overallStatus` — derived: Critical/High alerts → "Failed", Warning → "Warning", else → "Passed"
- Step 4: Build regulatory alignment array (static mapping — see below)
- Step 5: Assemble evidence JSON (6 sections):
  ```
  metadata → solution info, date range, zone, export version, record count
  summary → overall status, counts, severity/source distributions
  regulatoryAlignment → static mapping of deny events to FINRA/SEC/SOX/GLBA requirements
  correlations → daily correlation summaries with trends
  alerts → alert history with severity and type
  denyEvents → raw deny events (only if -IncludeRawEvents)
  ```
- Step 6: Write JSON with `ConvertTo-Json -Depth 10` + `Out-File -Encoding utf8`
- Step 7: Generate SHA-256 hash with `Get-FileHash -Algorithm SHA256`
- Step 8: Write `.sha256` companion file (format: `{HASH}  {filename}`)
- Step 9: Return `[PSCustomObject]@{ EvidenceFile; HashFile; SHA256; RecordCount; AlertCount; GeneratedAt }`

**Regulatory Alignment Mapping (EVI-02):**

Static array embedded as `$regulatoryAlignmentMapping`:

| Regulation | Requirement | Deny Event Relevance | Satisfied By | Controls |
|------------|------------|---------------------|--------------|----------|
| FINRA 4511 | Books and Records | Deny events as supervisory control evidence | denyEvents, correlations | 1.7, 3.4 |
| FINRA 3110 | Supervisory Systems | Correlation summaries demonstrate supervisory controls | correlations, alerts | 1.5, 3.4 |
| FINRA 25-07 | AI/ML Governance | RAI telemetry provides AI risk monitoring evidence | denyEvents, correlations | 1.5 |
| SEC 17a-3/4 | Recordkeeping | Zone-based retention per SEC requirements | denyEvents | 1.7 |
| SOX 302/404 | Internal Controls | Alert classification demonstrates control effectiveness | alerts, correlations | 3.4 |
| GLBA 501(b) | Safeguards Rule | DLP deny events demonstrate active safeguards | denyEvents | 1.5 |

**Acceptance criteria:**
- [ ] Produces `dec-evidence-{zone}-{yyyyMMdd-HHmmss}.json` with SHA-256 companion
- [ ] JSON has 6 sections: metadata, summary, regulatoryAlignment, correlations, alerts, denyEvents
- [ ] Overall status derived from alert severity distribution
- [ ] Regulatory alignment array maps 6 regulations to deny event categories
- [ ] `-IncludeRawEvents` gates raw event inclusion (default: excluded for file size)
- [ ] `ConvertTo-Json -Depth 10` prevents nested truncation
- [ ] Returns PSCustomObject with EvidenceFile, HashFile, SHA256, RecordCount, AlertCount, GeneratedAt

### Task 3: Create Test-EvidenceIntegrity.ps1

**File:** `maintainers-local/solutions-staging/deny-event-correlation-report/scripts/Test-EvidenceIntegrity.ps1`

**Action:** CREATE

**Details:**
- `#Requires -Version 5.1` (lower requirement for verification — runs anywhere)
- Function `Test-EvidenceIntegrity` with CmdletBinding
- Parameters:
  - `[Parameter(Mandatory)] [string]$EvidenceFile` — path to `.json` evidence file
  - `[string]$HashFile` — optional override (defaults to `$EvidenceFile.sha256`)
- Reads expected hash from `.sha256` companion file
- Computes actual hash with `Get-FileHash -Algorithm SHA256`
- Compares and returns `[PSCustomObject]@{ File; ExpectedHash; ActualHash; IsValid; VerifiedAt }`
- Exits with code 0 (valid) or 1 (mismatch) when run as script

**Acceptance criteria:**
- [ ] Reads `.sha256` companion file and extracts expected hash
- [ ] Computes actual SHA-256 of evidence JSON
- [ ] Returns structured result with IsValid boolean
- [ ] Works on PowerShell 5.1+ (Windows) and 7.0+ (cross-platform)
