# Plan 03-03: Drift Detection Refinement, Integration Verification, and CHANGELOG Update

## Goal

Verify end-to-end structural consistency across all Phase 3 artifacts, refine drift detection logic, ensure FLOW_SETUP.md covers the Dataverse validation history write path, and update CHANGELOG.md with the v0.3.0 entry. This plan ensures all pieces from Plans 03-01 and 03-02 fit together correctly.

## Tasks

### Task 1: Verify and Refine Drift Detection Logic

Review `Start-AccessValidationRunbook.ps1` drift detection implementation and verify:

1. **Setting comparison completeness:** All 3 agent access settings are compared:
   - `bot-limitSharingMode` (string comparison)
   - `bot-authoringSharingDisabled` (boolean comparison)
   - `bot-publishedBotLimitSharingMode` (string comparison)

2. **Drift direction classification:** Based on zone expectations from `zone-settings-baseline.json`:
   - **Weakened:** Setting became more permissive (e.g., `ExcludeExternalUsers` → `NoRestrictions`) → alert severity escalated
   - **Strengthened:** Setting became more restrictive (e.g., `NoRestrictions` → `ExcludeExternalUsers`) → informational
   - **Changed:** Non-directional change (e.g., `AllUsers` → `InternalOnly`) → requires review

3. **Edge cases:**
   - Environment has no active baseline → `IsFirstRun=true` for that environment, skip drift detection
   - Baseline exists but environment no longer in scan results → skip (environment may have been decommissioned)
   - Multiple zones in single scan → drift evaluated per-environment, not per-zone
   - Dataverse query failure → fail open (`HasDrift=false, IsFirstRun=true`)

4. **Fix any structural mismatches** between:
   - Runbook output JSON keys and Parse_Results schema in the flow
   - Drift object structure and adaptive card drift section placeholders
   - ZoneSummary keys and adaptive card zone summary section

**Acceptance Criteria:**
- [ ] All 3 settings are compared in drift detection
- [ ] Drift direction is correctly classified
- [ ] Edge cases handled (no baseline, query failure)
- [ ] Runbook output structure matches flow Parse_Results schema
