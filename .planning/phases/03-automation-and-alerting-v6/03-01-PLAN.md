# Plan 03-01: Runbook Wrapper, Baseline Capture, and AAMClient Drift Detection Functions

## Goal

Create the PowerShell runbook wrapper for automated daily agent access validation and the operator-initiated baseline capture script. These scripts bridge Phase 2 Dataverse infrastructure and Phase 3 Power Automate automation. The runbook enables non-interactive execution with structured JSON output that Power Automate can parse and route. The baseline capture gives operators the ability to snapshot current environment access settings as the approved baseline for future drift detection.

## Tasks

### Task 1: Add Save-AAMBaseline and Get-AAMLastValidation to AAMClient.psm1

Modify `agent-access-monitor/scripts/private/AAMClient.psm1` to add two new exported functions.

**Save-AAMBaseline:**

```powershell
function Save-AAMBaseline {
    [CmdletBinding(SupportsShouldProcess)]
    param(
        [Parameter(Mandatory)][string]$EnvironmentGuid,
        [Parameter(Mandatory)][string]$EnvironmentName,
        [Parameter(Mandatory)][int]$Zone,
        [Parameter(Mandatory)][string]$BotLimitSharingMode,
        [Parameter(Mandatory)][bool]$BotAuthoringSharingDisabled,
        [Parameter(Mandatory)][string]$BotPublishedBotLimitSharingMode,
        [string]$CapturedBy,
        [string]$RawJson
    )
```

Logic:
1. Query `fsi_accessbaselines` for active baseline: `$filter=fsi_isactive eq true and fsi_environmentguid eq '{EnvironmentGuid}'`
2. If found, PATCH `fsi_isactive = false` (deactivate previous baseline)
3. POST new baseline record with all fields and `fsi_isactive = true`
4. Set `fsi_name` to `"{EnvironmentName}-{Zone}-{timestamp}"`
5. All mutations gated by `ShouldProcess` (-WhatIf support)
6. Wrap in try/catch — failure logged with Write-Warning, never throws

**Get-AAMLastValidation:**

```powershell
function Get-AAMLastValidation {
    [CmdletBinding()]
    param(
        [int]$Top = 1
    )
```

Logic:
1. Query `fsi_accessvalidationhistories` ordered by `fsi_timestamp desc`, top `$Top`
2. Select: `fsi_name,fsi_runid,fsi_zone,fsi_severity,fsi_overallstatus,fsi_violationcount,fsi_summaryjson,fsi_timestamp`
3. Return PSCustomObject array (or `$null` if none found)
4. Wrap in try/catch — return `$null` on failure

**Export additions:** Add both functions to `Export-ModuleMember` list.

**Acceptance Criteria:**
- [ ] Save-AAMBaseline deactivates existing active baseline before saving new one
- [ ] Save-AAMBaseline supports -WhatIf via ShouldProcess
- [ ] Get-AAMLastValidation returns ordered history records from Dataverse
- [ ] Both functions handle connection failures gracefully (Write-Warning, not throw)
- [ ] Both functions are exported from AAMClient.psm1

### Task 2: Create Start-AccessValidationRunbook.ps1

Create `agent-access-monitor/scripts/Start-AccessValidationRunbook.ps1` following the SSC `Start-SessionValidationRunbook.ps1` pattern.

**Parameters:**

| Parameter | Type | Required | Default | Purpose |
|-----------|------|----------|---------|---------|
| `-TenantId` | string | Yes | — | Azure AD tenant GUID |
| `-ClientId` | string | Yes | — | App registration client ID |
| `-CertificateThumbprint` | string | Yes | — | Certificate for auth |
| `-DataverseUrl` | string | Yes | — | Dataverse environment URL |
| `-ExcludeSandbox` | switch | No | $true | Exclude sandbox environments |
| `-ExcludeTrial` | switch | No | $true | Exclude trial environments |
| `-GracePeriodHours` | int | No | 48 | Grace period for new environments |

**Script structure:**

```
1. #Requires -Version 7.0
2. #Requires -Modules MSAL.PS
3. Certificate-based authentication (Connect-AAMDataverse)
4. Read operational params from Dataverse env vars (GracePeriodHours, ExcludeSandbox)
5. Run Test-AgentAccessCompliance with -PersistResults -DataverseUrl
6. Query active baselines for drift detection
7. Compare current results to baselines per environment
8. Build output object:
   - RunType: "Scheduled"
   - Timestamp: ISO 8601
   - TotalEnvironments: from scan result
   - OverallStatus: Passed/Warning/Failed
   - Reason: human-readable summary
   - ZoneSummary: { Zone1: {Total, Compliant, Violations}, ... }
   - Violations: array of violation objects
   - Drift: { HasDrift, IsFirstRun, DriftedEnvironments, Details[] }
   - AlertRequired: true when Failed/Error OR HasDrift
   - AlertSeverity: highest severity from violations or "Critical" for Zone 3 drift
9. Output as JSON to pipeline (ConvertTo-Json -Depth 10)
```

**Drift detection logic:**
1. Call `Get-AAMActiveBaseline` for each environment in the scan results
2. For each environment with an active baseline, compare 3 settings:
   - `bot-limitSharingMode`: baseline vs current
   - `bot-authoringSharingDisabled`: baseline vs current
   - `bot-publishedBotLimitSharingMode`: baseline vs current
3. If any setting differs, add to drift details with direction (Weakened/Strengthened/Changed)
4. Weakened = setting became more permissive → alert required
5. If no active baseline exists for an environment, mark as `IsFirstRun=true` for that environment
6. On Dataverse query failure, set `HasDrift=false, IsFirstRun=true` (fail open)

**Acceptance Criteria:**
- [ ] Script runs non-interactively with certificate-based auth
- [ ] Calls Test-AgentAccessCompliance with -PersistResults for Dataverse writes
- [ ] Drift detection compares current settings to active baselines per environment
- [ ] Outputs structured JSON only (no Write-Host) with all required properties
- [ ] AlertRequired is true when violations detected OR drift detected
- [ ] AlertSeverity reflects the highest severity across all violations
- [ ] Fail-open on Dataverse errors (Write-Warning, continue with defaults)

### Task 3: Create Invoke-AccessBaselineCapture.ps1

Create `agent-access-monitor/scripts/Invoke-AccessBaselineCapture.ps1`.

**Parameters:**

| Parameter | Type | Required | Default | Purpose |
|-----------|------|----------|---------|---------|
| `-TenantId` | string | Yes | — | Azure AD tenant GUID |
| `-ClientId` | string | Yes | — | App registration client ID |
| `-CertificateThumbprint` | string | No | — | Certificate auth (optional, can use interactive) |
| `-DataverseUrl` | string | Yes | — | Dataverse environment URL |
| `-Zone` | int | No | — | Filter to specific zone (1, 2, or 3) |
| `-EnvironmentGuid` | string | No | — | Capture single environment baseline |
| `-ExcludeSandbox` | switch | No | $true | Exclude sandbox environments |
| `-CapturedBy` | string | No | current UPN | Identity of the capturing operator |

**Script structure:**

```
1. #Requires -Version 5.1
2. Parameter validation
3. Authenticate (certificate or interactive)
4. Connect-AAMDataverse
5. Call Get-EnvironmentAccessSettings to capture live settings
6. If -Zone specified, filter to matching environments
7. If -EnvironmentGuid specified, filter to single environment
8. For each environment:
   a. Build baseline record from current settings
   b. Call Save-AAMBaseline (handles deactivation of prior baseline)
   c. Report: "Baseline captured for {EnvironmentName} (Zone {Zone})"
9. Output summary: total captured, per-zone breakdown
```

**Acceptance Criteria:**
- [ ] Captures live agent access settings for all (or filtered) environments
- [ ] Calls Save-AAMBaseline for each environment (handles active baseline rotation)
- [ ] Supports -Zone filter for zone-specific captures
- [ ] Supports -EnvironmentGuid for single-environment captures
- [ ] Supports -WhatIf (ShouldProcess propagated to Save-AAMBaseline)
- [ ] Outputs structured capture summary
