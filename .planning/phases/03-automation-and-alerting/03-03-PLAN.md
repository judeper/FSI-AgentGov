Insert a new HTTP action named `Write_Validation_History` inside the `Scope_Try.actions` object in session-validation-flow.json. This action must be positioned in the execution chain AFTER Parse_Results and BEFORE Check_Alert_Required.

**Action definition:**

```json
"Write_Validation_History": {
  "runAfter": {
    "Parse_Results": ["Succeeded"]
  },
  "type": "Http",
  "inputs": {
    "method": "POST",
    "uri": "@{variables('DataverseUrl')}/api/data/v9.2/fsi_validationhistories",
    "headers": {
      "Content-Type": "application/json",
      "OData-MaxVersion": "4.0",
      "OData-Version": "4.0"
    },
    "authentication": {
      "type": "ManagedServiceIdentity",
      "audience": "@{variables('DataverseUrl')}"
    },
    "body": {
      "fsi_name": "@{body('Parse_Results')?['Zone']}-@{body('Parse_Results')?['Timestamp']}",
      "fsi_runid": "@{guid()}",
      "fsi_zone": "@{if(equals(body('Parse_Results')?['Zone'], 'Zone1'), 100000001, if(equals(body('Parse_Results')?['Zone'], 'Zone2'), 100000002, 100000003))}",
      "fsi_severity": "@{if(equals(body('Parse_Results')?['OverallStatus'], 'Passed'), 1, if(equals(body('Parse_Results')?['OverallStatus'], 'Warning'), 2, if(equals(body('Parse_Results')?['OverallStatus'], 'Failed'), 4, 5)))}",
      "fsi_validationtype": 6,
      "fsi_rawvalue": "@{string(body('Parse_Results'))}",
      "fsi_reason": "@{body('Parse_Results')?['Reason']}",
      "fsi_timestamp": "@{body('Parse_Results')?['Timestamp']}",
      "fsi_checkcount": 4,
      "fsi_baselineid": "@{if(equals(body('Parse_Results')?['Drift']?['IsFirstRun'], true), '', body('Parse_Results')?['Drift']?['BaselineDate'])}",
      "fsi_remediationhint": "@{if(equals(body('Parse_Results')?['AlertRequired'], true), body('Parse_Results')?['Reason'], '')}"
    }
  },
  "description": "Write validation results to Dataverse immutable audit trail (runs for ALL results, not just alerts)"
}
```

**Field mapping rationale:**
- `fsi_name`: "{Zone}-{Timestamp}" for human-readable record identification
- `fsi_runid`: New GUID per run via `@{guid()}` — correlates orchestrator record
- `fsi_zone`: Maps Zone1/Zone2/Zone3 string to fsi_acv_zone option set values (100000001/100000002/100000003) matching Invoke-BaselineCapture.ps1
- `fsi_severity`: Maps OverallStatus to fsi_acv_severity option set (Passed=1, Warning=2, Failed=4, Error=5). Note: GracePeriod=3 is not used by SSC.
- `fsi_validationtype`: Static value 6 (Orchestrator) — this is the overall orchestrator record. Per-validator records are not written by the flow (runbook writes individual validators).
- `fsi_rawvalue`: Full Parse_Results JSON stringified for audit
- `fsi_reason`: Human-readable reason from runbook output
- `fsi_timestamp`: Validation run timestamp (ISO 8601)
- `fsi_checkcount`: Static 4 (SSC has 4 validators: SessionControls, AuthStrength, PIM, BreakGlass)
- `fsi_baselineid`: Baseline date reference if not first run; empty string if first run
- `fsi_remediationhint`: Reason text when alert required, empty when passed

**Authentication:** Use Managed Service Identity (MSI) with audience set to DataverseUrl. This is the Power Automate premium HTTP connector pattern for Dataverse Web API access. The flow's connection identity must have the Dataverse System Administrator or a custom security role with Create permission on fsi_validationhistory entity.

**Update Check_Alert_Required runAfter:**

The existing `Check_Alert_Required` action has:
```json
"runAfter": {
  "Parse_Results": ["Succeeded"]
}
```

Change it to:
```json
"runAfter": {
  "Write_Validation_History": ["Succeeded", "Failed"]
}
```

The `["Succeeded", "Failed"]` array is critical — it means Check_Alert_Required (and therefore alerting) will run even if the Dataverse write fails. This implements the "Continue on failure" requirement: Dataverse write issues must NOT block alerting.

**Execution order after change:**
1. Create_Automation_Job → 2. Wait_For_Job → 3. Check_Job_Failed → 4. Get_Job_Output → 5. Parse_Results → 6. **Write_Validation_History** → 7. Check_Alert_Required

**Important constraints:**
- Write_Validation_History must be OUTSIDE the Check_Alert_Required If block (writes ALL results, not just alerts)
- The action position in the JSON object does not matter for execution order — runAfter controls the DAG. But for readability, place it between Parse_Results and Check_Alert_Required in the JSON source.
- Do NOT add a Dataverse connection reference to the `$connections` parameter — this action uses HTTP connector with MSI, not the Dataverse connector.

```markdown
### Dataverse Write Fails (Write_Validation_History)

**Symptom:** Write_Validation_History action shows "Forbidden" (403) or "Unauthorized" (401) error in flow run history, but alerting still works

**Cause:** Managed identity lacks Dataverse permissions, or DataverseUrl is incorrect

**Solution:**

1. Verify DataverseUrl variable matches the environment where SSC schema is deployed:
   - Navigate to [make.powerapps.com](https://make.powerapps.com) > Environment > Session details > Instance url
   - Must match the value in the Initialize_DataverseUrl action exactly
2. Check managed identity permissions:
   - Navigate to [admin.powerplatform.microsoft.com](https://admin.powerplatform.microsoft.com)
   - Select environment > **Settings** > **Users + permissions** > **Application users**
   - Find the flow's application user (matches the connection identity)
   - Assign **System Administrator** role or a custom role with Create on `fsi_validationhistory`
3. If using a custom security role:
   - Navigate to **Settings** > **Security roles**
   - Create or edit role > **Custom Entities** tab
   - Find `Validation History` > Grant **Create** at Organization level
4. Test by manually triggering the flow and checking Write_Validation_History action result

**Note:** Alerting continues even when Dataverse writes fail. The Check_Alert_Required action is configured to run after Write_Validation_History regardless of success or failure. However, if writes fail persistently, drift detection will not function correctly (Get-DriftStatus queries fsi_validationhistories for baseline comparison). Fix Dataverse access promptly.
```
