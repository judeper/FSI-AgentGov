**adaptive-card-session-alert.json:**

Create the Teams adaptive card template following the ACV adaptive-card-tenant-alert.json structure with SSC-specific content.

**Card structure:**

1. **Header container** (style: "attention"):
   - Title: `[ALERT] Session Security Drift`
   - Status: `${overallStatus}` (right-aligned, color: Attention)
   - Timestamp: `${timestamp}` (small, subtle)

2. **Drift info container:**
   - Section title: "Drift Detected"
   - FactSet with:
     - Zone: `${zone}`
     - Severity: `${overallStatus}`
     - Drift From: `${baselineStatus}` to `${currentStatus}`
     - Baseline Date: `${baselineDate}`

3. **Reason container:**
   - Section title: "Reason"
   - Text: `${reason}` (wrap: true)

4. **Validator status container:**
   - Section title: "Validator Status"
   - FactSet with SSC validators (NOT ACV validators):
     - Session Controls: `${sessionControlsStatus}`
     - Auth Strength: `${authStrengthStatus}`
     - PIM Settings: `${pimStatus}`
     - Break-Glass: `${breakGlassStatus}`

5. **Actions:**
   - "View in Power Platform" -> https://make.powerapps.com
   - "View Validation History" -> `${validationHistoryUrl}`

**Schema version:** 1.4 (same as ACV)

**Placeholders (10 total):** overallStatus, timestamp, zone, baselineStatus, currentStatus, baselineDate, reason, sessionControlsStatus, authStrengthStatus, pimStatus, breakGlassStatus, validationHistoryUrl

**session-validation-flow.json:**

Create the Power Automate flow definition following the ACV tenant-validation-flow.json structure with SSC-specific adaptations.

**Flow structure:**

```
$schema: Logic Apps workflow definition schema 2016-06-01
contentVersion: 1.0.0.0
parameters: { $connections: { type: Object } }
```

**Trigger:**
```json
"Recurrence": {
    "recurrence": {
        "frequency": "Day",
        "interval": 1,
        "schedule": { "hours": ["6"], "minutes": [0] },
        "timeZone": "UTC"
    },
    "type": "Recurrence"
}
```

**Variable initialization actions (9 variables, sequential runAfter chain):**

1. `Initialize_DataverseUrl` — string, "https://governance.crm.dynamics.com"
2. `Initialize_TenantId` — string, "contoso.onmicrosoft.com"
3. `Initialize_ClientId` — string, "your-client-id-here"
4. `Initialize_CertificateThumbprint` — string, "your-certificate-thumbprint-here"
5. `Initialize_SubscriptionId` — string, "your-subscription-id-here"
6. `Initialize_ResourceGroup` — string, "rg-session-validation"
7. `Initialize_AutomationAccount` — string, "aa-session-validator"
8. `Initialize_TeamsChannelId` — string, "your-teams-channel-id-here"
9. `Initialize_ComplianceDistributionList` — string, "compliance-alerts@contoso.com"
10. `Initialize_Zone` — string, "Zone3"

Each has description field. Each runAfter references the previous variable init action.

**Scope_Try (runAfter: Initialize_Zone):**

Actions inside Scope_Try (sequential):

1. **Create_Automation_Job** — Azure Automation Create Job action
   - runbookName: "Start-SessionValidationRunbook" (NOT Start-TenantValidationRunbook)
   - Parameters: Zone, DataverseUrl, TenantId, ClientId, CertificateThumbprint, ConfigPath (new — use "tenant-config.json")
   - Connection: azureautomation

2. **Wait_For_Job** — Until loop (same pattern as ACV)
   - Delay 30 seconds + Get_Job_Status
   - Expression checks Completed, Failed, Stopped, Suspended
   - Limit: 240 iterations, PT2H timeout

3. **Check_Job_Failed** — If condition (Failed | Stopped | Suspended)
   - Send_Job_Failure_Email to ComplianceDistributionList
   - Terminate_Failed

4. **Get_Job_Output** — Get job output (same pattern as ACV)

5. **Parse_Results** — ParseJson action with SSC-specific schema:
   ```json
   {
       "type": "object",
       "properties": {
           "RunType": { "type": "string" },
           "Timestamp": { "type": "string" },
           "Zone": { "type": "string" },
           "OverallStatus": { "type": "string" },
           "Reason": { "type": "string" },
           "Validators": {
               "type": "object",
               "properties": {
                   "SessionControls": {
                       "type": "object",
                       "properties": {
                           "Status": { "type": "string" },
                           "Reason": { "type": "string" }
                       }
                   },
                   "AuthStrength": {
                       "type": "object",
                       "properties": {
                           "Status": { "type": "string" },
                           "Reason": { "type": "string" }
                       }
                   },
                   "PimRoleSettings": {
                       "type": "object",
                       "properties": {
                           "Status": { "type": "string" },
                           "Reason": { "type": "string" }
                       }
                   },
                   "BreakGlass": {
                       "type": "object",
                       "properties": {
                           "Status": { "type": "string" },
                           "Reason": { "type": "string" }
                       }
                   }
               }
           },
           "Drift": {
               "type": "object",
               "properties": {
                   "DriftDetected": { "type": "boolean" },
                   "CurrentStatus": { "type": "string" },
                   "BaselineStatus": { "type": "string" },
                   "BaselineDate": { "type": "string" },
                   "IsFirstRun": { "type": "boolean" }
               }
           },
           "AlertRequired": { "type": "boolean" },
           "AlertSeverity": { "type": "string" }
       }
   }
   ```

6. **Check_Alert_Required** — If AlertRequired == true
   - **Check_Severity_For_Teams** — If OverallStatus == "Failed" OR "Error"
     - **Post_Teams_Card** — Post adaptive card to Teams channel
       - Use inline adaptive card JSON with nested replace() calls for all 12 placeholders
       - Replace ${overallStatus}, ${timestamp}, ${zone}, ${baselineStatus}, ${currentStatus}, ${baselineDate}, ${reason}, ${sessionControlsStatus}, ${authStrengthStatus}, ${pimStatus}, ${breakGlassStatus}, ${validationHistoryUrl}
       - Validator status extracted from body('Parse_Results')?['Validators']?['SessionControls']?['Status'] etc.
       - validationHistoryUrl = concat(variables('DataverseUrl'), '/main.aspx')
       - Connection: teams
   - **Send_Alert_Email** (runAfter Check_Severity_For_Teams)
     - To: ComplianceDistributionList
     - Subject: `[ALERT] Session Security Drift - @{Zone} - @{OverallStatus}`
     - Body: HTML table with zone, status, baseline comparison, reason, validator results
     - Importance: High if Failed/Error, Normal otherwise
     - Connection: office365

**Scope_Catch (runAfter Scope_Try: ["Failed", "Skipped", "TimedOut"]):**
- Send_Error_Email to ComplianceDistributionList
  - Subject: `[CRITICAL] Session Validation Flow Error`
  - Body: Flow name, zone, UTC timestamp, review instructions
  - Importance: High
  - Connection: office365

- `azureautomation` — Azure Automation
- `teams` — Microsoft Teams (maps to fsi_cr_teams_sessionvalidation)

**Document structure:**

# Session Security Configurator - Flow Setup Guide

## Overview

Step-by-step guide for deploying the SSC daily session validation flow in Power Automate.

## Prerequisites

- Azure Automation Account with:
  - Start-SessionValidationRunbook.ps1 imported as a runbook
  - Certificate uploaded (Certificates blade)
  - Modules installed: Microsoft.Graph.Identity.SignIns, MSAL.PS
  - Application permissions granted: Policy.Read.All, Directory.Read.All
- Dataverse environment with SSC schema deployed (run deploy.py)
- Microsoft Teams channel for alert notifications
- Email distribution list for compliance alerts
- Connection references bound in Power Automate (fsi_cr_teams_sessionvalidation, fsi_cr_office365_sessionvalidation)

## Step 1: Import Flow

1. Navigate to https://make.powerautomate.com
2. Select target environment
3. Click "My flows" > "Import" > "Import Package (Legacy)"
4. Upload `src/session-validation-flow.json`
5. Map connection references:
   - Azure Automation → Your Automation Account connection
   - Teams → fsi_cr_teams_sessionvalidation
   - Office 365 → fsi_cr_office365_sessionvalidation

## Step 2: Configure Variables

Update these variables in the flow designer:

| Variable | Value | Notes |
|----------|-------|-------|
| DataverseUrl | https://your-org.crm.dynamics.com | Your Dataverse environment URL |
| TenantId | your-tenant-id | Azure AD tenant identifier |
| ClientId | your-client-id | App registration client ID |
| CertificateThumbprint | your-thumbprint | Certificate in Azure Automation |
| SubscriptionId | your-subscription-id | Azure subscription with Automation Account |
| ResourceGroup | your-resource-group | Resource group with Automation Account |
| AutomationAccount | your-account-name | Azure Automation Account name |
| TeamsChannelId | your-channel-id | Teams channel for drift alerts |
| ComplianceDistributionList | alerts@your-org.com | Email distribution list |
| Zone | Zone3 | Governance zone to validate |

## Step 3: Test the Flow

1. Click "Test" > "Manually"
2. Verify runbook executes successfully
3. Check flow run history for:
   - Runbook job creation (Succeeded)
   - Parse JSON output (Succeeded)
   - Alert routing based on results

## Step 4: Enable Daily Schedule

1. After successful test, the Recurrence trigger activates automatically
2. Flow runs daily at 6:00 AM UTC
3. Monitor first 3 days of automated runs for consistency

## Step 5: Capture Initial Baseline

After the flow is running:

1. Run baseline capture for each zone:
   ```powershell
   .\Invoke-BaselineCapture.ps1 -Zone Zone3 -DataverseUrl "https://org.crm.dynamics.com" `
       -TenantId "your-tenant" -ClientId "your-client" -CertificateThumbprint "your-cert"
   ```
2. This creates the Dataverse baseline that drift detection compares against
3. Re-capture baselines after approved CA policy changes

## Multi-Zone Deployment

To validate all three zones, create three flow instances:

1. Clone the flow three times
2. Set Zone variable: Zone1, Zone2, Zone3 respectively
3. Stagger start times (6:00, 6:15, 6:30 AM UTC) to avoid load spikes
4. Use zone-specific Teams channels if desired

## Alert Routing Summary

| Condition | Teams Card | Email | Importance |
|-----------|-----------|-------|-----------|
| Failed or Error | Yes | Yes | High |
| Warning | No | Yes | Normal |
| Passed (no drift) | No | No | — |
| Flow error | No | Yes (CRITICAL) | High |

## Troubleshooting

### Flow Fails at Create_Automation_Job
- Verify SubscriptionId, ResourceGroup, AutomationAccount variables
- Check Azure Automation connection is authenticated
- Ensure runbook "Start-SessionValidationRunbook" exists

### Parse JSON Fails
- Check runbook output is valid JSON (no Write-Host in script)
- Verify runbook completes successfully (not Failed/Suspended)
- Review job output in Azure Portal > Automation Account > Jobs

### No Teams Card Posted
- Verify TeamsChannelId variable is correct
- Check Teams connection reference is bound
- Confirm OverallStatus is "Failed" or "Error" (Warning only triggers email)

### No Alerts Despite Drift
- Check if baseline exists (run Invoke-BaselineCapture.ps1 first)
- Verify AlertRequired is true in Parse JSON output
- Review drift detection in runbook output

## Version History

| Version | Date | Changes |
|---------|------|---------|
| 1.0.0 | 2026-02 | Initial flow setup guide |
```
