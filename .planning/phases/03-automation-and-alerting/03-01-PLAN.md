Create the Azure Automation runbook wrapper following the ACV Start-TenantValidationRunbook.ps1 pattern, adapted for SSC.

**Script structure:**

```powershell
#Requires -Version 7.0
#Requires -Modules @{ ModuleName="Microsoft.Graph.Identity.SignIns"; ModuleVersion="2.0.0" }, @{ ModuleName="MSAL.PS"; ModuleVersion="4.37.0" }
```

**Parameters (all mandatory except SkipPimValidation):**
- `[string]$Zone` — ValidateSet("Zone1", "Zone2", "Zone3")
- `[string]$DataverseUrl` — Dataverse environment URL
- `[string]$TenantId` — Azure AD tenant ID
- `[string]$ClientId` — Azure AD application ID
- `[string]$CertificateThumbprint` — Certificate for service principal auth
- `[string]$ConfigPath` — Path to tenant-config.json with breakGlassAccounts
- `[switch]$SkipPimValidation` — Optional, passes through to Test-SessionCompliance

**Execution flow (inside try block):**

1. Set `$ErrorActionPreference = "Stop"` and `$scriptRoot = $PSScriptRoot`

2. Dot-source required scripts:
   ```powershell
   . "$scriptRoot\Test-SessionCompliance.ps1"
   . "$scriptRoot\private\Compare-SessionBaseline.ps1"
   ```
   NOTE: Use Compare-SessionBaseline.ps1 (SSC Phase 1 helper) NOT Compare-ValidationBaseline.ps1 (ACV helper). However, drift detection needs to query Dataverse ValidationHistory. The SSC Compare-SessionBaseline.ps1 does local baseline comparison. For Dataverse drift detection, implement inline logic following the ACV Compare-ValidationBaseline pattern — query fsi_validationhistories for the most recent Passed record and compare severity.

   CORRECTION: Actually, re-read the research. The runbook needs drift detection against Dataverse ValidationHistory (not local baseline files). The approach is:
   - Call Test-SessionCompliance.ps1 to get current validation status
   - Query Dataverse fsi_validationhistories for baseline (inline, following ACV Compare-ValidationBaseline pattern)
   - The SSC Compare-SessionBaseline.ps1 compares against LOCAL baselines — different concern

   So implement drift detection as an inline function within the runbook (or dot-source Compare-ValidationBaseline pattern). Since ACV has the proven pattern, create a minimal inline drift detection function:

   ```powershell
   function Get-DriftStatus {
       param(
           [string]$DataverseUrl,
           [string]$DataverseToken,
           [string]$CurrentStatus
       )
       # Severity map
       $severityMap = @{ "Passed" = 1; "Warning" = 2; "Failed" = 3; "Error" = 4 }
       $currentSeverity = $severityMap[$CurrentStatus]

       try {
           # Query last Passed validation from fsi_validationhistories
           $filter = "fsi_severity eq 1"
           $apiUrl = "$DataverseUrl/api/data/v9.2/fsi_validationhistories"
           $apiUrl += "?`$filter=$filter&`$orderby=createdon desc&`$top=1&`$select=fsi_severity,fsi_timestamp,createdon"

           $headers = @{
               "Authorization"    = "Bearer $DataverseToken"
               "Accept"           = "application/json"
               "OData-MaxVersion" = "4.0"
               "OData-Version"    = "4.0"
           }

           $response = Invoke-RestMethod -Uri $apiUrl -Method Get -Headers $headers -ErrorAction Stop
           $baseline = $response.value | Select-Object -First 1

           if ($null -eq $baseline) {
               # First run — any non-Passed result is drift
               return [PSCustomObject]@{
                   DriftDetected  = ($CurrentStatus -ne "Passed")
                   CurrentStatus  = $CurrentStatus
                   BaselineStatus = $null
                   BaselineDate   = $null
                   IsFirstRun     = $true
               }
           }

           $baselineSeverity = $baseline.fsi_severity
           $reverseSeverityMap = @{ 1 = "Passed"; 2 = "Warning"; 3 = "Failed"; 4 = "Error" }

           return [PSCustomObject]@{
               DriftDetected  = ($currentSeverity -gt $baselineSeverity)
               CurrentStatus  = $CurrentStatus
               BaselineStatus = $reverseSeverityMap[$baselineSeverity]
               BaselineDate   = if ($baseline.fsi_timestamp) { $baseline.fsi_timestamp } else { $baseline.createdon }
               IsFirstRun     = $false
           }
       }
       catch {
           # Fail open — return drift detected to avoid suppressing alerts
           Write-Verbose "Drift detection failed: $($_.Exception.Message). Failing open."
           return [PSCustomObject]@{
               DriftDetected  = $true
               CurrentStatus  = $CurrentStatus
               BaselineStatus = $null
               BaselineDate   = $null
               IsFirstRun     = $null
               Error          = $_.Exception.Message
           }
       }
   }
   ```

3. Build validation parameters and call Test-SessionCompliance:
   ```powershell
   $validationParams = @{
       Zone       = $Zone
       ConfigPath = $ConfigPath
       TenantId   = $TenantId
       ClientId   = $ClientId
       CertificateThumbprint = $CertificateThumbprint
       DataverseUrl = $DataverseUrl
   }
   if ($SkipPimValidation) { $validationParams.SkipPimValidation = $true }

   $validationResults = Test-SessionCompliance @validationParams
   ```

4. Acquire Dataverse token via MSAL.PS:
   ```powershell
   Import-Module MSAL.PS -ErrorAction Stop
   $cert = Get-Item "Cert:\*\$CertificateThumbprint" -ErrorAction Stop
   $dataverseScope = "$($DataverseUrl.TrimEnd('/'))/.default"
   $tokenResult = Get-MsalToken -ClientId $ClientId -ClientCertificate $cert -TenantId $TenantId -Scopes $dataverseScope -ErrorAction Stop
   $dataverseToken = $tokenResult.AccessToken
   ```

5. Run drift detection:
   ```powershell
   $drift = Get-DriftStatus -DataverseUrl $DataverseUrl -DataverseToken $dataverseToken -CurrentStatus $validationResults.OverallStatus
   ```

6. Construct output object:
   ```powershell
   $output = [PSCustomObject]@{
       RunType       = "SessionValidation"
       Timestamp     = (Get-Date -AsUTC -Format "o")
       Zone          = $Zone
       OverallStatus = $validationResults.OverallStatus
       Reason        = $validationResults.Reason
       Validators    = $validationResults.Validators
       Drift         = $drift
       AlertRequired = ($drift.DriftDetected -or $validationResults.OverallStatus -ne "Passed")
       AlertSeverity = $validationResults.OverallStatus
   }
   ```

7. Output JSON to pipeline (no Write-Host):
   ```powershell
   $output | ConvertTo-Json -Depth 10
   ```

**Comment-based help:** Follow ACV pattern with .SYNOPSIS, .DESCRIPTION, .PARAMETER (all 7), .EXAMPLE, .OUTPUTS (JSON schema description), .NOTES (version 1.0.0, Azure Automation setup steps, performance notes).

Create the operator-initiated baseline capture script that snapshots live CA policy session controls to Dataverse.

**Script structure:**

```powershell
#Requires -Version 7.0
#Requires -Modules Microsoft.Graph.Identity.SignIns, MSAL.PS
```

**Parameters:**
- `[string]$Zone` — Mandatory, ValidateSet("Zone1", "Zone2", "Zone3")
- `[string]$DataverseUrl` — Mandatory, Dataverse environment URL
- `[string]$TenantId` — Mandatory, Azure AD tenant ID
- `[string]$ClientId` — Mandatory, Azure AD application ID
- `[string]$CertificateThumbprint` — Mandatory, Certificate for service principal auth
- `[switch]$Interactive` — Use interactive auth instead of certificate
- `[switch]$WhatIf` — Preview mode, shows what would be captured without writing to Dataverse

**Execution flow:**

1. **Connect to Microsoft Graph:**
   ```powershell
   if ($Interactive) {
       Connect-MgGraph -TenantId $TenantId -Scopes "Policy.Read.All"
   } else {
       Connect-MgGraph -TenantId $TenantId -ClientId $ClientId -CertificateThumbprint $CertificateThumbprint
   }
   ```

2. **Query live CA policies with session controls:**
   ```powershell
   $policies = Get-MgIdentityConditionalAccessPolicy | Where-Object {
       $_.State -eq "enabled" -and
       $_.SessionControls -and
       $_.SessionControls.SignInFrequency
   }
   ```

3. **Extract session control settings per policy:**
   ```powershell
   $sessionSettings = $policies | ForEach-Object {
       @{
           PolicyId                  = $_.Id
           PolicyName                = $_.DisplayName
           SignInFrequencyValue      = $_.SessionControls.SignInFrequency.Value
           SignInFrequencyType       = $_.SessionControls.SignInFrequency.Type
           PersistentBrowserMode     = $_.SessionControls.PersistentBrowser.Mode
           AuthenticationStrengthId  = $_.GrantControls.AuthenticationStrength.Id
           RequireCompliantDevice    = ($_.GrantControls.BuiltInControls -contains "compliantDevice")
           State                     = $_.State
       }
   }
   ```

4. **Normalize sign-in frequency to minutes** based on Zone defaults:
   ```powershell
   $zoneDefaults = @{
       "Zone1" = @{ SignInFrequencyMinutes = 480; AuthStrength = "standard" }
       "Zone2" = @{ SignInFrequencyMinutes = 240; AuthStrength = "passwordless" }
       "Zone3" = @{ SignInFrequencyMinutes = 60;  AuthStrength = "phishing-resistant" }
   }
   ```
   Extract the actual sign-in frequency from the first matching policy. If policies specify hours, convert to minutes. If no matching policies found, use zone defaults.

5. **Map zone to option set value:**
   ```powershell
   $zoneOptionSetMap = @{
       "Zone1" = 100000001
       "Zone2" = 100000002
       "Zone3" = 100000003
   }
   ```

6. **If -WhatIf:** Display captured settings to console as a formatted table and exit without writing to Dataverse.

7. **Acquire Dataverse token:**
   ```powershell
   Import-Module MSAL.PS -ErrorAction Stop
   if ($Interactive) {
       $tokenResult = Get-MsalToken -ClientId $ClientId -TenantId $TenantId -Scopes "$($DataverseUrl.TrimEnd('/'))/.default" -Interactive
   } else {
       $cert = Get-Item "Cert:\*\$CertificateThumbprint" -ErrorAction Stop
       $tokenResult = Get-MsalToken -ClientId $ClientId -ClientCertificate $cert -TenantId $TenantId -Scopes "$($DataverseUrl.TrimEnd('/'))/.default"
   }
   $dataverseToken = $tokenResult.AccessToken
   ```

8. **Deactivate existing active baselines for this zone:**
   Query `fsi_sessionbaselines?$filter=fsi_zone eq {zoneValue} and fsi_isactive eq true`
   For each result, PATCH to set `fsi_isactive = false`
   This ensures only one active baseline per zone.

9. **Create new SessionBaseline record:**
   POST to `$DataverseUrl/api/data/v9.2/fsi_sessionbaselines` with:
   ```json
   {
       "fsi_name": "Zone3-2026-02-07T06:00:00Z",
       "fsi_zone": {zoneOptionSetValue},
       "fsi_signinfrequencyminutes": {actualMinutes},
       "fsi_authstrength": "{authStrengthName}",
       "fsi_requirecompliantdevice": {boolean},
       "fsi_pimmaxactivationhours": null,
       "fsi_pimrequireapproval": null,
       "fsi_pimrequireauthcontext": null,
       "fsi_isactive": true,
       "fsi_capturedon": "{ISO 8601 UTC}",
       "fsi_rawjson": "{full session settings JSON}"
   }
   ```

10. **Output result as JSON:**
    ```powershell
    $result = [PSCustomObject]@{
        BaselineId            = $response.fsi_sessionbaselineid
        Zone                  = $Zone
        CapturedOn            = $capturedOn
        SignInFrequencyMinutes = $signInFrequencyMinutes
        AuthStrength          = $authStrength
        PoliciesCaptured      = $sessionSettings.Count
        PreviousBaselinesDeactivated = $deactivatedCount
    }
    $result | ConvertTo-Json -Depth 5
    ```

**Comment-based help:** .SYNOPSIS, .DESCRIPTION (explains baseline capture purpose and how it feeds drift detection), .PARAMETER (all 7), .EXAMPLE (interactive mode and certificate mode), .OUTPUTS, .NOTES (version 1.0.0, baseline management notes — single active per zone, deactivation of previous baselines).

**Key design decisions:**
- Manual operator action (not automated) per research recommendation
- Single active baseline per zone (deactivate before create)
- Captures full raw JSON for deep analysis in fsi_rawjson
- Supports both interactive and certificate auth
- WhatIf preview mode for safe operation
- JSON output to pipeline (no Write-Host in non-WhatIf mode)
- In WhatIf mode, use Write-Host for formatted preview (acceptable since not used in automation)
