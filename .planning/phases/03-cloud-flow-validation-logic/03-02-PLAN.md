# Plan 03-02: Notification Logic, Error Handling, Flow Finalization

## Objective

Extend `src/detect-inactivity-timeout-noncompliance.json` (created by Plan 03-01) with post-loop count aggregation, guarded email notification, flow-level Scope_Catch error handling, and flow metadata finalization. This completes the flow template.

## Must-Haves Addressed

| # | Must-Have | How Addressed |
|---|----------|---------------|
| 4 | Guarded notification: email only when Non-Compliant>0 OR Unknown>0; includes env/zone/actual/required/status; no empty notifications | Post-loop Dataverse queries + Condition_Has_Issues + HTML email via Office 365 SendEmailV2 |

## Tasks

### Task 1: Add post-loop aggregation queries

After `Apply_to_Each_Environment` (inside `Scope_Try`), add actions to count compliance results from the current scan run using Dataverse queries (required because concurrency > 1 prevents variable accumulators):

1. **`Query_NonCompliant_Records`** — Dataverse ListRecords:
   - `entityName`: `fsi_inactivitytimeoutcompliances`
   - `$filter`: `fsi_scanrunid eq '@{variables('ScanRunId')}' and fsi_compliancestatus eq 1`
   - `$select`: `fsi_environmentid,fsi_environmentname,fsi_zone,fsi_inactivitytimeoutenabled,fsi_timeoutduration,fsi_requiredmaxduration,fsi_compliancestatus,fsi_notes`
   - `runAfter`: `Apply_to_Each_Environment: ["Succeeded"]`
   - Description: "Query all Non-Compliant records from the current scan run for notification."

2. **`Query_Unknown_Records`** — Dataverse ListRecords:
   - `entityName`: `fsi_inactivitytimeoutcompliances`
   - `$filter`: `fsi_scanrunid eq '@{variables('ScanRunId')}' and fsi_compliancestatus eq 2`
   - `$select`: `fsi_environmentid,fsi_environmentname,fsi_zone,fsi_inactivitytimeoutenabled,fsi_timeoutduration,fsi_requiredmaxduration,fsi_compliancestatus,fsi_notes`
   - `runAfter`: `Apply_to_Each_Environment: ["Succeeded"]`
   - Description: "Query all Unknown records from the current scan run for notification."

3. **`Query_Compliant_Count`** — Dataverse ListRecords:
   - `entityName`: `fsi_inactivitytimeoutcompliances`
   - `$filter`: `fsi_scanrunid eq '@{variables('ScanRunId')}' and fsi_compliancestatus eq 0`
   - `$select`: `fsi_environmentid`
   - `$count`: true
   - `runAfter`: `Apply_to_Each_Environment: ["Succeeded"]`
   - Description: "Count Compliant records for scan summary statistics."

**Note:** Queries 1-3 can run in parallel (all depend only on `Apply_to_Each_Environment`).

**Acceptance criteria:**
- [ ] Queries filter by `fsi_scanrunid` to isolate current scan run
- [ ] Non-Compliant and Unknown queries retrieve full record details including `fsi_zone` for email body
- [ ] Compliant count query retrieves only count for summary statistics

### Task 2: Implement guarded notification condition

After the aggregation queries, add the notification guard:

1. **`Condition_Has_Issues`** — If condition:
   - Expression (OR):
     ```json
     {
       "or": [
         { "greater": ["@length(body('Query_NonCompliant_Records')?['value'])", 0] },
         { "greater": ["@length(body('Query_Unknown_Records')?['value'])", 0] }
       ]
     }
     ```
   - `runAfter`:
     - `Query_NonCompliant_Records: ["Succeeded"]`
     - `Query_Unknown_Records: ["Succeeded"]`
     - `Query_Compliant_Count: ["Succeeded"]`

2. **True branch (issues found):** proceed to Task 3

3. **False branch (all compliant):** empty actions `{}` — no email sent

**Acceptance criteria:**
- [ ] Condition checks `length > 0` on both Non-Compliant and Unknown result sets
- [ ] Uses OR logic — notification fires if either has results
- [ ] False branch explicitly does nothing (no empty email sent)

### Task 3: Compose and send the compliance alert email

Inside `Condition_Has_Issues` **true branch**:

1. **`Compose_Email_Subject`** — Compose:
   ```
   @{concat('[NON-COMPLIANT] Inactivity Timeout Compliance Scan — ', 
     string(add(length(body('Query_NonCompliant_Records')?['value']), length(body('Query_Unknown_Records')?['value']))),
     ' issue(s) detected')}
   ```

2. **`Compose_Email_Body`** — Compose HTML:
   ```html
   <html>
   <body>
     <h2>Inactivity Timeout Compliance Scan Results</h2>
     <p><strong>Scan Date:</strong> @{utcNow()}</p>
     <p><strong>Scan Run ID:</strong> @{variables('ScanRunId')}</p>
     <hr/>
     <h3>Summary</h3>
     <table border='1' cellpadding='5' style='border-collapse:collapse;'>
       <tr><td><strong>Compliant</strong></td><td>@{length(body('Query_Compliant_Count')?['value'])}</td></tr>
       <tr><td><strong>Non-Compliant</strong></td><td>@{length(body('Query_NonCompliant_Records')?['value'])}</td></tr>
       <tr><td><strong>Unknown</strong></td><td>@{length(body('Query_Unknown_Records')?['value'])}</td></tr>
     </table>
     <hr/>
     <h3>Issues Requiring Attention</h3>
     <table border='1' cellpadding='5' style='border-collapse:collapse;'>
       <tr style='background-color:#f0f0f0;'>
         <th>Environment</th>
         <th>Zone</th>
         <th>Status</th>
         <th>Timeout Enabled</th>
         <th>Actual Duration (min)</th>
         <th>Required Max (min)</th>
         <th>Notes</th>
       </tr>
       <!-- Non-Compliant rows built via Select + Join -->
       @{join(body('Build_Issue_Rows'), '')}
     </table>
     <hr/>
     <p><em>This alert was generated by the ITE - Detect Inactivity Timeout Non-Compliance flow. 
     Part of the FSI Agent Governance — Inactivity Timeout Enforcement solution. 
     Supports compliance with GLBA 501(b), SOX 302, FINRA 4511.</em></p>
   </body>
   </html>
   ```

3. **`Build_Issue_Rows`** — Select action on union of Non-Compliant + Unknown arrays:
   - Input: `@union(body('Query_NonCompliant_Records')?['value'], body('Query_Unknown_Records')?['value'])`
   - Map: produce HTML table row string per record with environment name, zone, status, timeout enabled, actual duration, required max, and notes

4. **`Send_Alert_Email`** — Office 365 SendEmailV2:
   - `emailMessage/To`: `@variables('NotificationRecipients')`
   - `emailMessage/Subject`: `@outputs('Compose_Email_Subject')`
   - `emailMessage/Body`: `@outputs('Compose_Email_Body')`
   - `emailMessage/Importance`: `"High"`
   - Connection: `shared_office365`
   - Description: "Send compliance alert email with Non-Compliant and Unknown environment details. Only sent when issues are detected (guarded notification)."

**Acceptance criteria:**
- [ ] Email includes scan summary (compliant/non-compliant/unknown counts)
- [ ] Email includes per-environment detail table with environment, zone, status, timeout enabled, actual duration, required max, notes
- [ ] Email subject contains issue count
- [ ] Email references regulatory alignment (GLBA, SOX, FINRA)
- [ ] Uses Office 365 `SendEmailV2` operation (not Teams)
- [ ] Importance set to High

### Task 4: Implement Scope_Catch for flow-level error handling

Add `Scope_Catch` as a sibling to `Scope_Try` in the top-level actions:

1. **`Scope_Catch`** — Scope:
   - `runAfter`: `{ "Scope_Try": ["Failed", "TimedOut"] }`
   - Description: "Error handling scope: catches unexpected failures in Scope_Try and sends CRITICAL notification email."

2. **Inside Scope_Catch:**

   a. **`Send_Flow_Error_Email`** — Office 365 SendEmailV2:
      - `emailMessage/To`: `@variables('NotificationRecipients')`
      - `emailMessage/Subject`: `"[CRITICAL] ITE Inactivity Timeout Compliance Scan — Flow Failure"`
      - `emailMessage/Body`:
        ```html
        <html><body>
          <h2>[CRITICAL] Inactivity Timeout Compliance Scan — Flow Failure</h2>
          <p>The ITE daily compliance scan flow encountered an unexpected error during execution.</p>
          <table border='1' cellpadding='5' style='border-collapse:collapse;'>
            <tr><td><strong>Flow Run ID</strong></td><td>@{workflow()['run']['name']}</td></tr>
            <tr><td><strong>Timestamp</strong></td><td>@{utcNow()}</td></tr>
            <tr><td><strong>Scan Run ID</strong></td><td>@{variables('ScanRunId')}</td></tr>
          </table>
          <p>Please investigate the flow run history in the <a href='https://make.powerautomate.com'>Power Automate portal</a>.</p>
          <p><em>This alert was generated by the ITE - Detect Inactivity Timeout Non-Compliance flow.</em></p>
        </body></html>
        ```
      - `emailMessage/Importance`: `"High"`
      - Description: "Send CRITICAL email when the flow encounters an unhandled failure."

**Acceptance criteria:**
- [ ] Scope_Catch runs after Scope_Try on `["Failed", "TimedOut"]`
- [ ] Error email includes flow run ID, timestamp, and scan run ID
- [ ] Error email links to Power Automate portal for investigation
- [ ] Uses same `NotificationRecipients` variable as alert email

## Notes

- This plan depends on Plan 03-01 which creates the base flow template. The post-loop queries reference `Apply_to_Each_Environment` and `ScanRunId` variable created by Plan 03-01.
- The email body uses `union()` to combine Non-Compliant and Unknown records before building the HTML table. This avoids two separate tables and provides a unified view.
- The `Build_Issue_Rows` action uses a Select action to transform Dataverse records into HTML table row strings, then `join()` concatenates them. This pattern avoids complex inline expression nesting in the email body.
- No Teams adaptive card is needed — email-only notification per FLW-03 requirements. This simplifies the connection reference set (no `shared_teams` connector).
- The Scope_Catch error email pattern matches CAA's `Send_Flow_Error_Email` pattern.
