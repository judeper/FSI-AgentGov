# Plan 03-01: RBAC Guide & Deployment Playbook

**Phase:** 3 — Deployment & Customization
**Requirements:** DEP-01 (RBAC configuration), DEP-02 (Deployment playbook)
**Wave:** 1 (no dependencies on other Phase 3 plans)

## Objective

Create a deployment guide that enables enterprise teams to import the Agent Usage & Performance Workbook into their Azure environment with proper RBAC configuration, solving the ALM separation-of-duties gap identified in Control 2.8.

## Must-Haves Addressed

| # | Must-Have | How Addressed |
|---|----------|---------------|
| 1 | RBAC configuration guide: Application Insights Reader role assignment | Dedicated RBAC section with role tables, persona mapping, CLI/PowerShell commands, ALM scenario explanation |
| 2 | Deployment playbook: ARM template or manual import, prerequisites, validation checklist | Full deployment guide with prerequisites checklist, manual import steps, ARM template option, post-deployment validation |

## Tasks

### Task 1: Create deployment-guide.md

**File:** `docs/playbooks/advanced-implementations/agent-usage-workbook/deployment-guide.md`
**Action:** Create new file (~280-320 lines)
**Pattern:** Follow CAA deployment guide format (`docs/playbooks/advanced-implementations/conditional-access-automation/deployment-guide.md`)

**Content structure:**

```markdown
# Agent Usage & Performance Workbook — Deployment Guide

**Status:** February 2026 — FSI-AgentGov v1.2.38
**Related Controls:** 3.1, 3.2, 3.3, 3.7, 3.8, 2.8, 2.9

---

## Overview
- Purpose: deploy the workbook and configure RBAC for read-only access
- Estimated time: 30-60 minutes
- Link to workbook source: src/agent-usage-workbook.json
- ALM scenario: solving separation-of-duties gap (Control 2.8)

## Prerequisites Checklist
- Azure subscription with Contributor access
- Application Insights resource (workspace-based)
- Copilot Studio agents connected to Application Insights
- "Log activities" enabled per agent
- At least one completed (non-test canvas) conversation
- Telemetry verified in customEvents table

## Step 1: Configure RBAC Access
### Option A: Read-Only Access for Workbook Consumers (DEP-01)
- Required roles: Monitoring Reader + Workbook Reader
- Persona-based RBAC table (Operations, Compliance, Executive, Support, Workbook Admin)
- az role assignment create commands
- PowerShell equivalent (New-AzRoleAssignment)
- ALM separation-of-duties explanation (Control 2.8 reference)
- Regulatory alignment note (SOX 302/404, FINRA 3110)

### Option B: Workbook Administrator Access
- Workbook Contributor + Monitoring Reader
- When to use: initial deployment, ongoing modifications

## Step 2: Import Workbook (Manual)
### 2.1: Open Application Insights Workbooks
- Portal navigation: Azure Portal > Application Insights > Workbooks
### 2.2: Open Advanced Editor
- Click + New > Advanced Editor (</>)
- Set Template Type to Gallery Template
### 2.3: Paste Workbook JSON
- Download or copy src/agent-usage-workbook.json
- Paste into editor, click Apply
### 2.4: Save Workbook
- Configure: Title, Subscription, Resource Group, Location
### 2.5: Configure Parameters
- Update fallbackResourceIds with actual resource ID
- Adjust MinutesSaved (default: 5) and HourlyRate (default: 75)

## Step 3: Import Workbook (ARM Template — Optional)
### 3.1: ARM Template Structure
- Microsoft.Insights/workbooks resource type
- serializedData containing workbook JSON
- Parameterized applicationInsightsId
### 3.2: Deploy via Azure CLI
- az deployment group create command
### 3.3: Deploy via PowerShell
- New-AzResourceGroupDeployment command

## Step 4: Post-Deployment Validation
- Validation checklist (10+ items)
- Positive RBAC verification (Monitoring Reader can view data)
- Negative RBAC verification (no access = denied)
- Telemetry flow verification KQL
- Anomaly detection caveat (14-day baseline needed)

## ALM Separation-of-Duties Scenario
- Problem: PPAC Analytics requires admin roles
- Solution: App Insights workbook via Monitoring Reader
- Control 2.8 reference
- Regulatory alignment

## Troubleshooting
- Issue/Cause/Resolution table
- Common issues: authentication, empty data, parameter errors, RBAC errors
- Diagnostic steps
- Log locations
```

**Language rules compliance:**
- Use "supports compliance with" not "ensures compliance"
- Use "aids in meeting" not "guarantees"
- Include implementation caveats throughout
- Use canonical role names from role-catalog.md
