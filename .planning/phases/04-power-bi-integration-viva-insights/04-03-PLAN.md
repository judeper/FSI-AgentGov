**Why stored functions (not materialized views):** Materialized views are NOT available in Log Analytics workspace — only in Azure Data Explorer clusters. Functions are parameterizable (date range filtering at source) and version-controllable in git.

**vw_session_fact.kql:**
Purpose: Pre-aggregate customEvents into session-level fact for Power BI Import mode consumption. Output schema aligns with FactAgentSessions.tmdl columns.

```kql
// Function signature: vw_session_fact(startDate:datetime, endDate:datetime)
// Deploy: .create-or-alter function vw_session_fact(startDate:datetime, endDate:datetime)

customEvents
| where timestamp between (startDate .. endDate)
| where name in ("BotMessageReceived", "BotMessageSend")
| where tostring(customDimensions['DesignMode']) == "False"
| extend
    AgentId = tostring(customDimensions["recipientId"]),
    ZoneId = tostring(customDimensions["Zone"]),
    ErrorCode = tostring(customDimensions["errorCodeText"]),
    LatencyMs = todouble(customDimensions["latencyMs"])
| summarize
    SessionCount = dcount(session_Id),
    MessageCount = count(),
    ErrorCount = countif(isnotempty(ErrorCode)),
    AvgLatencyMs = avg(LatencyMs),
    P95LatencyMs = percentile(LatencyMs, 95),
    CompletionRate = todouble(dcountif(session_Id, name == "BotMessageSend")) / dcount(session_Id)
    by SessionDate = bin(timestamp, 1d), AgentId, ZoneId
| project
    SessionDate,
    AgentId,
    ZoneId,
    SessionCount,
    MessageCount,
    ErrorCount,
    AvgLatencyMs,
    P95LatencyMs,
    CompletionRate
| order by SessionDate desc, SessionCount desc
```

Include comments documenting:
- Expected row count (~agents × days in range)
- Pro license 1GB limit guidance: 90-day window recommended for <100 agents, 30-day for >100 agents
- Integration pattern: M query calling function with parameterized date range

**vw_event_fact.kql:**
Purpose: Event-level detail for Power BI drill-down and audit trail. Output schema aligns with FactAgentEvents.tmdl columns.

```kql
// Function signature: vw_event_fact(startDate:datetime, endDate:datetime)

customEvents
| where timestamp between (startDate .. endDate)
| where name in ("BotMessageReceived", "BotMessageSend")
| where tostring(customDimensions['DesignMode']) == "False"
| extend
    EventTimestamp = timestamp,
    EventDateKey = toint(format_datetime(timestamp, "yyyyMMdd")),
    AgentId = tostring(customDimensions["recipientId"]),
    SessionId = session_Id,
    EventType = name,
    LatencyMs = todouble(customDimensions["latencyMs"]),
    ErrorCategoryId = iff(
        isnotempty(tostring(customDimensions["errorCodeText"])),
        tostring(customDimensions["errorCategory"]),
        ""
    ),
    UserId = hash_sha256(tostring(customDimensions["from_Id"])),
    ControlId = tostring(customDimensions["controlId"])
| project
    EventTimestamp,
    EventDateKey,
    AgentId,
    SessionId,
    EventType,
    LatencyMs,
    ErrorCategoryId,
    UserId,
    ControlId
| order by EventTimestamp desc
```

Include comments:
- WARNING: This function returns high-volume data. Use with DirectQuery (Premium) or short date ranges (7-14 days) for Import mode.
- UserId is SHA-256 hashed per Phase 2 PII convention.

**vw_dim_agent.kql:**
Purpose: Build agent dimension from telemetry metadata. Output schema aligns with DimAgent.tmdl.

```kql
// Function signature: vw_dim_agent()
// No date parameters — returns distinct agents from all time

customEvents
| where name in ("BotMessageReceived", "BotMessageSend")
| where tostring(customDimensions['DesignMode']) == "False"
| extend
    AgentId = tostring(customDimensions["recipientId"]),
    AgentName = tostring(customDimensions["recipientName"]),
    ZoneId = tostring(customDimensions["Zone"]),
    EnvironmentId = tostring(customDimensions["environmentId"])
| summarize
    AgentName = take_any(AgentName),
    ZoneId = take_any(ZoneId),
    EnvironmentId = take_any(EnvironmentId),
    FirstSeen = min(timestamp),
    LastSeen = max(timestamp),
    TotalSessions = dcount(session_Id)
    by AgentId
| extend
    AgentType = case(
        isnotempty(tostring(customDimensions["copilotStudioAgent"])), "CopilotStudio",
        isnotempty(tostring(customDimensions["agent365Sdk"])), "Agent365SDK",
        "AgentBuilder"
    ),
    IsProduction = (ZoneId in ("Zone2", "Zone3")),
    CreatedDate = FirstSeen,
    Description = strcat("Agent ", AgentName, " in ", ZoneId)
| project
    AgentId,
    AgentName,
    AgentType,
    ZoneId,
    EnvironmentId,
    IsProduction,
    CreatedDate,
    Description
```

Note: AgentType inference is heuristic — may need customization based on actual telemetry properties. Document this clearly.

# Connector Decision Matrix: ADX Connector vs DirectQuery

## Overview
Two paths to connect Power BI to your agent observability telemetry. Choose based on licensing, performance, and data freshness requirements.

## Decision Matrix

| Criteria | ADX Connector (Import) | DirectQuery |
|----------|----------------------|-------------|
| **License Required** | Power BI Pro ($10/user/month) | Premium/PPU ($20/user/month) or Fabric F-SKU |
| **Data Freshness** | Scheduled refresh (1-8x/day Pro, 1-48x/day Premium) | Real-time (live queries) |
| **Dataset Size Limit** | 1 GB (Pro), 10 GB (Premium) | No dataset limit (queries on-demand) |
| **Query Performance** | Fast (data cached locally) | Depends on Log Analytics query speed |
| **Recommended For** | Daily/weekly executive review, small-medium deployments (<100 agents) | Real-time monitoring, large deployments (>100 agents), event-level drill-down |
| **Pre-Aggregation** | Required (use vw_session_fact KQL function) | Optional (can query raw events) |
| **Offline Access** | Yes (cached data) | No (requires network) |
| **RLS Overhead** | Minimal (filtered at import) | Per-query evaluation |
| **Cost Impact** | KQL query cost at refresh time only | KQL query cost per visual interaction |

## Decision Flowchart
[Markdown flowchart/decision tree:]
1. Do you have Premium/PPU or Fabric F-SKU? → YES → Consider DirectQuery for real-time, Import for performance
2. → NO (Pro only) → Use ADX Connector with Import mode
3. Do you need real-time data (<15 min staleness)? → YES → DirectQuery (requires Premium)
4. → NO → Import mode with scheduled refresh
5. Do you have >100 agents? → YES → Pre-aggregate with vw_session_fact, consider 30-day window
6. → NO → 90-day window with vw_session_fact

## ADX Connector Setup (Import Mode)
Step-by-step with screenshots placeholders:

2. Enter Log Analytics workspace URL
3. Enter KQL function call: vw_session_fact(datetime(start), datetime(end))

6. Configure scheduled refresh in Power BI Service

## .pbit Template Deployment

   - Workspace URL: your Log Analytics workspace URL

## Known Limitations
- ADX Import: 1 GB Pro limit — use pre-aggregation for event data
- DirectQuery: No offline, higher per-query cost
- .pbit: Known measure loss bug — validate after opening (see Troubleshooting)
