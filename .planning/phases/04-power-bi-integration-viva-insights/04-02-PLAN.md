Create the centralized DAX measures file. All measures go in a single TMDL file organized by category with comment headers.

**TMDL measure syntax:**
```
table _Measures

    measure MeasureName = DAX_EXPRESSION
        formatString: "format"
        displayFolder: "Folder Name"
```

Use a calculated table named `_Measures` (underscore prefix sorts to top of field list). This is a common Power BI pattern for centralizing measures.

**Category 1: Core Session Metrics (PBI-02 requirement)**

```dax
Total Sessions = SUM(FactAgentSessions[SessionCount])
    formatString: "#,0"
    displayFolder: "Session Metrics"

Total Messages = SUM(FactAgentSessions[MessageCount])
    formatString: "#,0"
    displayFolder: "Session Metrics"

Total Errors = SUM(FactAgentSessions[ErrorCount])
    formatString: "#,0"
    displayFolder: "Session Metrics"

Avg Completion Rate = AVERAGE(FactAgentSessions[CompletionRate])
    formatString: "0.0%"
    displayFolder: "Session Metrics"

Active Agents = DISTINCTCOUNT(FactAgentSessions[AgentId])
    formatString: "#,0"
    displayFolder: "Session Metrics"
```

**Category 2: Latency Metrics (PBI-02 requirement)**

```dax
Avg Latency (ms) = AVERAGE(FactAgentSessions[AvgLatencyMs])
    formatString: "#,0.0"
    displayFolder: "Latency"

P95 Latency (ms) = AVERAGE(FactAgentSessions[P95LatencyMs])
    formatString: "#,0.0"
    displayFolder: "Latency"
```

Note: P95 at session-grain is an average of daily P95 values. For precise P95 across all events, use FactAgentEvents with PERCENTILE.INC (requires Premium/Import mode for large datasets). Document this caveat in the integration guide.

**Category 3: Error Rate Metrics (PBI-02 requirement)**

```dax
Error Rate =
    DIVIDE(
        SUM(FactAgentSessions[ErrorCount]),
        SUM(FactAgentSessions[MessageCount])
    )
    formatString: "0.0%"
    displayFolder: "Error Rates"

Error Rate by Zone =
    DIVIDE(
        SUM(FactAgentSessions[ErrorCount]),
        SUM(FactAgentSessions[MessageCount])
    )
    formatString: "0.0%"
    displayFolder: "Error Rates"
    /// Same formula — zone filtering comes from slicer context on DimZone
```

**Category 4: Compliance Score (per research weighted calculation)**

```dax
Compliance Score =
    VAR TotalWeightedControls =
        SUMX(
            DimControl,
            DimControl[PillarWeight]
        )
    VAR WeightedCompleteControls =
        SUMX(
            FILTER(
                DimControl,
                RELATED(FactAgentEvents[ControlId]) <> BLANK()
            ),
            DimControl[PillarWeight]
        )
    RETURN
        DIVIDE(WeightedCompleteControls, TotalWeightedControls) * 100
    formatString: "0.0"
    displayFolder: "Compliance"
```

Note: The compliance score above is a simplified pattern. In practice, evidence status should come from a control evidence tracking system. Document in the integration guide that this measure should be customized based on the organization's evidence collection workflow. Provide the Pillar 1=40%, Pillar 2=30%, Pillar 3=20%, Pillar 4=10% weighting per research.

```dax
Control Coverage % =
    DIVIDE(
        COUNTROWS(
            FILTER(DimControl, NOT(ISBLANK(DimControl[ControlId])))
        ),
        COUNTROWS(DimControl)
    ) * 100
    formatString: "0.0%"
    displayFolder: "Compliance"

Regulatory Gaps =
    COUNTROWS(
        FILTER(
            DimRegulation,
            ISBLANK(
                CALCULATE(
                    COUNTROWS(FactAgentEvents),
                    ALLEXCEPT(DimRegulation, DimRegulation[RegulationId])
                )
            )
        )
    )
    formatString: "#,0"
    displayFolder: "Compliance"
```

**Category 5: Trend Measures (Claude's discretion — applying WoW/MoM to high-value executive measures)**

Apply WoW and MoM to: Total Sessions, Error Rate, Avg Latency. These are the three measures executives monitor for trend direction. Point-in-time is sufficient for: Compliance Score, Active Agents, Control Coverage % (these change slowly).

```dax
Sessions WoW =
    VAR CurrentWeek = [Total Sessions]
    VAR PriorWeek =
        CALCULATE(
            [Total Sessions],
            DATEADD(DimDate[Date], -7, DAY)
        )
    RETURN
        DIVIDE(CurrentWeek - PriorWeek, PriorWeek)
    formatString: "+0.0%;-0.0%;0.0%"
    displayFolder: "Trends"

Sessions MoM =
    VAR CurrentMonth = [Total Sessions]
    VAR PriorMonth =
        CALCULATE(
            [Total Sessions],
            DATEADD(DimDate[Date], -1, MONTH)
        )
    RETURN
        DIVIDE(CurrentMonth - PriorMonth, PriorMonth)
    formatString: "+0.0%;-0.0%;0.0%"
    displayFolder: "Trends"

Error Rate WoW =
    VAR CurrentWeek = [Error Rate]
    VAR PriorWeek =
        CALCULATE(
            [Error Rate],
            DATEADD(DimDate[Date], -7, DAY)
        )
    RETURN
        CurrentWeek - PriorWeek
    formatString: "+0.0%;-0.0%;0.0%"
    displayFolder: "Trends"
    /// Note: Error rate trend is absolute change (not %), since base rate is already %

Avg Latency WoW =
    VAR CurrentWeek = [Avg Latency (ms)]
    VAR PriorWeek =
        CALCULATE(
            [Avg Latency (ms)],
            DATEADD(DimDate[Date], -7, DAY)
        )
    RETURN
        DIVIDE(CurrentWeek - PriorWeek, PriorWeek)
    formatString: "+0.0%;-0.0%;0.0%"
    displayFolder: "Trends"
```

**Category 6: Event-Level Measures (for drill-down using USERELATIONSHIP)**

```dax
Event Count =
    CALCULATE(
        COUNTROWS(FactAgentEvents),
        USERELATIONSHIP(FactAgentEvents[EventDateKey], DimDate[DateKey])
    )
    formatString: "#,0"
    displayFolder: "Event Detail"

Event Error Rate =
    CALCULATE(
        DIVIDE(
            COUNTROWS(FILTER(FactAgentEvents, NOT(ISBLANK(FactAgentEvents[ErrorCategoryId])))),
            COUNTROWS(FactAgentEvents)
        ),
        USERELATIONSHIP(FactAgentEvents[EventDateKey], DimDate[DateKey])
    )
    formatString: "0.0%"
    displayFolder: "Event Detail"
```

# Power BI Integration Guide

## Overview
Executive-facing compliance dashboards and agent observability analytics. No KQL knowledge required.

## Prerequisites
- Power BI Desktop (June 2022 or newer)
- Power BI Pro license (ADX connector) or Premium/PPU/Fabric F-SKU (DirectQuery)
- Read access to Log Analytics workspace
- Agent Observability Foundation deployed (Phase 1-3)

## Executive Dashboard Design

### Page 1: Compliance Posture (Landing Page)
Top-level KPIs: Compliance Score, Control Coverage %, Active Agents, Zone Health.
Card visuals for each KPI with conditional formatting (green >90%, yellow 80-90%, red <80%).
Zone health summary as matrix: Zone × Pillar showing evidence status.
This is the first page executives see — optimized for quick health check.

### Page 2: Regulation Drill-Down
**Valuable for regulatory examination readiness.**
Slicer: Select regulation (FINRA 3110, SEC 17a-4, SR 11-7, SOX 302/404, GLBA 501(b), OCC 2011-12, CFTC 1.31).
For selected regulation: list of required controls, evidence status per control, gap identification.
Table visual: ControlId | ControlName | EvidenceStatus | LastVerified | GapDescription
Use DimRegulation and DimControl with governance-mapping.md data to populate.
Frame as exam prep tool: "Use this page to prepare documentation packages for regulatory examinations."

### Page 3: Operational Health
Mirrors the Azure Monitor Operational Health workbook (Phase 3) in Power BI format.
Session trends (line chart, 30-day), Error Rate by Zone (clustered bar), Latency P95 trend (line chart).
WoW/MoM trend indicators next to each KPI card.
This page provides the same data as KQL workbooks but in a format executives can self-serve.

### Page 4: Adoption Trends
Agent adoption over time (line chart: active agents by month).
Session volume trend with MoM growth indicator.
Channel distribution (if available from telemetry — DirectLine, Teams, etc.).
Zone distribution donut chart showing agent count by zone.

### Page 5: Agent Detail
Drill-through page — right-click any agent in other pages to navigate here.
Agent metadata: Name, Type, Zone, Environment, Created Date.
Agent-specific metrics: Sessions, Error Rate, Avg Latency, Completion Rate.
Event-level grid for detailed audit trail (uses FactAgentEvents with USERELATIONSHIP measures).

## Deployment

### Option A: Using .pbit Template (Quick Start)
1. Download `agent-compliance-dashboard.pbit`
2. Open in Power BI Desktop — parameter prompt appears
3. Enter Log Analytics Workspace URL
4. Enter reporting date range (Start Date, End Date)
5. Click Load — data refreshes from workspace
6. Publish to Power BI Service workspace

### Option B: Building from TMDL (Customization)
1. Clone the repository
2. Open Power BI Desktop → File → Open → Navigate to semantic-model/ folder
3. Power BI Desktop imports TMDL definitions
4. Configure data source connection to your Log Analytics workspace
5. Customize measures, add organization-specific fields
6. Save as .pbix and publish

## Row-Level Security (RLS)

### How Zone-Based RLS Works
- Single role: ZoneBasedAccess
- Uses USERNAME() to resolve current user's email
- LOOKUPVALUE() checks UserZoneMapping table for user's assigned zone
- Filter applied to DimZone — relationships propagate to all fact tables
- Unmatched users see NO data (secure default: FALSE())

### Setting Up RLS
1. Populate UserZoneMapping table (CSV import or Entra ID sync)
2. Publish report to Power BI Service
3. Go to dataset Settings → Row-Level Security
4. Add users/security groups to ZoneBasedAccess role
5. Test with "View as" feature — verify correct zone data visible

### RLS Performance Testing
1. Open Performance Analyzer in Power BI Desktop
2. Start recording
3. Use View As → ZoneBasedAccess role → specific user
4. Refresh all visuals and compare query times
5. Acceptable: <2x overhead vs no RLS
6. If >3x: review relationship directions, check DimZone filter propagation

## Refresh Strategy

### ADX Connector (Import Mode — Pro License)
- Scheduled refresh: 1x daily recommended (8x/day max on Pro)
- Data flows through KQL pre-aggregation functions (vw_session_fact, vw_event_fact)
- Rolling window: 90 days default (configurable in KQL function parameters)
- Pro tip: Schedule refresh after midnight to capture full previous day

### DirectQuery (Premium/PPU/Fabric F-SKU)
- No scheduled refresh — queries live data
- Performance depends on Log Analytics query speed
- Best for: real-time compliance monitoring, live dashboards
- Caveat: Higher query costs against Log Analytics workspace

### Hybrid Approach (Premium/PPU/Fabric F-SKU)
- FactAgentSessions: Import mode with daily refresh (small dataset, fast visuals)
- FactAgentEvents: DirectQuery (large dataset, event-level drill-down on demand)
- Requires Premium/PPU or Fabric F-SKU for dual storage mode

## Fiscal Year Configuration
Default: Calendar year (January 1 - December 31).
To change: Edit DimDate table generation to set FiscalYear and FiscalQuarter based on organization's fiscal year end.
DAX time intelligence functions that use fiscal year: pass year_end_date parameter (e.g., TOTALYTD([Total Sessions], DimDate[Date], "6/30") for June 30 fiscal year end).

## Customization Guide
- Adding custom dimensions: Create new Dim*.tmdl in tables/ directory
- Adding measures: Append to CoreMetrics.tmdl following existing pattern
- Modifying RLS: Edit ZoneBasedAccess.tmdl filterExpression
- Adding dashboard pages: Use Power BI Desktop, reference existing measure names
