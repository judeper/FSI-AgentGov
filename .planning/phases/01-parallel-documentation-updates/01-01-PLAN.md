# Plan 01-01: Dataverse Purview Audit Deprecation

## Goal

Add a critical deprecation warning to Control 1.7 about the May 2026 Dataverse Purview audit event changes, provide Dataverse API alternative guidance, update regulatory-mappings.md for SEC 17a-4 / FINRA 4511 implications, and confirm that Controls 1.10 and 2.1 are unaffected.

## Requirements Covered

FCR-01, FCR-02, FCR-03

## Tasks

### Task 1: Add deprecation warning to Control 1.7

**File:** `docs/controls/pillar-1-security/1.7-comprehensive-audit-logging-and-compliance.md`

**Action:** Add a `!!! danger "Critical: Dataverse Purview Audit Event Changes — May 2026"` admonition in the Key Configuration Points section, near the existing "Dataverse Environment-Level Audit Configuration" subsection (around lines 138-143).

**Content to add:**
- Starting May 2026, Dataverse will no longer include before-and-after field change values in audit events sent to Microsoft Purview
- Organizations requiring detailed field-level change data for regulatory recordkeeping must retrieve this data directly from Dataverse APIs
- This affects SEC 17a-4 / FINRA 4511 compliance programs that rely on Purview audit integration for Dataverse field-level change records
- Include guidance: "Organizations should begin transitioning to Dataverse API-based audit retrieval before May 2026"
- Cross-reference: Link to regulatory-mappings.md for detailed regulatory impact

**Language rules:**
- Use "may affect" not "will break"
- Use "organizations should" not "organizations must" (except for regulatory requirements)
- Use hedged language: "supports compliance with", "required for"

**Acceptance criteria:**
- [ ] `!!! danger` admonition present with May 2026 deadline
- [ ] Dataverse API alternative clearly stated
- [ ] SEC 17a-4 and FINRA 4511 referenced
- [ ] Hedged, FSI-safe language used throughout
- [ ] Version footer updated to current month
