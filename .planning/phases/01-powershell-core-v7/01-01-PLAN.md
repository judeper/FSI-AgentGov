### Task 3: Create per-environment Dataverse authentication helper

```powershell
<#
.SYNOPSIS
    Obtains a Dataverse access token for a specific Power Platform environment.
.DESCRIPTION
    Acquires an OAuth2 access token scoped to the environment's Dataverse endpoint.
    Supports interactive authentication and service principal authentication.
    Implements token caching to avoid redundant token requests when scanning
    multiple environments.
#>
function Connect-EnvironmentDataverse {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory)]
        [string]$DataverseUrl,

        [Parameter()]
        [string]$TenantId,

        [Parameter()]
        [PSCredential]$ServicePrincipal,

        [Parameter()]
        [switch]$UseInteractive
    )

    # Implementation:
    # 1. Check token cache for unexpired token for this DataverseUrl
    # 2. If cached, return cached token
    # 3. If ServicePrincipal provided, use client credentials flow
    # 4. If UseInteractive, use device code or interactive browser flow
    # 5. Default: use Az.Accounts Get-AzAccessToken if already connected
    # 6. Cache token with expiry
    # Returns: [string] Access token
}
```

**Acceptance Criteria:**

### Task 5: Create expected moderation level lookup

Create `scripts/private/Get-ExpectedModerationLevel.ps1`:

```powershell
<#
.SYNOPSIS
    Returns the expected content moderation level for a given zone.
.DESCRIPTION
    Looks up the minimum required content moderation level from moderation-baseline.json.
    Returns the expected level and violation severity if current level is below expected.
#>
function Get-ExpectedModerationLevel {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory)]
        [ValidateSet('Zone1', 'Zone2', 'Zone3', 'Unknown')]
        [string]$Zone,

        [Parameter(Mandatory)]
        [ValidateSet('Low', 'Medium', 'High', 'Unknown')]
        [string]$CurrentLevel,

        [Parameter()]
        [string]$BaselinePath
    )

    # Returns:
    # [PSCustomObject]@{
    #     ExpectedLevel     = [string]   # 'Medium' or 'High'
    #     IsCompliant       = [bool]
    #     Severity          = [string]   # 'Critical'/'High'/'Medium'/null
    #     RegulatoryContext = [string]   # From baseline JSON
    # }
}
```

**Acceptance Criteria:**
- [ ] Loads moderation-baseline.json (with path fallback to `$PSScriptRoot/../templates/`)
- [ ] Implements full severity matrix from REQUIREMENTS.md (CMV-03)
- [ ] Returns null severity for compliant agents
- [ ] Handles 'Unknown' zone with Warning severity

### Task 8: Schema discovery — Validate Dataverse bot table structure

Query a test environment's Dataverse `bot` and `botcomponent` tables to confirm the exact schema for content moderation settings. This mitigates Research Risk 3.1 (HIGH — API availability).

**Discovery queries:**
```
GET https://{env}.crm.dynamics.com/api/data/v9.2/bots?$select=botid,name,configuration,statecode,statuscode&$top=5
GET https://{env}.crm.dynamics.com/api/data/v9.2/botcomponents?$filter=_botid_value eq '{botid}'&$select=componenttype,content&$top=20
```

**Document findings for:**
1. Exact column name for content moderation level (in `bot.configuration` JSON or `botcomponent.content`)
2. Value representation — string ("High"/"Medium"/"Low") vs. integer enum vs. JSON nested property
3. Which `botcomponent.componenttype` value corresponds to generative AI settings
4. Whether moderation setting is present on draft/unpublished agents

**Acceptance Criteria:**
- [ ] Schema findings documented in inline comments in `CMMClient.psm1` `Get-BotModerationLevel` function
- [ ] Confirmed column paths for moderation level extraction
- [ ] Value normalization logic handles discovered representation format
- [ ] Draft agent availability documented (affects CMV-05 implementation in Plan 01-02)
