# Phase 3 Plan 2: Remediation Approval Workflow with Adaptive Card

## Goal

Create the Power Automate approval workflow that triggers governance approval before agent sharing restrictions are applied, with adaptive card showing agent details, current sharing, proposed groups, and zone context.

**Ties to Phase 3 Goal:** Implements ENF-03 (remediation approval workflow). Provides governance control gate for remediation operations from Plan 03-01. Ensures destructive permission changes (Zone 1 group removal, Zone 3 full replacement) require explicit approval.

## Tasks

### Task 1: Design Approval Workflow Architecture

**Acceptance criteria:**
- [ ] Workflow trigger defined: Manual trigger (on-demand or scheduled daily)
- [ ] Query logic specified: Dataverse `fsi_agentsharingcompliances` filtered by `compliance_status=1` (NonCompliant), `last_checked` within 24 hours
- [ ] Exception filter specified: Exclude agents with active exceptions (query `fsi_SharingException` table if exists from UASD/Phase 4)
- [ ] Approval scope defined: Per-agent approval (individual approval requests) or batch approval (single request for N agents)
- [ ] Approval timeout defined: 7 days (configurable via environment variable)
- [ ] Approval assignee defined: Governance lead email (from environment variable `fsi_ASARD_ApprovalEmail`)
- [ ] Remediation execution method defined: HTTP action to BAP Admin API PATCH or invoke Python script via Azure Automation Runbook
- [ ] Notification channels defined: Teams adaptive card for approval result (success/rejection)

**Files:**
- None (design specification documented in this plan)

**Design decisions:**
- **Trigger:** Scheduled daily (09:00 UTC) or manual button click (governance lead initiates)
- **Scope:** Per-agent approval (clearer governance decision, avoids batch approval complexity)
- **Remediation method:** **Option 1 (Preferred):** HTTP action directly to BAP Admin API PATCH (reuse UASD pattern)
  - Pros: No external dependencies (Azure Automation), simpler flow, MSI auth built-in
  - Cons: Zone-specific remediation logic re-implemented in Power Automate expressions (can't reuse Python `asard_zone_rules.py`)
- **Remediation method:** **Option 2 (Alternative):** Invoke Python script via Azure Automation Runbook or HTTP-triggered Azure Function
  - Pros: Reuse Python remediation logic from Plan 03-01 (no duplication), consistent zone rules
  - Cons: Requires Azure Automation account or Function App (deployment dependency), additional auth configuration
- **Recommendation:** **Option 1 for Phase 3** (HTTP action to BAP Admin API), Option 2 for Phase 5 deployment enhancement if zone logic complexity increases

**Implementation notes:**
- Flow MSI (Managed Service Identity) requires Power Platform Administrator role assignment (same as service principal in Python script)
- Query Dataverse with FetchXML or OData filter: `$filter=fsi_compliance_status eq 1 and fsi_last_checked ge [24 hours ago]`
- Approval timeout: `ApprovalCreationInput/timeout` parameter (ISO 8601 duration, e.g., "P7D" = 7 days)
- Batch approval alternative: Loop through non-compliant agents, accumulate approval card sections, single approval request with multi-agent summary (more complex adaptive card)

### Task 2: Create Power Automate Approval Flow JSON

**Acceptance criteria:**
- [ ] Flow definition exported as JSON: `src/asard-remediation-approval-workflow.json`
- [ ] Trigger: Recurrence (daily 09:00 UTC) with manual trigger option (button in Power Automate portal)
- [ ] Action: List Dataverse records (`fsi_agentsharingcompliances`) with filter for non-compliant agents
- [ ] Action: Filter exceptions (optional — if UASD `fsi_SharingException` table exists, query and exclude agents with active exceptions)
- [ ] Loop: For each non-compliant agent (apply to each)
- [ ] Action: Get agent details (agent name, environment name, zone, current sharing principals JSON, violation type)
- [ ] Action: Get approved groups for zone (query `fsi_approvedsecuritygrouppolicies` filtered by zone)
- [ ] Action: Compose adaptive card JSON (agent details, current sharing, proposed groups, zone context)
- [ ] Action: Start approval (Approvals connector) with adaptive card body, assigned to governance lead, 7-day timeout
- [ ] Wait: Wait for approval response (Approve/Reject)
- [ ] Condition: If Approved → Execute remediation (HTTP PATCH to BAP Admin API) → Update Dataverse → Teams notification
- [ ] Condition: If Rejected → Update Dataverse (approval_status=Rejected) → Teams notification
- [ ] Action: Send summary notification (X agents approved, Y rejected, Z remediated successfully)

**Files:**
- `src/asard-remediation-approval-workflow.json` — Create new file (~1200 lines, Power Automate JSON export)
  - Trigger: `"type": "Recurrence"`, `"recurrence": {"frequency": "Day", "interval": 1, "startTime": "09:00:00"}`
  - Manual trigger: Add `"type": "manual"` trigger in addition to recurrence (Power Automate supports multiple triggers)
  - Dataverse connector: `"type": "OpenApiConnection"`, `"inputs": {"host": {"connectionName": "shared_commondataserviceforapps"}}`
  - Approvals connector: `"type": "OpenApiConnection"`, `"inputs": {"host": {"connectionName": "shared_approvals"}}`
  - HTTP action: `"type": "Http"`, `"inputs": {"method": "PATCH", "uri": "BAP Admin API URL", "authentication": {"type": "ManagedServiceIdentity"}}`
  - Teams connector: `"type": "OpenApiConnection"`, `"inputs": {"host": {"connectionName": "shared_teams"}}`

**Implementation notes:**
- Flow JSON structure follows Power Automate export format (version 2.x schema)
- Connection references: `shared_commondataserviceforapps`, `shared_approvals`, `shared_teams`, `shared_http` (for BAP Admin API)
- MSI authentication for HTTP action: `"authentication": {"type": "ManagedServiceIdentity", "audience": "https://api.bap.microsoft.com"}`
- Adaptive card body embedded in approval action: `"ApprovalCreationInput/details": "@{variables('adaptiveCardJson')}"`
- Approval response handling: `"outcomes": ["Approve", "Reject"]`, check `body('Start_approval')?['outcome']`
- Dataverse update: Upsert to `fsi_agentsharingcompliances` with alternate key (agent_id, environment_id), set `fsi_remediation_date`, `fsi_approval_status`, `fsi_compliance_status`

**Zone-specific remediation logic in flow:**
- Zone 1: Build empty `put` array (removes all groups) or preserve User principals only
- Zone 2: Parse current principals JSON, filter out Everyone/Public, build `put` array with remaining named groups + users
- Zone 3: Query approved groups from Dataverse, transform to BAP permission objects, build `put` array with approved groups only
- Expression examples:
  - Parse JSON: `json(triggerBody()?['fsi_sharing_principals'])`
  - Filter principals: `where(parsed, principal => not(contains(principal.id, 'everyone')))`
  - Transform to permission objects: `select(approvedGroups, group => {"properties": {"roleName": "CanView", "principal": {"id": group.id, "type": "Group", "displayName": group.name}}})`

**Testing approach:**

- Test with single non-compliant agent in lab Dataverse environment
- Verify approval request received (email notification + approval center)

  - REMOVE list: Current principals that will be removed (Everyone, unapproved groups, excess users)

### Task 4: Implement Approval Decision Handling

**Acceptance criteria:**
- [ ] Approval action: `Start approval` (Approvals connector) with title, assignee, adaptive card body, timeout
- [ ] Wait for response: Flow waits for approval/rejection (blocking wait, timeout after 7 days)
- [ ] Approval outcome checked: `body('Start_approval')?['outcome']` equals "Approve" or "Reject"
- [ ] On Approve: Execute remediation (HTTP PATCH to BAP Admin API), validate post-remediation (optional), update Dataverse (`compliance_status=0`, `remediation_date`, `approval_status=Approved`)
- [ ] On Reject: Log rejection reason (`body('Start_approval')?['comments']`), update Dataverse (`approval_status=Rejected`, no remediation), skip BAP API call
- [ ] Error handling: If PATCH fails (4xx/5xx), update Dataverse (`compliance_status=3` [Error]), log error details
- [ ] Approval metadata logged: Approver email (`body('Start_approval')?['responder']`), approval date, rejection reason (if rejected)

**Files:**
- `src/asard-remediation-approval-workflow.json` — Add approval decision logic (expand Task 2 flow)
  - Action: `Start approval` (Approvals connector)
    - `ApprovalCreationInput/title`: "ASARD Remediation Approval — @{variables('agent_name')}"
    - `ApprovalCreationInput/assignedTo`: `@{variables('approverEmail')}` (from environment variable)
    - `ApprovalCreationInput/details`: Adaptive card JSON (embedded or loaded from variable)
    - `ApprovalCreationInput/timeout`: "P7D" (7 days)
  - Condition: `@equals(body('Start_approval')?['outcome'], 'Approve')`
    - True branch: HTTP PATCH to BAP Admin API + Dataverse update + Teams success notification
    - False branch: Dataverse update (rejected) + Teams rejection notification

**Implementation notes:**
- Approvals connector automatically sends email notification to approver with embedded adaptive card
- Approval center: Approver can view/respond in Power Automate Approvals center (web + mobile app)
- Approval timeout: If no response within 7 days, flow times out, agent remains non-compliant (will appear in next scheduled approval run)
- Rejection reason: `body('Start_approval')?['comments']` field contains approver's text comment (optional, may be empty)
- Approver identity: `body('Start_approval')?['responder']` contains approver's email address (logged in Dataverse for audit trail)

**Approval email format:**
```

[Adaptive Card Preview]

You have an approval request for agent sharing remediation.
Agent: HR Onboarding Bot
Environment: Production - Finance
Zone: Zone 3 (Enterprise Managed)
Violation: UnapprovedGroup

[View Details] [Approve] [Reject]
```

### Task 5: Implement Remediation Execution via HTTP Action

**Acceptance criteria:**
- [ ] HTTP action: PATCH to BAP Admin API with MSI authentication
- [ ] URL: `https://api.bap.microsoft.com/providers/Microsoft.BusinessAppPlatform/scopes/admin/environments/@{variables('env_id')}/bots/@{variables('agent_id')}/permissions?api-version=2021-04-01`
- [ ] Headers: `Content-Type: application/json`
- [ ] Authentication: `ManagedServiceIdentity` with audience `https://api.bap.microsoft.com`
- [ ] Body: `{"put": @{variables('permission_objects')}}` (zone-specific permission objects array)
- [ ] Response handling: Check status code (200 OK = success, 4xx/5xx = error)
- [ ] Error logging: Log HTTP response body, status code, agent_id, environment_id (for troubleshooting)
- [ ] Retry logic: Power Automate HTTP action automatic retry (3 attempts with exponential backoff) for 429/500/502/503

**Files:**
- `src/asard-remediation-approval-workflow.json` — Add HTTP PATCH action (expand Task 2 flow)
  - Action: `HTTP` (built-in connector)
    - `method`: "PATCH"
    - `uri`: BAP Admin API URL with environment_id and agent_id variables
    - `headers`: `{"Content-Type": "application/json"}`
    - `body`: `{"put": @{variables('permission_objects')}}`
    - `authentication`: `{"type": "ManagedServiceIdentity", "audience": "https://api.bap.microsoft.com"}`
    - `retryPolicy`: `{"type": "exponential", "count": 3, "interval": "PT10S"}` (3 retries, 10s initial interval)

**Implementation notes:**
- MSI authentication: Flow must run with Managed Service Identity enabled (configured in flow properties)
- MSI role assignment: Managed Identity principal must be added to Power Platform Administrator role (Entra ID or Power Platform admin center)
- Permission objects structure (Zone 3 example):
  ```json
  [
    {
      "properties": {
        "roleName": "CanView",
        "principal": {
          "id": "group-guid-1",
          "type": "Group",
          "displayName": "Finance-Approved-Viewers"
        }
      }
    }
  ]
  ```
- Zone-specific logic: Build `permission_objects` array based on zone classification (Zone 1: empty or User principals, Zone 2: filtered principals, Zone 3: approved groups)
- Error handling: If HTTP action fails, flow should continue (not throw exception), log error, update Dataverse with `compliance_status=3` (Error)
