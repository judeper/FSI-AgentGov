# Phase 3 Plan 1: Remediation Script with WhatIf Mode and Approved Group Management

## Goal

Create the remediation script that removes Everyone/Public/unapproved sharing principals and applies zone-appropriate approved Azure AD security groups, with WhatIf simulation mode and post-remediation validation to confirm changes.

**Ties to Phase 3 Goal:** Implements ENF-01 (remediation script with WhatIf) and ENF-02 (approved security group management). Prepares remediation capability for ENF-03 approval workflow (Plan 03-02).

### Task 4: Implement Post-Remediation Validation

**Acceptance criteria:**
- [ ] After PATCH succeeds, wait 2 seconds (API consistency delay)
- [ ] Re-scan agent permissions: `bap_client.get_agent_permissions(env_id, agent_id)`
- [ ] Re-evaluate compliance: `check_agent_compliance(agent_id, env_id, env_name, sharing_principals_json, client)`
- [ ] If compliant: Log success, update Dataverse (`compliance_status=0`, `remediation_date=now()`)
- [ ] If non-compliant: Log validation failure with mismatch details, update Dataverse (`compliance_status=3` [Error], `remediation_date=now()`, log evidence)
- [ ] Retry validation up to 3 times with increasing delays (2s, 5s, 10s) if validation fails (handle BAP API eventual consistency)
- [ ] Log all validation attempts and results (audit trail)

**Files:**
- `scripts/remediate_agent_sharing.py` — Add function:
  - `validate_remediation(agent_id, env_id, env_name, bap_client, dataverse_client, max_retries=3)` → Dict
    - Returns: `{"validated": bool, "compliant": bool, "attempts": int, "error": str}`
    - Loop: For retry in range(max_retries):
      1. time.sleep(delay) — Delays: [2, 5, 10] seconds
      2. Get current permissions from BAP API
      3. Call `check_agent_compliance()` with current principals
      4. If compliant: return success
      5. If non-compliant and retries remaining: continue
      6. If non-compliant and no retries: return failure with details
  - Integrate into `remediate_agent()` workflow: After PATCH succeeds → call `validate_remediation()` → update Dataverse based on result

**Implementation notes:**
- Research lines 355-399 detail validation workflow: PATCH → wait → GET → evaluate → update Dataverse
- Dataverse compliance_status values: 0=Compliant, 1=NonCompliant, 2=Exception, 3=Error (from Phase 1 option set)
- Validation failure scenarios (research lines 401-410): BAP eventual consistency (most common), concurrent modification, zone classification change
- Log full evidence: Pre-PATCH principals JSON, PATCH body, post-PATCH principals JSON, compliance evaluation result
- Retry delays handle eventual consistency (BAP API may return stale data immediately after PATCH)

**Testing approach:**
- Unit test: Validation success (mock GET returns approved groups, check_agent_compliance returns compliant=True)
- Unit test: Validation failure after 1 retry (mock GET returns old principals first, then approved groups)
- Unit test: Validation failure after 3 retries (mock GET always returns old principals, max retries exhausted)
- Integration test: Remediate lab agent, validate post-remediation (verify compliance_status=0 in Dataverse)
