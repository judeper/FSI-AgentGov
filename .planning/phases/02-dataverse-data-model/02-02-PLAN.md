## Tasks

### Task 1: Create `create_timeout_errorlog_schema.py` — Table Definition

**Action:** Create `scripts/create_timeout_errorlog_schema.py` with:

1. **Module docstring** listing the errorlog table and usage examples
2. **Imports:** `argparse`, `logging`, `sys`, `typing.Any/Dict/List`, `caa_client.CAAClient`
3. **Column helper functions** (copy from CAA pattern): `_label`, `_string_col`, `_memo_col`, `_datetime_col`
   - Only include helpers actually used (no boolean/integer/picklist needed for this table)
4. **`fsi_inactivitytimeout_errorlog` table definition:**
   - `SchemaName`: `fsi_InactivityTimeoutErrorLog`
   - `PrimaryNameAttribute`: `fsi_name` (String 256, required) — composite `{EnvironmentName}-{errortype}-{timestamp}`
   - `OwnershipType`: `OrganizationOwned`
   - `EntitySetName`: `fsi_inactivitytimeouterrorlogs`
   - `Description`: Error logging for inactivity timeout compliance scan failures
5. **`fsi_inactivitytimeout_errorlog` columns:**
   - `fsi_environmentid` (String 100, required) — EnvironmentName
   - `fsi_errortype` (String 50, required) — 401/403/404/429/MissingPolicy/ParseError
   - `fsi_errorraw` (Memo) — raw error response / stack trace
   - `fsi_timestamp` (DateTime, required) — when error occurred

**Acceptance criteria:**
- [ ] `fsi_name` is PrimaryNameAttribute (composite key pattern)
- [ ] `fsi_errortype` is free-text String (not a Choice) — allows unanticipated error types
- [ ] Only necessary column helpers are included (no unused helpers)
- [ ] Table is append-only (documented in comments — security role removes Delete post-deployment)
