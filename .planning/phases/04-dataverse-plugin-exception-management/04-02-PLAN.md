# Plan 04-02: Exception Register + Validation Script + Request Template

## Goal

Create exception management artifacts for MIME type restriction governance: a CSV register template for tracking approved exceptions, a PowerShell validation script that compares environment configuration against the register, and a Markdown exception request form template.

## Context

- **Exception pattern:** v16 (UASD) established exception management with `uasd-exception-approval-workflow.json` and Dataverse-backed exception tracking
- **Control 1.25:** References exception register in Zone 2+ requirements for justified MIME type additions
- **FsiMimeControl module:** `Test-FsiMimeCompliance` can detect MIME types present in environment but absent from zone template — exceptions explain those gaps
- **Register location:** `scripts/governance/` (alongside other governance scripts)
- **Template location:** `docs/templates/` (alongside `control-setup-template.md`)

## Tasks

### Task 1: Create mime-type-exceptions.csv

**File:** `scripts/governance/mime-type-exceptions.csv`

**Acceptance criteria:**

1. CSV header row with required columns: `ExceptionId`, `Requestor`, `RequestorEmail`, `Department`, `RequestDate`, `MimeType`, `Extensions`, `BusinessJustification`, `AlternativesConsidered`, `RiskAssessment`, `MitigatingControls`, `Approver`, `ApproverEmail`, `ApprovalDate`, `ReviewDate`, `ExpirationDate`, `Status`, `Zone`, `EnvironmentId`, `Notes`
2. Two sample rows demonstrating legitimate exception scenarios:
   - Exception for `application/zip` in a Zone 2 environment (document exchange workflow)
   - Exception for `application/x-zip-compressed` in a Zone 3 environment (regulatory filing portal)
3. Status values: `Active`, `Expired`, `Revoked`, `PendingReview`
4. ReviewDate set to 90 days from request date
5. ExpirationDate set to 1 year from approval date
6. Sample mitigating controls reference DLP scanning and Sentinel monitoring

### Task 2: Create validate-exceptions.ps1

**File:** `scripts/governance/validate-exceptions.ps1`

**Acceptance criteria:**

1. PowerShell 7.0+ script with `#Requires -Version 7.0`
2. Comment-based help with `.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`
3. Parameters:
   - `DataverseUrl` (mandatory) — environment to validate
   - `AccessToken` (optional) — falls back to `Get-AzAccessToken`
   - `ExceptionRegisterPath` (mandatory, default `./scripts/governance/mime-type-exceptions.csv`)
   - `ZoneTemplate` (`[ValidateSet('zone1','zone2','zone3')]`)
   - `OutputFormat` (`[ValidateSet('Table','JSON','Object')]`, default Table)
   - `OutputPath` (optional)
4. Processing logic:
   - Import `FsiMimeControl.psm1` and call `Get-FsiMimeConfig` to read current environment MIME configuration
   - Load zone template to determine expected baseline
   - Import exception register CSV and filter by `Status -eq 'Active'` and matching `EnvironmentId`
   - Compare each MIME type in the environment configuration against: (a) zone template allowlist, (b) active exceptions
   - Flag MIME types that are allowed in the environment but NOT in the zone template AND NOT covered by an active exception
   - Flag expired exceptions (ReviewDate or ExpirationDate in the past)
   - Flag exceptions approaching expiration (within 30 days)
5. Output: PSCustomObject array with `MimeType`, `Source` (Template/Exception/Unauthorized), `ExceptionId`, `Status`, `ExpirationDate`, `Action` (OK/ReviewNeeded/Unauthorized/Expired)
6. Summary output with counts: Compliant, Exception-Covered, Unauthorized, Expired, Expiring Soon
7. [PASS]/[FAIL]/[WARN] pattern consistent with existing governance scripts

### Task 3: Create exception-template.md

**File:** `docs/templates/exception-template.md`

**Acceptance criteria:**

1. Title: `# MIME Type Exception Request`
2. Header metadata: Template Version, Control Reference (1.25), Last Updated
3. Sections:
   - **Requestor Information** — Name, Email, Department, Date
   - **Exception Details** — MIME Type(s), File Extension(s), Zone, Environment ID, Environment Name
   - **Business Justification** — Purpose/workflow requiring this file type, volume and frequency, duration (permanent/temporary with end date)
   - **Alternatives Considered** — Alternative approaches evaluated, reason each alternative was insufficient
   - **Risk Assessment** — Threat scenarios for this file type, data sensitivity classification, likelihood and impact rating
   - **Mitigating Controls** — DLP policy coverage, Sentinel monitoring, additional scanning, access restrictions
   - **Approval** — Approver Name, Approver Email, Approval Date, conditions/restrictions
   - **Review Schedule** — Next review date, review cadence, responsible reviewer
4. Footer with instructions for submission process
5. FSI-safe language throughout (no overclaims)
6. Checkbox-style fields where appropriate for quick completion
