# Plan 04-01: Dataverse Plugin + Deployment Scripts

## Goal

Create `ValidateMimeTypePlugin.cs` implementing server-side magic bytes validation for Zone 3 environments, plus deployment and test scripts for Plugin Registration Tool automation.

## Context

- **Zone 3 requirement:** `requireServerSideValidation: true` in `scripts/governance/mime-templates/zone3.json`
- **Control 1.25:** References server-side magic-byte validation as Zone 3 defense-in-depth layer
- **Existing solution patterns:** `src/` contains JSON artifacts (flows, workbooks, adaptive cards); `scripts/governance/` contains PowerShell modules/scripts
- **Plugin pattern:** Dataverse pre-validation plugin triggered on file upload, validates file header bytes against declared MIME type
- **MimeConfig.json:** Configuration file determining which MIME types are allowed and their expected magic bytes signatures

## Tasks

### Task 1: Create MimeConfig.json

**File:** `src/MimeConfig.json`

**Acceptance criteria:**

1. JSON structure with `version`, `description`, `enforcementMode` (Block/LogOnly), `maxFileSizeBytes` (10485760 = 10MB), `zone` (3)
2. `allowedTypes` array — each entry: `mimeType`, `extensions` (string[]), `magicBytes` (hex string or array of hex strings for multi-signature types), `description`
3. Types included: PDF (`25 50 44 46`), PNG (`89 50 4E 47`), JPEG (`FF D8 FF`), GIF (`47 49 46 38`), TIFF (`49 49 2A 00` / `4D 4D 00 2A`), plain text (no magic bytes — text validation by absence of binary), CSV (no magic bytes), XLSX/DOCX/PPTX (OpenXML = `50 4B 03 04` PK zip header)
4. `blockedSignatures` array — known dangerous headers: PE executable (`4D 5A`), ELF (`7F 45 4C 46`), Mach-O (`FE ED FA CE` / `FE ED FA CF` / `CE FA ED FE` / `CF FA ED FE`), Java class (`CA FE BA BE`), MS-DOS (`4D 5A`)
5. `correlationIdHeader` field for trace integration

### Task 2: Create ValidateMimeTypePlugin.cs

**File:** `src/ValidateMimeTypePlugin.cs`

**Acceptance criteria:**

1. C# class implementing `IPlugin` interface (Microsoft.Xrm.Sdk)
2. Registered on `Create` message, `annotation` (Note) entity, pre-validation stage
3. Reads file content from `documentbody` (base64) and `mimetype` fields
4. **Magic bytes validation logic:**
   - Decode base64 content, read first 16 bytes
   - Compare against `blockedSignatures` — if match, block with descriptive error
   - If `enforcementMode == "Block"`, throw `InvalidPluginExecutionException`
   - If `enforcementMode == "LogOnly"`, create trace log entry and allow
5. **OpenXML validation:** For DOCX/XLSX/PPTX, verify PK zip header (`50 4B 03 04`) and validate `[Content_Types].xml` presence
6. **Allowlist validation:** Check declared MIME type against `allowedTypes`; reject unlisted types
7. **Max file size guard:** Reject files exceeding `maxFileSizeBytes`
8. **Correlation ID:** Read from plugin execution context `CorrelationId` for tracing
9. **Configuration loading:** Read `MimeConfig.json` from plugin secure configuration string or unsecure configuration
10. Comprehensive XML documentation comments
11. Error messages use FSI-safe language (no overclaims)

### Task 3: Create register-plugin.ps1

**File:** `scripts/governance/register-plugin.ps1`

**Acceptance criteria:**

1. PowerShell 7.0+ script with `#Requires -Version 7.0`
2. Comment-based help with `.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`
3. Parameters: `DataverseUrl` (mandatory), `AssemblyPath` (mandatory), `AccessToken` (optional, falls back to `Get-AzAccessToken`)
4. Registers plugin assembly via Dataverse Web API (`POST /api/data/v9.2/pluginassemblies`)
5. Registers plugin step on `Create` of `annotation` entity, pre-validation stage
6. Registers secure configuration with `MimeConfig.json` content
7. `-WhatIf` support via `SupportsShouldProcess`
8. Error handling with descriptive messages
9. Outputs registration result object

### Task 4: Create test-plugin.ps1

**File:** `scripts/governance/test-plugin.ps1`

**Acceptance criteria:**

1. PowerShell 7.0+ script with `#Requires -Version 7.0`
2. Comment-based help
3. Parameters: `DataverseUrl` (mandatory), `AccessToken` (optional)
4. Creates test annotations with various file types:
   - PDF file (should pass)
   - PNG image (should pass)
   - EXE file disguised as .txt (should fail — PE header detected)
   - Clean text file (should pass)
   - Oversized file (should fail — size guard)
5. Reports test results with [PASS]/[FAIL] pattern (consistent with existing scripts)
6. Cleanup: deletes test annotations after verification
7. Outputs summary table
