**SDM-DriftDetector.json (Scheduled Detection Flow):**

Per RESEARCH.md "Pattern 1: Scheduled Detection Flow with Multi-Source Polling":

**Trigger:**
```json
"triggers": {
  "Recurrence": {
    "recurrence": {
      "frequency": "Minute",
      "interval": 15,
      "startTime": "2026-01-01T00:00:00Z",
      "timeZone": "UTC"
    },
    "type": "Recurrence"
  }
}
```

**Actions sequence:**

1. **Initialize variables:**
   - LastCheckTime: `@{addMinutes(utcNow(), -15)}`
   - SourceStatus: empty array (for tracking which sources succeeded/failed)
   - ViolationsFound: 0

2. **List active agent scopes:**
   - Dataverse List Rows: `fsi_agentscopes?$filter=fsi_status eq 2`

3. **Query Unified Audit Log** (in Scope for error handling):
   - HTTP with Azure AD to `https://manage.office.com/api/v1.0/@{variables('TenantId')}/activity/feed/subscriptions/content`
   - Filter: contentType=Audit.General, time window from LastCheckTime to now
   - Handle failure gracefully per RESEARCH.md "Pattern 2: Graceful Degradation"

4. **For each audit event** (filter RecordType=261):
   - Parse JSON to extract agent ID, accessed resources
   - **Match to scope:** Find scope where fsi_agentid matches event agent
   - **If no scope found:**
     - Create violation: fsi_violationtype=6 (No Baseline), fsi_severity=2 (High)
   - **If scope found:**
     - Parse allowed resources from scope (JSON arrays)
     - For each accessed resource:
       - Check if resource in allowed list
       - If not: Create violation with appropriate type and severity

5. **Log detection run:**
   - Compose output with source status array and violations count
   - Could extend to write to custom logging table

**Severity assignment:**
- Connector: fsi_severity=2 (High), fsi_violationtype=1
- SharePoint Site: fsi_severity=3 (Medium), fsi_violationtype=2
- Dataverse Table: fsi_severity=3 (Medium), fsi_violationtype=3
- External API: fsi_severity=2 (High), fsi_violationtype=4
- No Baseline: fsi_severity=2 (High), fsi_violationtype=6

**SDM-AlertDispatcher.json (Alert Delivery Flow):**

Per CONTEXT.md "Dual delivery: both Teams Adaptive Card and email for each violation"

**Trigger:**
```json
"triggers": {
  "When_a_row_is_added": {
    "type": "OpenApiConnectionWebhook",
    "inputs": {
      "host": {
        "connectionName": "shared_commondataserviceforapps",
        "operationId": "SubscribeWebhookTrigger"
      },
      "parameters": {
        "subscriptionRequest/message": 1,
        "subscriptionRequest/entityname": "fsi_scopeviolation",
        "subscriptionRequest/scope": 4
      }
    }
  }
}
```

**Actions sequence:**

1. **Get agent scope details:**
   - Expand fsi_agentscopeid to get agent name, owner

2. **Build Adaptive Card** (per RESEARCH.md "Pattern 3"):
   ```json
   {
     "$schema": "http://adaptivecards.io/schemas/adaptive-card.json",
     "type": "AdaptiveCard",
     "version": "1.5",
     "body": [
       {
         "type": "TextBlock",
         "text": "Scope Drift Violation Detected",
         "weight": "Bolder",
         "size": "Large",
         "color": "Attention"
       },
       {
         "type": "FactSet",
         "facts": [
           {"title": "Agent:", "value": "@{...agent name...}"},
           {"title": "Violation:", "value": "@{...violation type...}"},
           {"title": "Resource:", "value": "@{triggerOutputs()?['body/fsi_resourcename']}"},
           {"title": "Severity:", "value": "@{...severity label...}"},
           {"title": "Detected:", "value": "@{triggerOutputs()?['body/fsi_detectedon']}"}
         ]
       }
     ],
     "actions": [
       {
         "type": "Action.OpenUrl",
         "title": "View Violation",
         "url": "@{...Dataverse URL...}"
       }
     ]
   }
   ```

3. **Post to Teams channel:**
   - Use Teams connector "Post card in chat or channel"
   - Reference environment variable for channel ID

4. **Send email notification:**
   - Use Outlook connector "Send an email"
   - To: Agent owner + SDM_SecurityTeamEmail (environment variable)
   - Subject: "[Scope Drift] Violation: @{fsi_resourcename}"
   - Body: HTML with violation details

5. **Update violation status:**
   - Set fsi_status to 2 (Under Investigation) after alerts sent

Use connection references (fsi_cr_dataverse, fsi_cr_teams, fsi_cr_outlook) not hardcoded connections.
