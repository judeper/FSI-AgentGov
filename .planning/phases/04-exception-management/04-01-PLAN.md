# Phase 4 Plan 1: Exception Tracking and Review Workflow

## Goal

Create the exception management capability for agents that legitimately require broader sharing, with time-bound tracking and automated review. Agents with active exceptions are excluded from remediation actions. Expired exceptions trigger re-scanning.

This plan delivers:
- Exception tracking via additional columns on the existing `fsi_agentsharingcompliances` table (compliance_status already includes "Exception" = 2)
- Detection and remediation scripts updated to check for active exceptions before flagging/remediating
- Exception review workflow (Power Automate flow) with scheduled checks for expiring/expired exceptions
- Teams notifications for governance leads when exceptions approach expiration

## Notes

**Design decision: Compliance table extension vs. separate exception table**

This plan uses compliance table extension (additional columns on `fsi_agentsharingcompliances`) rather than a separate `fsi_asardexceptions` table. Rationale:
- Simpler queries: Agent compliance + exception data in one record
- Consistent with existing compliance_status option set (Exception = 2)
- Reduces join complexity in detection/remediation scripts
- UASD pattern uses separate table, but ASARD has simpler exception model (time-bound only, no approval workflow in v1)

**Exception approval process in v1:**

ASARD v1 uses **manual exception entry** (direct Dataverse record update). The UASD exception manager app pattern exists (`uasd-exception-manager-app.json`) but implementing a full Canvas app is out of scope for v22. Future enhancement: Create ASARD exception manager app based on UASD pattern.

**Re-scan on expiration:**

Expired exceptions trigger automatic re-evaluation by:
1. Exception review workflow detects expired exception (expires_at < now)
2. Workflow updates Dataverse record: Set compliance_status=1 (NonCompliant), clear all exception fields
3. Workflow sends Teams notification with expired agent list
4. Next scheduled detection run will re-evaluate agent and flag as non-compliant (no active exception)
5. Governance lead can then choose to remediate or re-grant exception

**Notification recipients:**

Exception review workflow sends Teams notifications to a governance leads channel. Channel configuration is a deployment parameter (specified in connection reference or flow variable). Default: Same channel as main ASARD alert notifications.
