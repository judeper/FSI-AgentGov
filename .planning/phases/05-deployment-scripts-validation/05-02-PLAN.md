Create deploy-alerts.ps1 with the following structure:

**Header block:**
- Script description comment block explaining purpose, the 3-phase deployment order, usage examples, and prerequisites
- `#Requires -Version 7.0`
- `[CmdletBinding()]` param block with:
  - `[Parameter(Mandatory=$true)] [string]$ResourceGroup`
  - `[Parameter(Mandatory=$true)] [string]$ApplicationInsightsId` — Full resource ID of App Insights
  - `[Parameter(Mandatory=$false)] [ValidateSet("dev","prod")] [string]$Environment = "dev"`
  - `[Parameter(Mandatory=$false)] [switch]$DryRun`
  - `[Parameter(Mandatory=$false)] [switch]$Force` — Skip confirmation prompt
- `Set-StrictMode -Version Latest`
- `$ErrorActionPreference = "Stop"`

**Banner function:**
- `Show-Banner` — Print script name, version, 3-phase deployment order diagram

**Test-Prerequisites function:**
- Same checks as deploy-workbooks.ps1: Azure CLI version, authentication, resource group, Application Insights
- Additionally check that ARM template files exist at expected paths:
  - `alerts/action-groups/logic-app-teams-notification.json`
  - `alerts/action-groups/action-group-zone1.json`, zone2, zone3
  - `alerts/ALRT-01-high-failure-rate.json`, ALRT-02, ALRT-03
  - `alerts/shared-parameters.$Environment.json`
- Returns `$true` or `$false`

**Deploy-LogicApp function:**
- Deploys `alerts/action-groups/logic-app-teams-notification.json`
- Uses `--parameters logicAppName="fsi-agent-alert-teams-$Environment"` (per alerts/README.md)
- Captures Logic App callback URL from deployment outputs: `$deployment.properties.outputs.logicAppCallbackUrl.value`
- Returns the callback URL string
- Check `$LASTEXITCODE`, throw on failure with troubleshooting hints

**Deploy-ActionGroups function:**
- Parameters include `$LogicAppCallbackUrl` (passed from Deploy-LogicApp)
- Deploys 3 action group templates: action-group-zone1.json, zone2, zone3
- Uses shared parameters file: `--parameters "@$sharedParametersPath"`
- Additionally passes `teamsLogicAppCallbackUrl=$LogicAppCallbackUrl` (overrides placeholder in shared params)
- Captures action group IDs from outputs
- Returns hashtable with zone1/zone2/zone3 action group IDs
- Check `$LASTEXITCODE` after each deployment

**Deploy-AlertRules function:**
- Parameters include `$ActionGroupIds` hashtable (passed from Deploy-ActionGroups)
- Deploys 3 alert rule templates: ALRT-01, ALRT-02, ALRT-03
- Uses shared parameters file: `--parameters "@$sharedParametersPath"`
- Uses `--mode Incremental` for safe updates
- Check `$LASTEXITCODE` after each deployment

**Main execution block:**
- Call `Show-Banner`
- If `$DryRun`: print "*** DRY RUN MODE ***" in yellow
- Call `Test-Prerequisites` — exit 1 if fails
- Unless `$Force`: prompt user to confirm deployment (alert rules affect production monitoring)
- Execute 3 phases sequentially with clear phase headers:
  1. `[Phase 1/3: Logic App Deployment]` — Deploy-LogicApp
  2. `[Phase 2/3: Action Groups Deployment]` — Deploy-ActionGroups (pass Logic App URL)
  3. `[Phase 3/3: Alert Rules Deployment]` — Deploy-AlertRules (pass Action Group IDs)
- Print deployment summary with all deployed resources
- Wrap in top-level try-catch with troubleshooting guidance
- Include note about dynamic threshold baseline period (14-day learning period before alerts fire)

**Important patterns (from research):**
- Always check `$LASTEXITCODE` after every `az` command
- Use `$PSScriptRoot`-relative path resolution
- Deployment order is CRITICAL: Logic App → Action Groups → Alert Rules
- Return values from each phase pass to next phase (callback URL → action group IDs)
- All ARM templates use fixed GUIDs for idempotency (already configured in Phase 3)
- Shared parameters file provides environment-specific values; script overrides dynamic values (Logic App URL)
