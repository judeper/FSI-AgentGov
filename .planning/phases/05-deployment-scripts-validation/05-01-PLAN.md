Create deploy-workbooks.ps1 with the following structure:

**Header block:**
- Script description comment block explaining purpose, usage examples, and prerequisites
- `#Requires -Version 7.0`
- `[CmdletBinding()]` param block with:
  - `[Parameter(Mandatory=$true)] [string]$ResourceGroup`
  - `[Parameter(Mandatory=$true)] [string]$ApplicationInsightsId` — Full resource ID of App Insights
  - `[Parameter(Mandatory=$false)] [ValidateSet("dev","prod")] [string]$Environment = "dev"`
  - `[Parameter(Mandatory=$false)] [switch]$DryRun`
  - `[Parameter(Mandatory=$false)] [switch]$Verbose`
- `Set-StrictMode -Version Latest`
- `$ErrorActionPreference = "Stop"`

**Banner function:**
- `Show-Banner` — Print script name, version, purpose (pattern from provision.py print_banner)

**Test-Prerequisites function:**
- Check Azure CLI is installed (`az version`)
- Check Azure CLI version >= 2.50.0
- Check Azure CLI is authenticated (`az account show`)
- Check resource group exists (`az group show --name $ResourceGroup`)
- Check Application Insights resource exists (parse $ApplicationInsightsId to extract name, run `az monitor app-insights component show`)
- Each check prints ✓ (green) on pass, ✗ (red) on fail with remediation hint
- Returns `$true` or `$false`

**Deploy-SingleWorkbook function:**
- Parameters: `$WorkbookName`, `$DisplayName`, `$TemplatePath`, `$ParametersPath`, `$ResourceGroup`, `$ApplicationInsightsId`, `$DryRun`
- Resolve paths with `Join-Path $PSScriptRoot` and `Resolve-Path` (NOT relative paths — see Pitfall 2 from research)
- Verify template and parameter files exist with `Test-Path`
- If `$DryRun`: print what would be deployed and the az command, return
- Run `az deployment group create --resource-group $ResourceGroup --template-file $TemplatePath --parameters "@$ParametersPath" --parameters applicationInsightsId=$ApplicationInsightsId --mode Incremental --output json`
- Pipe to `ConvertFrom-Json`
- Check `$LASTEXITCODE -ne 0` and throw on failure (Pitfall 1 from research)
- Print success with workbook resource ID from deployment outputs
- Color-coded output: Cyan for info, Green for success, Red for error, Yellow for warning

**Main execution block:**
- Call `Show-Banner`
- If `$DryRun`: print "*** DRY RUN MODE ***" in yellow
- Call `Test-Prerequisites` — exit 1 if fails
- Define workbook array with 3 entries:
  1. `@{Name="operational-health"; DisplayName="Agent Operational Health"}`
  2. `@{Name="error-diagnostics"; DisplayName="Agent Error Diagnostics"}`
  3. `@{Name="usage-overview"; DisplayName="Agent Usage Overview"}`
- Loop through array, calling `Deploy-SingleWorkbook` for each
- Build template paths: `Join-Path $PSScriptRoot "../workbooks/$Name/workbook-template.json"`
- Build parameter paths: `Join-Path $PSScriptRoot "../workbooks/$Name/workbook-parameters.$Environment.json"`
- Track deployed count, print summary table at end
- Wrap in top-level try-catch for unexpected errors with troubleshooting guidance

**Important patterns (from research):**
- Always check `$LASTEXITCODE` after every `az` command
- Use `$PSScriptRoot`-relative path resolution (never relative paths)
- Suppress az CLI stderr noise with `2>$null` only for existence checks, not deployments
- Use `--mode Incremental` (default) for safe idempotent deployment
- Fixed GUIDs in parameter files ensure workbook updates (not duplicates) on re-run
