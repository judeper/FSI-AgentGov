# Plan 03-02: Sentinel Analytics Alert Rule ARM Template

## Goal

Create `src/high-volume-blocks.json` — a deployable ARM template for a Microsoft Sentinel scheduled analytics rule that detects high-volume blocked file upload attempts (>10 per user per hour), with MITRE ATT&CK mapping and incident grouping.

## Context

- **DLP policy template:** Created in Plan 03-01 generates the blocked upload events this rule monitors
- **KQL query basis:** `query-mime-blocks.kql` from Plan 03-01 provides the detection pattern
- **Alert threshold:** >10 blocked uploads/user/hour per ROADMAP.md specification
- **No existing Sentinel ARM templates** in the repo — this establishes the pattern
- **ARM API version:** `2023-02-01` for Microsoft.SecurityInsights/alertRules

## Tasks

### Task 1: Create high-volume-blocks.json ARM template

**File:** `src/high-volume-blocks.json`

**Acceptance criteria:**

1. **ARM template structure:**
   - `$schema`: `https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#`
   - `contentVersion`: `1.0.0.0`
   - `parameters`: workspaceName (string), location (string, default: resourceGroup().location)
   - `resources`: Single `Microsoft.OperationalInsights/workspaces/providers/alertRules` resource

2. **Alert rule metadata:**
   - `kind`: `Scheduled`
   - `apiVersion`: `2023-02-01`
   - `displayName`: "FSI-MIME: High-Volume Blocked Upload Attempts"
   - `description`: "Detects users with more than 10 blocked file upload attempts within one hour, which may indicate persistent attempts to upload malicious or unauthorized file types. Part of Control 1.25 — MIME Type Restrictions for File Uploads."
   - `severity`: "Medium"
   - `enabled`: true

3. **Query configuration:**
   - KQL query detecting >10 blocked uploads per user per hour
   - Source table: `PowerPlatformDlpActivity_CL`
   - Aggregation: `summarize BlockCount=count() by UserPrincipalName, EnvironmentName, bin(TimeGenerated, 1h)`
   - Threshold: `| where BlockCount > 10`
   - Output: UserPrincipalName, EnvironmentName, BlockCount, TimeWindow
   - `queryFrequency`: PT1H (every hour)
   - `queryPeriod`: PT1H (1-hour lookback)
   - `triggerOperator`: GreaterThan
   - `triggerThreshold`: 0

4. **MITRE ATT&CK mapping:**
   - Tactic: InitialAccess (T1566 — Phishing), Execution (T1204 — User Execution)
   - Technique: T1566 (attacker may attempt to upload malicious files via agent), T1204 (user may unknowingly execute disguised file)

5. **Entity mapping:**
   - Entity type: Account
   - Field mapping: `UserPrincipalName` → `FullName`

6. **Incident configuration:**
   - `createIncident`: true
   - `groupingConfiguration`:
     - `enabled`: true
     - `reopenClosedIncident`: false
     - `lookbackDuration`: PT5H
     - `matchingMethod`: Selected
     - `groupByEntities`: Account
   - `groupByAlertDetails`: []

7. **Alert details override:**
   - `alertDisplayNameFormat`: "High-Volume Blocked Uploads: {{UserPrincipalName}}"
   - `alertDescriptionFormat`: "User {{UserPrincipalName}} had {{BlockCount}} blocked file upload attempts in environment {{EnvironmentName}} within one hour."

8. **Custom details:**
   - `EnvironmentName`: EnvironmentName
   - `BlockCount`: BlockCount

9. **Tags/metadata:**
   - Include `tags` object with `controlReference: "1.25"`, `framework: "FSI Agent Governance"`, `version: "1.0.0"`

## Verification

- Valid ARM template (JSON parseable, correct schema)
- KQL query is syntactically valid
- MITRE ATT&CK techniques are correctly referenced
- Entity mapping correctly references Account type
- Incident grouping configured by user
- No FSI language rule violations in descriptions
