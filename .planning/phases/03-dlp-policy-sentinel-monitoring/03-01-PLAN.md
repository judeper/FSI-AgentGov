# Plan 03-01: DLP Policy Template + Sentinel KQL Queries

## Goal

Create a Purview DLP policy template for blocking executable file uploads in Power Platform environments, and two Sentinel KQL queries for monitoring blocked upload attempts and exception register utilization.

## Context

- **Zone templates:** `scripts/governance/mime-templates/zone{2,3}.json` provide the blocked extension and MIME type lists
- **Solution artifacts:** Located in `src/` directory per project convention
- **Control 1.25:** Defines DLP integration as recommended (Zone 2) or required (Zone 3)
- **No existing DLP or KQL templates** in the repo — these are first-of-kind artifacts

## Tasks

### Task 1: Create DLP policy template

**File:** `src/dlp-policy-template.json`

**Acceptance criteria:**

1. **JSON structure** — Valid Purview unified DLP policy format with `name`, `displayName`, `description`, `mode`, `locations`, `rules` array

2. **Policy metadata:**
   - `displayName`: "FSI Agent Governance - MIME Type Upload Restrictions"
   - `description`: References Control 1.25, FSI Agent Governance Framework
   - `mode`: "TestWithNotifications" (safe default for deployment; customer switches to "Enable" after validation)
   - `state`: "Enabled"

3. **Locations:**
   - Power Platform environments location type
   - Configurable environment filter with placeholder GUID and comment
   - Include `allEnvironments` toggle (default: false for scoped deployment)

4. **Rule 1 — Block Executable File Extensions:**
   - `ruleName`: "Block Executable File Uploads"
   - `conditions`: File extension matches for 11 core dangerous types: exe, bat, cmd, ps1, vbs, js, jar, dll, msi, scr, hta
   - `actions`: Block access, generate audit log, create incident report
   - `severity`: High
   - `notifyUser`: true (end-user notification of blocked upload)

5. **Rule 2 — Block Script and Archive Extensions:**
   - `ruleName`: "Block Script and Archive File Uploads"
   - `conditions`: File extension matches: com, cpl, inf, lnk, pif, reg, sct, wsf, wsh, cab, gadget
   - `actions`: Block access, generate audit log, create incident report
   - `severity`: Medium

6. **Incident settings:**
   - `generateIncidentReport`: true
   - `reportSeverity`: "High" for Rule 1, "Medium" for Rule 2
   - `sendToAdmin`: true
   - `incidentReportContent`: file name, user, environment, matched rule

7. **Deployment notes:** JSON comments (top-level `_deploymentNotes` field) explaining:
   - Change `mode` from "TestWithNotifications" to "Enable" for enforcement
   - Update `environmentFilter` with actual environment GUIDs
   - Review blocked extensions against organization needs before enabling

### Task 2: Create query-mime-blocks.kql

**File:** `src/query-mime-blocks.kql`

**Acceptance criteria:**

1. **Header comments:**
   - Title: "MIME Type Block Events — 30-Day Summary"
   - Purpose: Aggregates blocked file upload attempts by extension, user, and environment
   - Control reference: 1.25 — MIME Type Restrictions
   - Framework: FSI Agent Governance Framework
   - Usage: Run in Microsoft Sentinel or Log Analytics workspace

2. **Query logic:**
   - Source table: `PowerPlatformDlpActivity_CL` with comment noting `PowerPlatformAdminActivity` alternative
   - Time filter: `| where TimeGenerated > ago(30d)`
   - Filter: Upload block events (operation type = blocked/denied)
   - Parse: File extension from filename field
   - Aggregation: `summarize BlockCount=count(), LastBlocked=max(TimeGenerated) by FileExtension, UserPrincipalName, EnvironmentName`
   - Sort: By BlockCount descending
   - Output columns: FileExtension, UserPrincipalName, EnvironmentName, BlockCount, LastBlocked, FirstBlocked

3. **Additional enrichment:**
   - Daily trend: Include a commented-out variant with `bin(TimeGenerated, 1d)` for time-series charting
   - Top 10 blocked extensions: Include commented-out variant with `| top 10 by BlockCount`

### Task 3: Create query-exception-usage.kql

**File:** `src/query-exception-usage.kql`

**Acceptance criteria:**

1. **Header comments:**
   - Title: "Exception Register Usage Analysis — 90-Day Review"
   - Purpose: Correlates file upload activity with exception-listed MIME types to detect unusual patterns
   - Control reference: 1.25 — MIME Type Restrictions
   - Usage: Run in Microsoft Sentinel or Log Analytics workspace

2. **Query logic:**
   - Source table: `PowerPlatformDlpActivity_CL`
   - Time filter: `| where TimeGenerated > ago(90d)`
   - Exception list: Parameterized `let ExceptionMimeTypes = dynamic([...])` with placeholder values
   - Filter: Uploads matching exception MIME types
   - Aggregation: `summarize UploadCount=count(), DistinctUsers=dcount(UserPrincipalName), LastUpload=max(TimeGenerated) by MimeType, EnvironmentName`
   - Anomaly detection: Include deviation calculation comparing current week vs 90-day average

3. **Alert threshold guidance:**
   - Comment noting: "Flag for review if any exception MIME type shows >3x normal volume"
   - Commented-out `| where UploadCount > 3 * AvgWeeklyCount` filter for alert rule use
