# Plan 03-02: Exception Manager Canvas App + Import Script

## Objective

Create two artifacts:
1. Exception Manager Canvas App definition — a minimal viable Power Apps Canvas App for exception submission, status viewing, and expiration display
2. `scripts/governance/Import-ApprovedSecurityGroups.ps1` — PowerShell script to import approved security groups from CSV/JSON into the `fsi_ApprovedSecurityGroup` Dataverse table

## Tasks

### Task 1: Create `scripts/governance/Import-ApprovedSecurityGroups.ps1`

**Create** the approved security group import script following the established governance script pattern.

#### 1a. Standard Header (Comment-Based Help)

```powershell
<#
.SYNOPSIS
    Imports approved security groups into Dataverse for UASD validation.

.DESCRIPTION
    Reads approved security group definitions from a CSV or JSON file and
    upserts them into the fsi_ApprovedSecurityGroup Dataverse table. Uses
    fsi_entraid_group_id as the unique key for upsert operations.

    Designed for initial seeding and ongoing maintenance of the approved
    security groups registry used by the Unrestricted Agent Sharing Detector.

.PARAMETER InputPath
    Path to the CSV or JSON file containing approved security groups.

.PARAMETER InputFormat
    Input file format. Valid values: CSV, JSON. Default: auto-detect from extension.

.PARAMETER DataverseUrl
    Dataverse environment URL (e.g., https://org.crm.dynamics.com).

.PARAMETER WhatIf
    Preview changes without writing to Dataverse.

.EXAMPLE
    .\Import-ApprovedSecurityGroups.ps1 -InputPath .\approved-groups.csv -DataverseUrl https://org.crm.dynamics.com
    Imports approved security groups from CSV file.

.EXAMPLE
    .\Import-ApprovedSecurityGroups.ps1 -InputPath .\approved-groups.json -DataverseUrl https://org.crm.dynamics.com -WhatIf
    Preview import from JSON without making changes.
#>
```

#### 1b. Script Requirements

```powershell
#Requires -Version 7.0
#Requires -Modules Az.Accounts
```

#### 1c. Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `InputPath` | string | Yes | — | Path to CSV/JSON file |
| `InputFormat` | string | No | Auto | CSV or JSON |
| `DataverseUrl` | string | Yes | — | Dataverse environment URL |
| `Zone` | string | No | "All" | Default zone for imported groups |
| `WhatIf` | switch | No | false | Preview mode |

#### 1d. CSV Format

```csv
GroupId,DisplayName,Zone,IsActive
xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx,Finance Security Group,Zone2,true
yyyyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy,HR Security Group,Zone1,true
```

#### 1e. JSON Format

```json
[
  {
    "GroupId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "DisplayName": "Finance Security Group",
    "Zone": "Zone2",
    "IsActive": true
  }
]
```

#### 1f. Logic

1. Read and validate input file
2. Authenticate to Dataverse via `Get-AzAccessToken`
3. For each group record:
   a. Query `fsi_approvedsecuritygroups` for existing record by `fsi_entraid_group_id`
   b. If exists: PATCH update (display name, zone, is_active)
   c. If not exists: POST create new record
4. Report summary (created, updated, skipped, errors)

#### 1g. Output

Console summary with counts. No file output (write to Dataverse only).

### Task 2: Create Exception Manager Canvas App Definition

**Create** `src/uasd-exception-manager-app.json` as a Canvas App metadata/definition document.

NOTE: Power Apps Canvas Apps cannot be fully defined as importable JSON like Power Automate flows. Instead, create a structured JSON specification document that defines all screens, controls, data sources, and formulas. This serves as the implementation blueprint for building the app in Power Apps Studio.

#### 2a. App Screens

**Screen 1: ExceptionSubmissionScreen**
- Agent lookup dropdown (from `fsi_AgentSharingSetting`)
- Violation type dropdown (from `fsi_UASD_violationtype` option set)
- Business justification text input (multi-line, required)
- Data classification dropdown (from `fsi_UASD_dataclassification` option set)
- Submit button → creates `fsi_SharingException` row with:
  - `fsi_exception_status`: Pending (0)
  - `fsi_requested_by`: User().Email
  - `fsi_requested_at`: Now()
  - `fsi_expires_at`: DateAdd(Now(), 90, TimeUnit.Days)

**Screen 2: ExceptionStatusScreen**
- Gallery of user's exception requests
- Columns: Agent Name, Violation Type, Status (color-coded), Requested Date, Expires At
- Filter by status option
- Status color coding:
  - Pending (0): Yellow
  - Approved (1): Green
  - Denied (2): Red
  - Expired (3): Gray

**Screen 3: ExpirationDashboardScreen**
- Gallery of all approved exceptions approaching expiration (within 14 days)
- Columns: Agent Name, Approved By (Security + Data Owner), Expires At, Days Remaining
- Sorted by expiration date ascending
- Admin-only view (check user role)

#### 2b. Data Sources

| Source | Table | Usage |
|--------|-------|-------|
| Dataverse | `fsi_AgentSharingSetting` | Agent lookup for submission |
| Dataverse | `fsi_SharingException` | CRUD for exception records |
| Dataverse | `fsi_ApprovedSecurityGroup` | Reference display |

#### 2c. Navigation

Simple tab-based navigation: Submit | My Requests | Expiring (admin)

**Acceptance criteria:**
- [ ] Valid JSON specification document
- [ ] 3 screens defined: Submission, Status, Expiration Dashboard
- [ ] Data source connections to 3 Dataverse tables
- [ ] Exception submission creates correct Dataverse record
- [ ] Status view with color-coded exception states
- [ ] Expiration dashboard shows approaching expirations
- [ ] Lab-grade minimal viable implementation
