# Plan 03-01: Remediation Flow + Exception Approval Flow

## Objective

Create two Power Automate cloud flow JSON definitions:
1. `src/uasd-remediation-apply-sharing-policy.json` — triggers on violation creation, checks exceptions, routes through approval or auto-remediation, and overwrites agent principals via BAP PATCH
2. `src/uasd-exception-approval-workflow.json` — triggers on exception request creation, implements sequential dual approval (Security → Data Owner), sets expiration, and includes expiration scanner

## Tasks

### Task 1: Create `src/uasd-remediation-apply-sharing-policy.json`

**Create** the remediation flow JSON following the structural pattern from `src/uasd-detector-scan-agents.json`.

**Top-level structure:**
```json
{
  "properties": {
    "connectionReferences": { ... },
    "definition": {
      "$schema": "...",
      "contentVersion": "1.0.0.0",
      "parameters": { "$connections", "$authentication" },
      "triggers": { ... },
      "actions": { ... }
    },
    "displayName": "fsi-UASD-Remediation-ApplySharingPolicy",
    "description": "Remediates sharing violations by overwriting agent principals with approved security groups via BAP API.",
    "state": "Started"
  },
  "schemaVersion": "1.0.0.0"
}
```

#### 1a. Connection References (2)

| Logical Name | Connector ID | Source |
|---|---|---|
| `fsi_cr_dataverse_sharingdetector` | `shared_commondataserviceforapps` | Invoker |
| `fsi_cr_teams_sharingdetector` | `shared_teams` | Invoker |

#### 1b. Trigger — Dataverse Row Created/Updated

```json
"When_Violation_Created_Or_Updated": {
  "type": "OpenApiConnectionWebhook",
  "inputs": {
    "parameters": {
      "subscriptionRequest/entityname": "fsi_sharingviolation",
      "subscriptionRequest/message": 4,
      "subscriptionRequest/scope": 4,
      "subscriptionRequest/filterexpression": "fsi_violation_status eq 0"
    },
    "host": {
      "apiId": "/providers/Microsoft.PowerApps/apis/shared_commondataserviceforapps",
      "connectionName": "shared_commondataserviceforapps",
      "operationId": "SubscribeWebhookTrigger"
    }
  }
}
```

Triggers when a `fsi_SharingViolation` row is created or updated with status = Open (0).

#### 1c. Variable Initialization (5 variables)

| Order | Variable | Type | Default | Description |
|-------|----------|------|---------|-------------|
| 1 | `ViolationId` | string | trigger record ID | Record ID from trigger |
| 2 | `AgentId` | string | from trigger | `fsi_agent_id` from violation |
| 3 | `EnvironmentId` | string | from trigger | `fsi_environment_id` from violation |
| 4 | `ViolationType` | integer | from trigger | `fsi_violation_type` from violation |
| 5 | `RemediationMode` | string | "Approval" | Default is Approval for ALL zones |

#### 1d. Scope_Try — Main Remediation Logic

**Action sequence inside Scope_Try:**

1. **Get_Violation_Details** — Dataverse `GetItem` on `fsi_sharingviolations` to get full violation record

2. **Check_Active_Exception** — Dataverse `ListRecords` on `fsi_sharingexceptions`:
   - `$filter`: `fsi_agent_id eq '{AgentId}' and fsi_violation_type eq {ViolationType} and fsi_exception_status eq 1 and fsi_expires_at ge {utcNow()}`
   - `$top`: 1

3. **Has_Active_Exception** — `Condition`: length > 0
   - True: Update violation status to Exception_Granted (2), exit
   - False: continue to remediation path

4. **Determine_Remediation_Mode** — `Condition`: check if auto-remediation applies
   - `ViolationType eq 1` (PUBLIC_INTERNET_LINK) AND `fsi_UASD_AutoRemediatePublicLink eq true`
   - True: Set RemediationMode = "Automatic"
   - False: RemediationMode stays "Approval" (default for ALL zones)

5. **Remediation_Mode_Switch** — `Switch` on RemediationMode:

   **Case "Automatic":**
   - **Load_Approved_Groups** — query approved groups for agent's zone
   - **Build_Approved_Principals_Array** — Compose array of approved group principals
   - **BAP_PATCH_Overwrite_Principals** — HTTP PATCH to BAP API:
     ```
     PATCH https://api.bap.microsoft.com/providers/Microsoft.BusinessAppPlatform/scopes/admin/environments/{EnvironmentId}/bots/{AgentId}/permissions?api-version=2021-04-01
     Body: { "put": [ ...approved group principals ] }
     Authentication: MSI, audience https://api.bap.microsoft.com
     ```
   - **Update_Violation_Remediated** — Dataverse update: status = Remediated (1), remediated_at, remediated_by = "Auto"
   - **Post_Remediation_Notification** — Teams card: auto-remediation complete

   **Case "Approval":**
   - **Create_Approval_Request** — Compose approval details with violation info
   - **Start_Approval** — Approval action to designated approver(s)
   - **Wait_For_Approval** — Wait on approval response
   - **Check_Approval_Outcome** — Condition on approval response:
     - Approved:
       - **Load_Approved_Groups_ForApproval** — same query
       - **Build_Approved_Principals_Array_ForApproval** — Compose approved principals
       - **BAP_PATCH_Overwrite_Principals_Approved** — same HTTP PATCH
       - **Update_Violation_Remediated_Approved** — status = Remediated (1)
       - **Post_Approval_Notification** — Teams card: remediation approved and applied
     - Rejected:
       - **Update_Violation_Rejected** — leave status as Open, add note
       - **Post_Rejection_Notification** — Teams card: remediation rejected

### Task 2: Create `src/uasd-exception-approval-workflow.json`

**Create** the exception approval flow JSON.

**Top-level structure:**
```json
{
  "properties": {
    "connectionReferences": { ... },
    "definition": { ... },
    "displayName": "fsi-UASD-ExceptionApproval-Workflow",
    "description": "Manages dual-approval exception lifecycle for sharing violations.",
    "state": "Started"
  },
  "schemaVersion": "1.0.0.0"
}
```

#### 2a. Trigger — Dataverse Row Created

Triggers when `fsi_SharingException` created with `fsi_exception_status = 0` (Pending).

#### 2b. Variables (3)

| Variable | Type | Default |
|----------|------|---------|
| `ExceptionId` | string | trigger record ID |
| `DefaultExceptionDays` | integer | 90 |
| `ExpiresAt` | string | computed from request date + 90 days |

#### 2c. Scope_Try — Main Approval Logic

1. **Get_Exception_Details** — Dataverse `GetItem` on `fsi_sharingexceptions`

2. **Compute_Expiration_Date** — `Compose`: `addDays(utcNow(), variables('DefaultExceptionDays'))`

3. **Security_Approval** — `Approval` action (First to respond):
   - Title: "UASD Exception Request — Security Approval"
   - Details: Agent name, violation type, business justification, data classification
   - Assigned to: Security team (configurable)

4. **Check_Security_Approval** — Condition on outcome:
   - Rejected:
     - Update exception status to Denied (2)
     - Post denial notification
     - Terminate
   - Approved:
     - Update `fsi_approved_by_security` with approver name
     - Continue to Data Owner approval

5. **Data_Owner_Approval** — `Approval` action (First to respond):
   - Title: "UASD Exception Request — Data Owner Approval"
   - Details: same + security approval info
   - Assigned to: Data Owner (configurable)

6. **Check_DataOwner_Approval** — Condition:
   - Rejected:
     - Update exception status to Denied (2)
     - Post denial notification
   - Approved:
     - Update exception:
       - `fsi_exception_status`: Approved (1)
       - `fsi_approved_by_data_owner`: approver
       - `fsi_approved_at`: utcNow()
       - `fsi_expires_at`: computed expiration
     - Update related violation: status = Exception_Granted (2)
     - Post approval notification with expiration date

7. **Expiration Scanner Scope** — Separate scope (runs on schedule):
   - Query exceptions where `fsi_exception_status eq 1 and fsi_expires_at lt {utcNow()}`
   - For each expired: update status to Expired (3)
   - Re-evaluate violation: if exception expired and sharing still non-compliant, reopen violation

NOTE: The expiration scanner is better implemented as a separate scheduled flow or as part of the detector flow. For this plan, include the expiration scanner logic as documentation comments within the flow JSON, but the actual scanner runs within the detector flow on each scan cycle.
