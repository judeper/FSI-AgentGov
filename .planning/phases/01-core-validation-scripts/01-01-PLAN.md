**Connect-AuditServices.ps1:**
- Function `Connect-AuditServices` that handles connection to Exchange Online PowerShell
- Support two auth modes via parameter set:
  - Interactive: Uses `Connect-ExchangeOnline -ShowBanner:$false`
  - ServicePrincipal: Uses `Connect-ExchangeOnline -CertificateThumbprint` or `-AppId -CertificateFilePath` parameters
- Accept parameters: `-TenantId`, `-ClientId`, `-CertificateThumbprint` (for service principal), `-Interactive` (switch)
- Do NOT support client secret for Exchange Online (Microsoft deprecated basic auth; certificate-based is the standard)
- Include `-ErrorAction Stop` on all connection calls
- Wrap in try-catch with specific error types:
  - `CommandNotFoundException` -> "ExchangeOnlineManagement module not installed"
  - Connection errors -> "Failed to connect to Exchange Online. Check credentials/network."
  - Generic catch -> re-throw with context
- Also include function `Connect-ComplianceSession` that calls `Connect-IPPSSession` (needed for Purview retention queries in Plan 02)
- Same auth pattern (interactive vs service principal)
- Include `Disconnect-AuditServices` function that calls both `Disconnect-ExchangeOnline -Confirm:$false` and `Disconnect-ExchangeOnline` for compliance session, both with `-ErrorAction SilentlyContinue`
- Add `#Requires -Version 7.0` and `#Requires -Modules @{ ModuleName="ExchangeOnlineManagement"; ModuleVersion="3.7.0" }` at top
- Follow existing scope-drift-monitor script style: comment-based help (.SYNOPSIS, .DESCRIPTION, .PARAMETER, .EXAMPLE, .NOTES)

**New-CanaryEvent.ps1:**
- Function `New-CanaryEvent` that generates a retrievable audit event for dual validation
- Strategy: Use `Set-Mailbox` to update CustomAttribute15 on the connected admin's mailbox with a canary GUID, then revert. This creates an auditable Exchange admin event that Search-UnifiedAuditLog can retrieve.
- Accept parameters: `-CanaryId` (string, defaults to `[Guid]::NewGuid().ToString()`), `-MailboxIdentity` (string, defaults to connected user)
- Return a PSCustomObject with: `CanaryId`, `Timestamp`, `Operation` ("Set-Mailbox"), `Target` (mailbox identity)
- Wrap in try-catch. On failure, return object with `Status = "Failed"` and `ErrorMessage` property
- The canary event approach: Set CustomAttribute15 to "ACV-Canary-{CanaryId}", wait 2 seconds, revert to original value
- Add `#Requires -Version 7.0` at top
- Comment-based help with .SYNOPSIS, .DESCRIPTION, .NOTES explaining the canary approach

**Script structure:**

Header:
- `#Requires -Version 7.0`
- `#Requires -Modules @{ ModuleName="ExchangeOnlineManagement"; ModuleVersion="3.7.0" }`
- Comment-based help (.SYNOPSIS: "Validates M365 Unified Audit Log configuration using dual validation strategy", .DESCRIPTION, .PARAMETER, .EXAMPLE, .NOTES)
- [CmdletBinding()] with params: `-SkipCanaryValidation` (switch), `-GracePeriodHours` (int, default 24), `-CanaryWaitSeconds` (int, default 300), `-Interactive` (switch), `-TenantId`, `-ClientId`, `-CertificateThumbprint`

Dot-source private helpers at top:
```powershell

```

**Main logic (implement as function `Test-UnifiedAuditLog` called at end of script):**

Step 1 — Connect:
- Call Connect-AuditServices with auth params passed through
- Wrap in try-catch; on failure return result object with Status="Error", Reason="Connection failed"

Step 2 — Check Unified Audit Log (TVAL-01):
- `$config = Get-AdminAuditLogConfig -ErrorAction Stop`
- Check `$config.UnifiedAuditLogIngestionEnabled`
- CRITICAL: This MUST use Exchange Online PowerShell, NOT Security & Compliance. The Connect-AuditServices helper handles this correctly.
- If False: return immediately with Status="Failed", Check="UnifiedAuditLog", Reason="UnifiedAuditLogIngestionEnabled is False", Confidence="HIGH"

Step 3 — Check Admin Audit Log (TVAL-03):
- Same config object: check `$config.AdminAuditLogEnabled`
- If False: add to results but continue (admin audit is separate concern)

Step 4 — Dual Validation via Canary Event (TVAL-04):
- Skip if `-SkipCanaryValidation` switch is set (return with Confidence="MEDIUM" and note that canary was skipped)
- Generate canary: `$canary = New-CanaryEvent`
- If canary generation failed, return Warning with reason
- Wait: `Start-Sleep -Seconds $CanaryWaitSeconds` (default 5 min)
- Search: `Search-UnifiedAuditLog -StartDate (Get-Date).AddHours(-1) -EndDate (Get-Date) -FreeText $canary.CanaryId -ResultSize 1`
- If found: Status="Passed", Confidence="HIGH", Reason="Cmdlet enabled AND canary event retrieved"
- If NOT found: Check if audit was enabled within grace period. Use logic: if no historical events exist for past $GracePeriodHours hours, it may be newly enabled
  - Within grace period: Status="GracePeriod", Confidence="MEDIUM", Reason="Enabled within $GracePeriodHours hours, audit lag expected"
  - Outside grace period: Status="Warning", Confidence="MEDIUM", Reason="Cmdlet reports enabled but canary event not found after $CanaryWaitSeconds seconds"

Step 5 — Disconnect:
- Call Disconnect-AuditServices in finally block

**Return object structure (PSCustomObject):**
```
@{
    Timestamp       = (Get-Date -Format "o")
    ValidationType  = "UnifiedAuditLog"
    Checks          = @(
        @{ Name = "UnifiedAuditLogIngestionEnabled"; Status = "Passed|Failed"; Value = $true|$false }
        @{ Name = "AdminAuditLogEnabled"; Status = "Passed|Failed"; Value = $true|$false }
        @{ Name = "CanaryEventValidation"; Status = "Passed|Failed|GracePeriod|Skipped|Warning"; CanaryId = "..."; WaitSeconds = 300 }
    )
    OverallStatus   = "Passed|Failed|Warning|GracePeriod"
    Confidence      = "HIGH|MEDIUM"
    Reason          = "Summary reason"
}
```

IMPORTANT: Use `$ErrorActionPreference = "Stop"` at script level. All cmdlet calls must have `-ErrorAction Stop`. Follow the established pattern from scope-drift-monitor (Invoke-DriftScan.ps1).

Do NOT use `ensures compliance` or `guarantees` in any comments — use "supports compliance with", "helps meet" per CONTRIBUTING.md language rules.
