### Task 1: Create Deployment Guide (DPL-01)
**File:** `docs/playbooks/asard-deployment-guide.md`

**Content Structure:**
1. **Introduction:** Overview of ASARD deployment, scope, regulatory context
2. **Prerequisites:**
   - Azure AD app registration capability
   - Power Platform admin role
   - Dataverse environment access
   - Python 3.9+
   - Required packages (msal, requests, azure-identity)
3. **Deployment Steps:**
   - Step 1: Azure AD app registration with BAP Admin API permissions
   - Step 2: Run `create_asard_dataverse_schema.py` to create Dataverse tables
   - Step 3: Populate approved security group policy table
   - Step 4: Configure zone classification (environment naming conventions)
   - Step 5: Run detection scan (`detect_agent_sharing_violations.py`) — first dry run, then full scan
   - Step 6: Import Power Automate flows (approval + exception review)
   - Step 7: Configure Teams webhook for notifications
   - Step 8: Schedule recurring scans (daily/weekly)
4. **Verification:**
   - Confirm Dataverse schema created
   - Run test detection scan
   - Check Dataverse records populated
   - Verify Teams notifications received
   - Test approval workflow
5. **Post-Deployment:**
   - Monitoring recommendations
   - Baseline establishment
   - Exception backlog review

**Acceptance Criteria:**

- [ ] Each deployment step has command examples and expected output
- [ ] Verification steps cover all critical components

### Task 2: Create Troubleshooting Guide (DPL-02)
**File:** `docs/playbooks/asard-troubleshooting-guide.md`

**Content Structure:**
1. **Introduction:** Purpose, scope, escalation paths
2. **BAP API Authentication Issues:**
   - Symptom: 401 Unauthorized errors
   - Causes: Expired tokens, insufficient permissions, wrong tenant
   - Diagnostics: Check token expiry, verify app permissions, validate tenant ID
   - Resolution: Refresh tokens, update permissions, correct configuration
3. **Security Group Resolution Failures:**
   - Symptom: Agents marked as violations despite approved groups
   - Causes: Group not found, deleted groups, nested groups not supported
   - Diagnostics: Check group existence in Azure AD, verify group ID format
   - Resolution: Update approved group list, handle deleted groups, document nested group limitations
4. **Agent Enumeration Failures:**
   - Symptom: Incomplete agent inventory
   - Causes: API throttling, environment access denied, deleted agents
   - Diagnostics: Check API rate limits, verify environment permissions, review API responses
   - Resolution: Implement retry logic, request access, handle deleted agents
5. **Dataverse Write Errors:**
   - Symptom: Violation records not saved
   - Causes: Schema mismatch, alternate key conflicts, throttling
   - Diagnostics: Validate schema version, check for duplicate keys, monitor API limits
   - Resolution: Update schema, resolve conflicts, implement backoff
6. **Detection False Positives/Negatives:**
   - Symptom: Incorrect violation detection
   - Causes: Zone classification errors, sharing principal parsing issues
   - Diagnostics: Review zone rules, verify environment naming conventions, check sharing principals
   - Resolution: Adjust zone rules, update naming patterns, refine parsing logic
7. **Remediation Failures:**
   - Symptom: PATCH operations fail
   - Causes: API errors, validation failures, concurrent modifications
   - Diagnostics: Review API error messages, check agent state, verify timing
   - Resolution: Retry with exponential backoff, validate before remediation, handle concurrency
8. **Exception Workflow Issues:**
   - Symptom: Expired exceptions not reset, notifications not sent
   - Causes: Flow misconfiguration, webhook failures, trigger conditions
   - Diagnostics: Check flow run history, validate webhook URL, review triggers
   - Resolution: Reconfigure flows, update webhooks, adjust trigger conditions

**Acceptance Criteria:**
- [ ] Each issue has symptom, cause, diagnostics, resolution
- [ ] Diagnostic steps are actionable and specific
- [ ] Resolutions reference actual scripts and parameters
- [ ] Regulatory language compliant
- [ ] Cross-references to deployment guide where appropriate
- [ ] MkDocs markdown format
