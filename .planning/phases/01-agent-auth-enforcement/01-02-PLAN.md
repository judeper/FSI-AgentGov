# Plan 01-02: Drift Detection + Evidence Export + JSON Output

## Objective

Extend `Test-AgentAuthConfiguration.ps1` with drift detection that compares current scan results against a previous baseline, SHA-256 evidence hashing for regulatory audit trails, and Dataverse-compatible JSON output structure.

## Tasks

### Task 1: Baseline Loading and Comparison Logic

**Action:** Add drift detection functions and wire up `$BaselinePath` parameter.

**Details:**
- `Import-AuthBaseline` function:
  - Loads previous scan JSON from `$BaselinePath`
  - Returns `$null` if file doesn't exist (first scan = no baseline to compare)
  - Validates JSON structure matches expected schema

- `Compare-AgentAuthBaseline` function:
  - Accepts current checks array and previous baseline object
  - Builds lookup by composite key: `"$EnvironmentId|$AgentId|$SSPMId"`
  - Detects drift types:
    - `NewAgent` — agent exists in current scan but not baseline
    - `RemovedAgent` — agent in baseline but not current scan  
    - `SettingChanged` — auth setting value changed (e.g., AuthMode switched from "Always" to "AsNeeded")
    - `StatusChanged` — check result changed (Pass→Fail, Fail→Pass)
  - Returns array of drift objects:
    ```
    SSPMId, AgentId, AgentName, EnvironmentId, EnvironmentName,
    DriftType, PreviousValue, CurrentValue, PreviousStatus, CurrentStatus,
    DetectedAt
    ```

- Wire up in main script flow:
  1. After all checks complete (end of Plan 01 output section)
  2. If `$BaselinePath` provided and file exists, load and compare
  3. Add `Drifts` property to results object
  4. Include drift count in console summary

**Acceptance criteria:**
- First scan (no baseline) produces empty drift array with informational message
- Subsequent scan with changes produces accurate drift records
- Composite key handles agents that appear in multiple environments

### Task 2: SHA-256 Evidence Hashing

**Action:** Implement evidence integrity hashing for each check result and for the overall results object.

**Details:**
- **Per-check evidence hash:**
  - For each SSPM check result, compute SHA-256 over the evidence payload (raw API response JSON)
  - Store as `EvidenceHash` property on each check result
  - Pattern: serialize evidence to JSON, hash, hex string

- **Overall integrity hash:**
  - After all results assembled, compute SHA-256 over the complete results JSON
  - Store in `Metadata.IntegrityHash`
  - Only when `-IncludeEvidence` switch is specified
  - Use established pattern from `Invoke-HardeningBaselineCheck.ps1`

- **Evidence payload:**
  - For SSPM-1.1-01 through SSPM-1.1-03: raw bot properties JSON
  - For SSPM-1.1-04: raw permissions array JSON
  - For SSPM-1.1-05: tenant settings JSON
  - For SSPM-1.1-06: agent blocking status JSON (or "ManualCheck" if API unavailable)

**Acceptance criteria:**
- Each check result has `EvidenceHash` when evidence is available
- Overall `IntegrityHash` computed when `-IncludeEvidence` specified
- Hash format: uppercase hex without dashes (consistent with existing scripts)

### Task 4: Baseline Auto-Save

**Action:** After a successful scan, automatically save results as the new baseline (when `$BaselinePath` is specified).

**Details:**
- After all checks and drift detection complete
- If `$BaselinePath` is specified:
  - Save current results JSON to `$BaselinePath`
  - Create parent directory if needed
  - Log: "Baseline saved to $BaselinePath"
- This enables the next scan to detect drifts against the current state
- Use `-WhatIf` to preview without writing

**Acceptance criteria:**
- Baseline JSON file created/overwritten after successful scan
- File contains valid JSON matching the output structure
- WhatIf mode does not write the baseline file
