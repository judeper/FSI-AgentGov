# Plan 01-01: Script Core + BAP API Integration + 6 SSPM Checks

## Objective

Create `Test-AgentAuthConfiguration.ps1` with PowerShell 7.0 conventions, BAP API integration for per-agent authentication configuration retrieval, and validation of 6 SSPM items with zone-based logic.

## Tasks

### Task 1: Script Scaffolding and Parameters

**Action:** Create `scripts/governance/Test-AgentAuthConfiguration.ps1` with comment-based help, `#Requires` directives, and parameter block.

**Details:**
- Comment-based help with `.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`, `.OUTPUTS`, `.NOTES`
- `#Requires -Version 7.0`
- `#Requires -Modules @{ ModuleName = 'Microsoft.PowerApps.Administration.PowerShell'; ModuleVersion = '2.0.0' }`
- Parameters: `$OutputFormat` (Table/JSON/Object default Table), `$OutputPath`, `$EnvironmentFilter`, `$ZoneMapping` (hashtable), `$IncludeEvidence` (switch), `$BaselinePath` (for drift detection — wired up in Plan 02)
- `[CmdletBinding(SupportsShouldProcess)]`
- Banner and WhatIf preview following established pattern

**Acceptance criteria:**
- Script loads without parse errors in PowerShell 7.0+
- All parameters have validation attributes
- Help text is complete

### Task 2: Helper Functions

**Action:** Implement helper functions for BAP API access and result building.

**Details:**
- `Get-BapApiToken` — acquires OAuth token for `https://api.bap.microsoft.com` via `Get-AzAccessToken` (same pattern as `Invoke-SharingAudit.ps1`)
- `Invoke-BapApi` — wrapper around `Invoke-RestMethod` with Bearer auth, error handling, retry support
- `Get-EnvironmentZone` — returns zone number from `$ZoneMapping` hashtable (same pattern as `Invoke-HardeningBaselineCheck.ps1`, default Zone 1)
- `New-AuthCheckResult` — creates standardized check result PSCustomObject with: `SSPMId`, `ItemNumber`, `Setting`, `Status` (Pass/Fail/Skip/Warning), `Expected`, `Actual`, `AgentId`, `AgentName`, `EnvironmentId`, `EnvironmentName`, `Zone`, `Message`

**Acceptance criteria:**
- `Get-BapApiToken` returns token string or throws descriptive error
- `Invoke-BapApi` handles 401/403/429 gracefully
- `New-AuthCheckResult` produces consistent objects

### Task 3: Tenant-Level Checks (SSPM-1.1-05, SSPM-1.1-06)

**Action:** Implement Check Group 1 — tenant-level authentication governance settings.

**Details:**
- **SSPM-1.1-05 (AI Feature Publishing):** Use `Get-TenantSettings` → `powerPlatform.copilotStudio.publishBotsWithAIFeatures`. Zone 1: Pass (allowed). Zone 2/3: Fail if enabled.
  - Since this is a tenant-wide setting, check it once and report zone-specific status
- **SSPM-1.1-06 (Unapproved Agent Blocking):** Attempt to query M365 Admin Center agent inventory API for blocking status. If API unavailable, report as `Skip` with message directing to manual verification.
  - This check is expected to be Semi-Automated — document the manual fallback

**Acceptance criteria:**
- SSPM-1.1-05 correctly evaluates tenant toggle
- SSPM-1.1-06 attempts API, falls back to Skip gracefully
- Results added to `$allChecks` collection

### Task 4: Per-Agent Checks (SSPM-1.1-01 through SSPM-1.1-04)

**Action:** Implement Check Group 2 — per-agent authentication and sharing validation.

**Details:**
- Enumerate environments via BAP API (same URL as `Invoke-SharingAudit.ps1`)
- Apply `$EnvironmentFilter` if specified
- For each environment, list agents via `/bots` endpoint
- For each agent, extract authentication properties:

  **SSPM-1.1-01 (No Authentication):**
  - Check `properties.configuration.authenticationMode` or equivalent
  - "NoAuthentication" → Fail in ALL zones
  - Any other value → Pass

  **SSPM-1.1-02 (Sign-in Required for Manual Auth):**
  - If auth mode is "Manual"/"AuthenticateManually", check `requireUserAuthentication` toggle
  - Not enabled → Zone 1: Warning, Zone 2/3: Fail
  - If auth mode is not Manual → Pass (N/A)

  **SSPM-1.1-03 (Authentication Timing):**
  - Check `authenticationTiming` or `authenticationTrigger` property
  - "AsNeeded" → Zone 1: Warning, Zone 2/3: Fail
  - "Always" → Pass

  **SSPM-1.1-04 (Sharing Scope):**
  - Query permissions endpoint (same as SharingAudit)
  - If any Organization/Tenant/Public principal exists → Zone 1: Warning, Zone 2/3: Fail

- Handle missing/unexpected properties with `Skip` status and descriptive message
- Progress output via `Write-Verbose` with environment/agent counters

**Acceptance criteria:**
- All 4 per-agent checks produce results for every scanned agent
- Zone-based logic correctly differentiates Zone 1 warnings from Zone 2/3 failures
- Missing API properties handled gracefully (Skip, not crash)

### Task 5: Results Aggregation and Output

**Action:** Implement results aggregation, console summary, and output formatting.

**Details:**
- Aggregate check results into PSCustomObject:
  ```
  Metadata: ScriptName, ScriptVersion (1.0.0), CheckedAt, DurationSeconds, EnvironmentsScanned, AgentsScanned, IntegrityHash
  Summary: TotalChecks, Passed, Failed, Skipped, Warnings, OverallStatus
  Checks: array of check results
  Gaps: array of gap description strings
  ```
- Console summary banner (cyan box drawing, same style as HardeningBaseline)
- Output switch: JSON → file or console, Table → Format-Table, Object → Write-Output
- JSON output creates parent directory if needed (established pattern)

**Acceptance criteria:**
- Output structure matches established governance script patterns
- JSON output is valid and parseable
- Console summary displays counts correctly
