  <name>Task 1: Create unified monitoring framework in monitoring_shared.py</name>
  <files>scripts/monitoring_shared.py, scripts/learn_monitor.py</files>
  <action>
Create `scripts/monitoring_shared.py` containing the unified monitoring framework. This is the core of the "one system, multiple source adapters" architecture required by the locked decision on unified monitoring.

**Part A: Extract shared utilities from learn_monitor.py (refactor, not duplicate):**
1. `fetch_page(url, session, max_retries)` - HTTP fetch with retry logic and exponential backoff (lines ~172-211 of current learn_monitor.py)
2. `normalize_content(html)` - HTML normalization using BeautifulSoup (strip scripts, styles, nav, normalize whitespace, mask dates)
3. `compute_hash(content)` - SHA-256 content hashing
4. `classify_change(old_text, new_text, url)` - 4-tier classification (CRITICAL/HIGH/MEDIUM/NOISE) with pattern matching
5. `find_affected_controls(url, docs_dir)` - Scan `docs/controls/pillar-*/` and `docs/playbooks/` for files referencing the URL. Return dict with `controls` (list of {control_id, title, file_path}) and `playbooks` (list of {file_path, priority}). Priority is CRITICAL if portal-walkthrough, HIGH otherwise.
6. `format_change_summary(changes)` - Generate a summary table at the top of change reports showing: Change #, URL (shortened), Classification, Affected Controls, Action Required. Enables the "quick scan" requirement from CONTEXT.md.

**Part B: Unified state management (critical for unification):**
7. `save_state_atomic(state, state_path)` - Atomic state file writing (temp file + rename, with backup)
8. `load_state(state_path)` - State loading with corruption recovery (JSON parse with fallback to empty state)

The unified state file format uses a single file (`data/monitor-state.json`) with source-keyed sections:
```json
{
  "version": 1,
  "sources": {
    "learn": {
      "last_run": "2026-02-04T06:00:00Z",
      "entries": { ... }
    },
    "regulatory-federal-register": {
      "last_run": "2026-02-04T07:00:00Z",
      "entries": { ... }
    },
    "regulatory-finra": {
      "last_run": "2026-02-04T07:00:00Z",
      "entries": { ... }
    }
  }
}
```
- `load_state()` returns the full state dict; callers access their source key
- `save_state_atomic()` writes the full state dict atomically
- Backward compatibility: if `data/learn-monitor-state.json` exists (old format), `load_state()` migrates it into the unified format under the `"learn"` key on first load
- Helper: `get_source_state(state, source_key)` returns the source-specific section (or empty dict if new source)
- Helper: `set_source_state(state, source_key, source_state)` updates a source section

**Part C: Unified report format helpers:**
9. `generate_report_header(title, run_date, metadata_dict)` - Standard report header with title, date, and metadata
10. `generate_executive_summary(changes_by_tier)` - Standard executive summary with tier counts
11. `write_report(report_content, report_dir, filename)` - Write report to disk, creating directory if needed

Reports from all sources go into `reports/monitoring/` with filenames that include the source type:
- `reports/monitoring/learn-changes-YYYY-MM-DD.md`
- `reports/monitoring/regulatory-changes-YYYY-MM-DD.md`

This keeps all monitoring output in one directory while allowing source-specific filenames.

Update the report generation section of `learn_monitor.py` to produce enhanced change reports with the new format:

**Report structure (top to bottom):**

1. **Header** - Report title, date, run metadata (URLs checked, time taken). Use `generate_report_header()` from monitoring_shared.
2. **Executive Summary** - Quick stats: Total URLs, Changes by tier (CRITICAL: N, HIGH: N, MEDIUM: N, NOISE: N), Redirects, Errors. Use `generate_executive_summary()` from monitoring_shared.
3. **Summary Table** - Generated by `format_change_summary()`. Columns: #, URL (shortened to last path segment), Classification, Affected Controls (comma-separated IDs like "1.3, 1.5"), Action
4. **Detailed Changes** - For each CRITICAL and HIGH change:
   - URL (full)
   - Classification badge
   - **Affected Controls** section listing each control ID and title
   - **Affected Playbooks** section listing playbook paths with priority
   - **What Changed** section with unified diff (truncated to 100 lines if longer)
5. **Redirects** section (unchanged from current)
6. **Errors** section (unchanged from current)
7. **MEDIUM/NOISE Changes** - Collapsed list (just URLs and classification, no diffs)

**Report output:** Write to `reports/monitoring/learn-changes-YYYY-MM-DD.md` using `write_report()` from monitoring_shared.

**Key enhancement:** Each change now includes "Affected Controls" populated by `find_affected_controls()`. This maps "learn.microsoft.com/purview/dlp-policies changed" to "affects Controls 1.3, 1.5" as specified in CONTEXT.md.
