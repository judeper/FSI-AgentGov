Create `scripts/regulatory_monitor.py` — a regulatory source adapter that extends the unified monitoring system from Plan 08-01. This script MUST import and use `monitoring_shared.py` for all shared operations.

**Required imports from monitoring_shared.py:**
```python
from monitoring_shared import (
    fetch_page, compute_hash, save_state_atomic, load_state,
    get_source_state, set_source_state,
    generate_report_header, generate_executive_summary,
    format_change_summary, write_report,
)
```

**1. Federal Register API Integration:**
- Use the Federal Register API (https://www.federalregister.gov/api/v1/documents.json) — no API key required
- Query for documents from these agencies (using their Federal Register slugs):
  - `securities-and-exchange-commission` (SEC)
  - `commodity-futures-trading-commission` (CFTC)
  - `comptroller-of-the-currency` (OCC)
  - `federal-reserve-system` (Federal Reserve / Fed SR 11-7)
- Filter for document types: RULE, PRORULE (proposed rule), NOTICE
- Fetch documents published since last check (from unified state file, source key: `"regulatory-federal-register"`)
- For each document, extract: title, URL, publication_date, type, abstract, agencies
- Use `requests` library (already available)

**2. FINRA Notices Monitoring:**
- Fetch the FINRA regulatory notices page: `https://www.finra.org/rules-guidance/notices`
- Use BeautifulSoup to extract notice entries (title, URL, date)
- Compare against unified state file (source key: `"regulatory-finra"`) to identify new notices
- Note: FINRA does not provide RSS, so HTML scraping is required

**3. FSI Relevance Classification (uses same tier names as Learn Monitor):**
- Classify each regulatory item using the unified 4-tier system (CRITICAL/HIGH/MEDIUM/NOISE) for consistency with Learn Monitor:
  - CRITICAL: Directly mentions AI agents, copilot, or automated advice in FSI context
  - HIGH: AI, artificial intelligence, machine learning, LLM, generative, chatbot, automation, supervision (FINRA 3110), recordkeeping (FINRA 4511), SEC 17a-3/4
  - MEDIUM: broker-dealer, investment adviser, customer communication, cybersecurity, data protection, privacy, compliance, audit
  - NOISE: Everything else (general regulatory items with no FSI/AI relevance)
- Classification function: `classify_regulatory_relevance(title, abstract) -> (tier, reason)`
- Broad FSI capture per CONTEXT.md: capture ALL FSI regulatory changes, let reviewer triage

**4. Unified State Management (MUST use shared state file):**
- State file: `data/monitor-state.json` (the SAME file used by Learn Monitor)
- Use `load_state()` and `save_state_atomic()` from monitoring_shared.py
- Use `get_source_state(state, "regulatory-federal-register")` and `get_source_state(state, "regulatory-finra")` to access source-specific sections
- Source state structure (within the unified state file):
  ```json
  {
    "regulatory-federal-register": {
      "last_run": "2026-02-04T07:00:00Z",
      "last_checked": "2026-02-04",
      "entries": { "2026-12345": "hash", "2026-12346": "hash" }
    },
    "regulatory-finra": {
      "last_run": "2026-02-04T07:00:00Z",
      "entries": { "https://www.finra.org/...": "hash" }
    }
  }
  ```
- IMPORTANT: The `entries` dict structure matches the Learn Monitor's `entries` pattern for consistency

**5. Report Generation (MUST use shared report helpers):**
- Output to `reports/monitoring/regulatory-changes-YYYY-MM-DD.md` (same directory as Learn reports)
- Use `generate_report_header()`, `generate_executive_summary()`, `format_change_summary()`, and `write_report()` from monitoring_shared.py
- Report format mirrors Learn Monitor reports for consistency:
  ```markdown
  # Regulatory Monitor Report - YYYY-MM-DD

  [Header from generate_report_header()]

  [Executive Summary from generate_executive_summary()]

  ## Summary

  [Summary table from format_change_summary()]

  ## CRITICAL / HIGH Items

  ### 1. [Title](URL)
  - **Source:** SEC via Federal Register
  - **Published:** YYYY-MM-DD
  - **Type:** RULE / PRORULE / NOTICE
  - **Classification:** HIGH — AI-specific
  - **Abstract:** ...
  - **Potentially Affected Controls:** (keyword-based suggestions)
    - Mentions "supervision" → see Control 2.12
    - Mentions "recordkeeping" → see Controls 1.7, 1.10

  ## MEDIUM Items
  (same format, abbreviated)

  ## NOISE Items
  (list only, no details)
  ```

**6. CLI Interface (match Learn Monitor pattern):**
- Arguments: `--dry-run` (don't update state), `--verbose`, `--limit N` (limit items per source), `--source federal-register|finra|all` (default: all)
- Exit codes: 0 (no new items), 1 (new items found), 2 (error)
- Match the CLI pattern of learn_monitor.py for consistency
