  <action>
Create `scripts/regulatory_monitor.py` - a standalone regulatory monitoring script that:

**1. Federal Register API Integration:**
- Use the Federal Register API (https://www.federalregister.gov/api/v1/documents.json) - no API key required
- Query for documents from these agencies (using their Federal Register slugs):
  - `securities-and-exchange-commission` (SEC)
  - `commodity-futures-trading-commission` (CFTC)
  - `comptroller-of-the-currency` (OCC)
  - `federal-reserve-system` (Federal Reserve / Fed SR 11-7)
- Filter for document types: RULE, PRORULE (proposed rule), NOTICE
- Fetch documents published since last check (stored in state file)
- For each document, extract: title, URL, publication_date, type, abstract, agencies
- Use `requests` library (already available, used by Learn Monitor)

**2. FINRA Notices Monitoring:**
- Fetch the FINRA regulatory notices page: `https://www.finra.org/rules-guidance/notices`
- Use BeautifulSoup to extract notice entries (title, URL, date)
- Compare against state file to identify new notices since last check
- Note: FINRA does not provide RSS, so HTML scraping is required

**3. FSI Relevance Classification:**
- For each regulatory item, classify relevance using keyword patterns:
  - HIGH relevance: AI, artificial intelligence, machine learning, LLM, generative, copilot, agent, chatbot, automation, supervision (FINRA 3110), recordkeeping (FINRA 4511), SEC 17a-3/4
  - MEDIUM relevance: broker-dealer, investment adviser, customer communication, cybersecurity, data protection, privacy, compliance, audit
  - LOW relevance: everything else
- Classification function: `classify_fsi_relevance(title, summary) -> (relevance_level, reason)`
- Broad FSI capture per CONTEXT.md: capture ALL FSI regulatory changes, let reviewer triage

**4. State Management:**
- State file: `data/regulatory-monitor-state.json`
- State structure:
  ```json
  {
    "last_run": "2026-02-04T06:00:00Z",
    "federal_register": {
      "last_checked": "2026-02-04",
      "known_document_ids": ["2026-12345", "2026-12346"]
    },
    "finra": {
      "last_checked": "2026-02-04",
      "known_notice_urls": ["https://www.finra.org/..."]
    }
  }
  ```
- Use atomic state file writing (import from monitoring_shared if available, otherwise implement inline with temp+rename pattern)

**5. Report Generation:**
- Output to `reports/regulatory-changes/regulatory-changes-YYYY-MM-DD.md`
- Report format:
  ```markdown
  # Regulatory Monitor Report - YYYY-MM-DD

  **Run Date:** YYYY-MM-DD HH:MM UTC
  **Sources Checked:** Federal Register (SEC, CFTC, OCC, Fed), FINRA Notices
  **New Items:** N (HIGH: X, MEDIUM: Y, LOW: Z)

  ## Summary

  | # | Source | Title | Date | Relevance | Reason |
  |---|--------|-------|------|-----------|--------|
  | 1 | SEC | ... | ... | HIGH | AI-specific |
  | 2 | FINRA | ... | ... | MEDIUM | Supervision |

  ## HIGH Relevance Items

  ### 1. [Title](URL)
  - **Source:** SEC via Federal Register
  - **Published:** YYYY-MM-DD
  - **Type:** RULE / PRORULE / NOTICE
  - **Relevance:** HIGH - AI-specific
  - **Abstract:** ...
  - **Potentially Affected Controls:** (keyword-based suggestions)
    - Mentions "supervision" → see Control 2.12
    - Mentions "recordkeeping" → see Controls 1.7, 1.10

  ## MEDIUM Relevance Items
  (same format, abbreviated)

  ## LOW Relevance Items
  (list only, no details)
  ```

**6. CLI Interface:**
- Arguments: `--dry-run` (don't update state), `--verbose`, `--limit N` (limit items per source), `--source federal-register|finra|all` (default: all)
- Exit codes: 0 (no new items), 1 (new items found), 2 (error)
- Match the CLI pattern of learn_monitor.py for consistency

**7. Keyword-to-Control Mapping:**
- Implement a simple keyword-to-control mapping for "Potentially Affected Controls" section:
  ```python
  KEYWORD_CONTROL_MAP = {
      'supervision': ['2.12', '2.18'],
      'recordkeeping': ['1.7', '1.10'],
      'retention': ['1.7', '1.10'],
      'data loss prevention': ['1.3', '1.5'],
      'dlp': ['1.3', '1.5'],
      'audit': ['1.7', '3.1', '3.2'],
      'access control': ['1.1', '1.2', '1.11'],
      'encryption': ['1.14', '1.15'],
      'risk management': ['2.6', '2.7'],
      'incident': ['2.14', '2.15'],
      'disaster recovery': ['2.16', '2.17'],
      'information barrier': ['1.22', '1.23'],
      'communication': ['1.10', '2.18', '2.19'],
      'ai': ['2.6', '2.12', '3.8'],
      'artificial intelligence': ['2.6', '2.12', '3.8'],
      'machine learning': ['2.6', '2.12'],
      'model risk': ['2.6'],
  }
  ```
- This provides actionable suggestions without requiring exact URL-to-control matching (which is not possible for regulatory content not embedded in docs)

**Dependencies:** `requests`, `beautifulsoup4` (both already installed for Learn Monitor). `feedparser` is NOT needed since FINRA does not provide RSS.

**Important:** If `monitoring_shared.py` from Plan 08-01 is not yet available, implement atomic state writing and hash utilities inline. The import can be added later. This allows parallel execution with Plan 08-01.
