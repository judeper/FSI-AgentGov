# Plan 01-03: Policy Drift Detection Scripts

## Goal

Create the policy drift detection capability — baseline capture, comparison logic, and drift monitoring orchestrator — enabling operators to detect unauthorized CA policy modifications. After this plan, operators can snapshot CA policy state, compare against baselines, and identify drift with severity-classified output.

## Must-Haves Covered

- **Must-Have 5**: Policy drift detection comparing deployed CA policies against template baselines (enabled→disabled, conditions changed, controls weakened)

## Tasks

### Task 1: Policy Baseline Loading

**Create** `scripts/private/Get-PolicyBaseline.ps1`

`Get-CAAPolicyBaseline` function:
- Queries Graph API for all CA policies matching FSI naming pattern (`CA-CopilotStudio-*`, `CA-AgentBuilder-*`, `CA-M365Copilot-*`, `CA-BlockLegacyAuth-*`, `CA-RequireCompliantDevice-*`)
- Returns normalized policy objects with:
  - `PolicyId`, `DisplayName`, `State`
  - `Conditions` (users, applications, signInRiskLevels, clientAppTypes, platforms)
  - `GrantControls` (operator, builtInControls, authenticationStrength)
  - `SessionControls` (signInFrequency, persistentBrowser)
  - `Zone` (derived from policy name pattern)
  - `SnapshotTimestamp` (UTC)
- `-PolicyNamePrefix` parameter to customize pattern matching
- Handles pagination for large policy sets
- `SupportsShouldProcess` — `-WhatIf` shows which policies would be queried
- Full help comments

**Acceptance:** Returns normalized policy objects for all FSI CA policies; zone correctly derived from name; timestamps are UTC.

### Task 2: Baseline Comparison Logic

**Create** `scripts/private/Compare-PolicyBaseline.ps1`

`Compare-CAAPolicyBaseline` function:
- Compares two baseline snapshots (previous vs current) on these dimensions:
  1. **State changes**: enabled ↔ reportOnly ↔ disabled
  2. **Condition changes**: users added/removed from includes/excludes, applications changed, risk levels changed
  3. **Grant control changes**: controls added/removed, operator changed (AND→OR = weakening)
  4. **Session control changes**: frequency changed, persistent browser toggled
  5. **Policy additions/removals**: new policies appearing, expected policies missing
- Severity classification (following ACV canonical: 1=Passed, 2=Warning, 3=GracePeriod, 4=Failed, 5=Error):
  - **5 (Error)**: Expected policy deleted or missing
  - **4 (Failed)**: Policy disabled, grant controls weakened, break-glass exclusion removed
  - **3 (GracePeriod)**: Policy in report-only when should be enforced
  - **2 (Warning)**: Session frequency loosened, new exclusions added
  - **1 (Passed)**: No drift detected
- Zone-based severity escalation: Zone 3 violations escalate by +1 severity
- Returns array of drift objects: `@{ PolicyName; DriftType; Dimension; Expected; Actual; Severity; Zone; Description }`
- Full help comments

**Acceptance:** Correctly identifies all 5 drift dimensions; severity classifications match ACV canonical; zone escalation works; no false positives on unchanged policies.

### Task 3: Baseline Export Script

- Full help comments with examples

**Acceptance:** Produces valid JSON baseline file; metadata includes all fields; -WhatIf previews without query; summary output is informative.

### Task 4: Drift Detection Orchestrator

**Create** `scripts/Watch-PolicyDrift.ps1`

Main drift monitoring orchestrator:
- `[CmdletBinding(SupportsShouldProcess)]`
- Parameters: `-TenantId` (M), `-BaselinePath` (M), `-ConfigPath` (O), `-OutputPath` (O), `-OutputFormat Table|JSON|Object`, `-SeverityThreshold` (default: Warning)
- Workflow:
  1. Load baseline from `-BaselinePath`
  2. Query current CA policy state via `Get-CAAPolicyBaseline`
  3. Compare via `Compare-CAAPolicyBaseline`
  4. Filter by `-SeverityThreshold`
  5. Output results in requested format
  6. If `-OutputPath` specified, write JSON report
- Summary output:
  ```
  ╔══════════════════════════════════════════════════════╗
  ║  CA Policy Drift Detection Results                  ║
  ╠══════════════════════════════════════════════════════╣
  ║  Policies Checked:  8                               ║
  ║  Drift Detected:    2                               ║
  ║  Critical:          1  (Zone 3 policy disabled)     ║
  ║  Warning:           1  (Session timeout changed)    ║
  ║  Passed:            6                               ║
  ╚══════════════════════════════════════════════════════╝
  ```
- Exit codes: 0 = no drift, 1 = drift detected (enables CI/CD integration)
- `-WhatIf` shows what would be checked without querying
- Full help comments with workflow examples

**Acceptance:** Detects drift against baseline; severity filtering works; output formats correct; exit codes set properly; summary banner displays correctly.
