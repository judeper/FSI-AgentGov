# Plan 01-02: Template Validation and Script Refactoring with Dry-Run

## Goal

Validate all 8 CA policy templates against the Graph API v1.0 schema, fix the M365 Copilot hardcoded ID inconsistency, and refactor the 3 existing scripts to use the private helpers from Plan 01, add `SupportsShouldProcess` for dry-run, and integrate zone lookup. After this plan, all scripts follow Tier 2 conventions and templates are verified current.

## Must-Haves Covered

- **Must-Have 2**: All 8 templates validated against Graph API schema
- **Must-Have 4**: SupportsShouldProcess / -WhatIf on all deployment and compliance operations

## Tasks

### Task 1: Policy Template Validation

**Validate** all 8 templates in `templates/` against Graph API v1.0 `conditionalAccessPolicy` resource schema.

Checks per template:
1. All required properties present (`displayName`, `state`, `conditions`, `grantControls`)
2. All property values use valid Graph API enums (`state` values, `operator` values, `builtInControls` values, `clientAppTypes`)
3. Placeholder tokens follow consistent format (`<placeholder-name>`)
4. No deprecated properties used

**Fix** M365 Copilot hardcoded ID inconsistency:
- `CA-M365Copilot-AllZones.json`: Replace hardcoded `fb8d773d-7ef8-4ec0-a117-179f88add510` with `<m365-copilot-app-id>` placeholder
- `CA-BlockLegacyAuth-AI.json`: Same replacement
- Document well-known ID in config sample as `applications.m365Copilot` default value

**Add** schema version metadata to each template:
```json
{
  "_metadata": {
    "schemaVersion": "v1.0",
    "lastValidated": "2026-02-10",
    "targetControl": "1.11"
  }
}
```

**Acceptance:** All 8 templates pass schema validation; no hardcoded app IDs remain; metadata added to all templates.

### Task 2: Refactor Deploy-CAPolicies.ps1

**Modify** `scripts/Deploy-CAPolicies.ps1`:

1. Add `[CmdletBinding(SupportsShouldProcess, ConfirmImpact = 'High')]`
2. Replace custom `-DryRun` with `SupportsShouldProcess` `-WhatIf`:
   - Keep `-DryRun` as deprecated alias to maintain backward compatibility
   - Map `-DryRun` to `$WhatIfPreference = $true` at function entry
3. Add `#Requires -Modules @{ ModuleName = 'Microsoft.Graph.Identity.SignIns'; ModuleVersion = '2.0.0' }`
4. Import private helpers: `. $PSScriptRoot/private/Connect-GraphSession.ps1`, etc.
5. Replace `Write-Host` with `Write-Verbose` for operational messages (keep `Write-Host` for banner/summary only)
6. Integrate zone lookup: when `-Zone` parameter provided, auto-select template set
7. Add comprehensive help comments (`.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`, `.OUTPUTS`, `.NOTES`)
8. Use `$PSCmdlet.ShouldProcess("Policy: $policyName", "Deploy to tenant $TenantId")` before Graph API calls

**Acceptance:** `-WhatIf` previews all policy deployments without Graph calls; `-DryRun` still works as alias; zone parameter auto-selects templates; verbose output provides operational detail.

### Task 3: Refactor Register-ServicePrincipal.ps1

**Modify** `scripts/Register-ServicePrincipal.ps1`:

1. Add `[CmdletBinding(SupportsShouldProcess, ConfirmImpact = 'High')]`
2. Replace `Read-Host` confirmation with `$PSCmdlet.ShouldContinue()` (pipeline-safe)
3. Replace custom `-DryRun` with `SupportsShouldProcess` `-WhatIf`
4. Import `Connect-GraphSession.ps1` for consistent auth
5. Replace `Write-Host` with `Write-Verbose` for operational messages
6. Add comprehensive help comments
7. Document required Graph API permissions inline (replace hardcoded permission GUIDs with comments)

**Acceptance:** `-WhatIf` previews service principal creation without Graph calls; no interactive `Read-Host` calls; permission GUIDs are documented inline.

### Task 4: Refactor Test-PolicyCompliance.ps1

**Modify** `scripts/Test-PolicyCompliance.ps1`:

1. Add `[CmdletBinding(SupportsShouldProcess)]`
2. Add `-WhatIf` support: preview which policies would be checked without querying Graph
3. Modularize compliance checks into callable sections:
   - Policy existence check
   - Policy state check (enabled vs report-only vs disabled)
   - Break-glass exclusion verification
   - MFA/grant controls validation
   - **New:** Session controls validation (signInFrequency, persistentBrowser)
4. Add `-OutputFormat Table|JSON|Object` parameter (AAM pattern)
5. Import private helpers (zone lookup, parameter validation)
6. Replace `Write-Host` with `Write-Verbose` for operational messages
7. Add zone-aware compliance criteria: check policies match zone requirements
8. Add comprehensive help comments

**Acceptance:** Compliance check runs in all 3 output formats; session controls validated; zone-specific criteria applied; `-WhatIf` previews check targets without querying.
