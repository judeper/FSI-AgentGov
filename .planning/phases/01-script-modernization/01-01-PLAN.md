# Plan 01-01: Solution Scaffold, Module Manifest, and Private Helpers

## Goal

Create the CAAClient module foundation — manifest, private helper scripts, zone lookup integration, and parameter validation — following the proven AAM Tier 2 module pattern. After this plan, the module structure is in place for script refactoring (Plan 02) and drift detection (Plan 03) to build on.

## Must-Haves Covered

- **Must-Have 1** (partial): Module manifest with FunctionsToExport, RequiredModules, CompatiblePSEditions
- **Must-Have 3**: Zone lookup adapted from AAM Get-ZoneClassification.ps1

## Tasks

### Task 1: Module Manifest

**Create** `scripts/conditional-access-automation.psd1`

- `ModuleVersion = '1.0.0'`
- `CompatiblePSEditions = @('Core')`
- `PowerShellVersion = '7.0'`
- `RequiredModules`: `Microsoft.Graph.Identity.SignIns` (≥2.0.0), `Microsoft.Graph.Applications` (≥2.0.0)
- `FunctionsToExport`: `Deploy-CAPolicies`, `Test-PolicyCompliance`, `Register-ServicePrincipal`
- `Description`: FSI Agent Governance — Conditional Access Automation for Controls 1.11, 1.23, 1.18
- `Tags`: ConditionalAccess, Governance, FSI, MFA, ZeroTrust

**Acceptance:** Module manifest loads without error via `Test-ModuleManifest`.

### Task 2: Private Directory and Connect-GraphSession

**Create** `scripts/private/Connect-GraphSession.ps1`

Adapt from SSC pattern:
- `Connect-CAAGraphSession` function with `-TenantId` and `-Scopes` parameters
- Default scopes: `Policy.Read.All`, `Policy.ReadWrite.ConditionalAccess`, `Application.Read.All`
- `SupportsShouldProcess` — WhatIf shows which scopes would be requested
- `Write-Verbose` logging for auth flow
- Full help comments (`.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`)

**Acceptance:** Function connects to Graph with required scopes; `-WhatIf` previews without connecting.

### Task 3: Zone Lookup Integration

**Create** `scripts/private/Get-ZoneClassification.ps1`

Adapt from AAM `Get-ZoneClassification.ps1`:
- `Get-CAAZoneClassification` function
- **Primary**: ELM Dataverse lookup on `fsi_environments` table by environment GUID → `fsi_zone_classification` option set
- **Fallback**: Naming convention pattern matching (zone3: `-z3-`, `-zone3-`, `-prod-`, `-enterprise-`; zone2: `-z2-`, `-zone2-`, `-team-`, `-collab-`; zone1: `-z1-`, `-zone1-`, `-personal-`, `-dev-`)
- **CA-specific adaptation**: Given zone classification, resolve security group ID from config for CA policy targeting
- Returns `@{ Zone = 'Zone1|Zone2|Zone3|Unknown'; GroupId = '<group-id-or-null>' }`
- `-DataverseUrl` optional parameter (when omitted, naming convention only)
- Full help comments

**Acceptance:** ELM lookup returns zone + group mapping; naming convention correctly classifies known patterns; unknown environments return `'Unknown'`.

### Task 4: Parameter Validation Helpers

**Create** `scripts/private/Test-ParameterValidation.ps1`

Adapt from AAM `Test-ParameterValidation.ps1`:
- `Test-CAAConfigPath` — validates config JSON exists and has required keys (`tenantId`, `groups`, `breakGlassAccounts`, `applications`)
- `Test-CAATemplateSet` — validates template set name matches available templates
- `Test-CAABreakGlassAccounts` — validates break-glass account IDs are valid GUIDs
- `Test-CAAGraphConnection` — verifies active Graph session with required scopes
- All functions return `$true` or throw with descriptive error message
- Full help comments

**Acceptance:** Validation functions correctly reject invalid input with clear error messages; valid input passes silently.

### Task 5: CAAClient Module Shell

**Create** `scripts/private/CAAClient.psm1`

Shell for Phase 2 Dataverse integration (mirrors AAM pattern):
- Module-scoped variables: `$script:DataverseUrl`, `$script:AccessToken`, `$script:Headers`
- Exported function stubs with `throw "Not implemented — requires Phase 2 Dataverse infrastructure"`:
  - `Connect-CAADataverse`
  - `Get-CAAConnection`
  - `Get-CAAEnvironmentVariable`
  - `Get-CAAActiveBaseline`
  - `Write-CAAValidationHistory`
  - `Write-CAAViolation`
  - `Save-CAABaseline`
  - `Get-CAALastValidation`
- Full help comments on each stub documenting expected behavior

**Acceptance:** Module imports without error; stub functions throw with clear Phase 2 message.
