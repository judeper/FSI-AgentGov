<task type="auto">
  <name>Task 1: Structural and formatting audit of Pillar 1 controls and playbooks</name>
  <files>.planning/phases/02-documentation-audit-foundation/AUDIT-PILLAR-1.md</files>
  <action>
Audit all 24 Pillar 1 controls (docs/controls/pillar-1-security/1.1-*.md through 1.24-*.md) and their 96 playbooks (docs/playbooks/control-implementations/1.1/ through 1.24/) for structural and formatting issues.

**Step 1 — Run structural validation:**
Run `python scripts/verify_controls.py` and capture output. Record any Pillar 1 failures.

**Step 2 — Check 10-section template compliance for each control:**
Read each control file. Verify all 10 required sections exist in correct order:
1. Objective
2. Why This Matters for FSI
3. Control Description
4. Key Configuration Points
5. Zone-Specific Requirements
6. Roles & Responsibilities
7. Related Controls
8. Implementation Guides
9. Verification Criteria
10. Additional Resources

Also verify: header metadata block (Control ID, Pillar, Regulatory Reference, Last UI Verified, Governance Levels) and footer metadata (*Updated: January 2026 | Version: v1.2 | UI Verification Status: Current*).

**Step 3 — Check formatting consistency:**
Use grep to scan all Pillar 1 controls for:
- Admonition usage patterns (grep for "^!!!" — identify types used)
- Blockquote usage (grep for "^>" — identify if used for playbook links vs content that should be admonitions)
- Table formatting (Zone-Specific: 3-column, Roles: 2-column, Related Controls: 2-column)
- Code block language identifiers (powershell, kusto, bash)
- Link patterns (internal control links, playbook links, external Microsoft Learn links)

Standard formatting (derived from best-formatted controls 2.1, 3.1, 1.1):
- `!!! warning` for licensing requirements, deadlines, breaking changes
- `!!! info` for preview features, context clarifications
- `!!! tip` for advanced implementations, deployable solutions
- `!!! danger` for critical action-required items
- `!!! note` for verification scope, terminology clarifications
- Blockquotes ONLY for extended quotations or the Implementation Guides section playbook link block
- Internal control links: `[X.X - Name](../pillar-N/file.md)`
- Playbook links: `[Portal Walkthrough](../../playbooks/control-implementations/X.X/portal-walkthrough.md)`

**Step 4 — Scan all 96 Pillar 1 playbooks:**
For each control's 4 playbooks (portal-walkthrough.md, powershell-setup.md, verification-testing.md, troubleshooting.md):
- Verify file exists and is non-empty
- Check for consistent heading structure
- Verify PowerShell cmdlets are not using deprecated modules (AzureAD vs Microsoft.Graph, etc.)
- Check that portal navigation paths reference current admin center names
- Flag any playbooks using deprecated x-api-key patterns (may already have been fixed in Phase 1)

**Step 5 — Begin writing AUDIT-PILLAR-1.md:**
Start the audit report with structural and formatting findings. Use the report structure from RESEARCH.md Pattern 1. Classify each finding as Critical/Moderate/Minor.

<task type="auto">
  <name>Task 2: Content accuracy and citation audit of Pillar 1 controls</name>
  <files>.planning/phases/02-documentation-audit-foundation/AUDIT-PILLAR-1.md</files>
  <action>
Continue the Pillar 1 audit by verifying content accuracy against Microsoft Learn documentation and regulatory citations.

**Step 1 — Microsoft Learn URL verification:**
Read `data/learn-monitor-state.json`. For each Pillar 1 control:
- Extract all Microsoft Learn URLs from the control
- Check if each URL exists in learn-monitor-state.json (flag unmonitored URLs)
- Note any URLs where learn_monitor detected recent changes
- For controls referencing features as "current" or "GA", verify this matches Learn documentation status
- Use WebFetch on 3-5 critical Learn URLs per control batch to spot-check content alignment (prioritize controls with security-critical content: 1.1, 1.5, 1.6, 1.8, 1.11, 1.24)

**Step 2 — Regulatory citation verification:**
For each Pillar 1 control, extract regulatory citations using grep pattern:
`(FINRA [0-9]{4}|SEC [0-9]{2}a-[0-9]|SOX [0-9]{3}|GLBA [0-9]{3}|OCC [0-9]{4}-[0-9]{2}|SR [0-9]{2}-[0-9]|CFTC [0-9]\.[0-9]{2})`

Verify:
- Citations include specific subsections (not just "FINRA 4511" but "FINRA 4511(a)")
- Retention periods cited match actual regulation (3-year vs 6-year)
- Rule vs guidance distinction (FINRA 3110 is binding rule; FINRA Notice 24-09 is guidance)
- SOX citations reference appropriate sections (302 for officer certification, 404 for internal controls)
- Cross-check against docs/reference/regulatory-mappings.md for consistency

**Step 3 — Role naming verification:**
Check that all controls use canonical role names from docs/reference/role-catalog.md:
- "Entra Global Admin" not "Global Administrator"
- "Purview Compliance Admin" not "Compliance Administrator"
- "Power Platform Admin" not "Power Apps Admin"
- "Exchange Online Admin" not "Exchange Administrator"

**Step 4 — Language compliance:**
Grep for prohibited language patterns per CONTRIBUTING.md:
- "ensures compliance" (should be "supports compliance with")
- "guarantees" (should be "helps meet")
- "will prevent" (should be "helps prevent")
- "eliminates risk" (should be "reduces risk")

**Step 5 — Complete AUDIT-PILLAR-1.md:**
Add content accuracy and citation findings to the audit report. Include:
- Summary table with severity counts
- Verification notes (URLs checked, Learn Monitor run date, template compliance status)
- Each finding with: Issue, Evidence (URL/regulation text), Current Doc Says, Should Say, Affected Files
