    **docs/pii-sanitization-guide.md** — PII decision framework for Copilot Studio telemetry (TELE-05):

    Structure:
    1. Title + overview: Why PII in telemetry matters for FSI (GLBA 501(b), state privacy laws)
    2. Decision Framework — 4-step flowchart in text:
       - Step 1: Does field contain customer-identifiable data? → If no, retain
       - Step 2: Is field needed for analytics/troubleshooting? → If no, drop
       - Step 3: Is reversibility required for compliance audit? → If yes, encrypt (with key management)
       - Step 4: Default action → Hash (one-way, preserves cardinality for analytics)
    3. Field-Level Recommendations — Table from research:
       | Field | Contains PII? | Recommendation | Rationale |
       | customDimensions.text | YES | Drop or hash | Customer prompts contain names, accounts, SSNs |
       | customDimensions.speak | YES | Drop or hash | Speech output may contain PII |
       | customDimensions.fromName | YES | Hash (one-way) | User identity not needed for analytics |
       | customDimensions.recipientName | YES | Hash (one-way) | Agent identity sufficient |
       | customDimensions.channelId | NO | Retain | Channel type is not PII |
       | customDimensions.locale | NO | Retain | Language preference is not PII |
       | customDimensions.designMode | NO | Retain | Test vs production flag |
       | customDimensions.TopicName | NO | Retain | Intent classification, no PII |
    4. Implementation Options — Brief guidance on each approach:
       - **Drop**: Disable "Log sensitive Activity properties" in Copilot Studio (recommended default)
       - **Hash**: Application Insights telemetry processor (not available for Copilot Studio server-side; requires post-ingestion KQL transformation or Logic App preprocessing)
       - **Encrypt**: Azure Key Vault integration for reversible encryption (complex, Phase 2+ consideration)
    5. Default Recommendation: Disable sensitive logging in Copilot Studio. If sensitive logging required, use post-ingestion transformation in Phase 2.

    3. Sampling Configuration — Explain ingestion sampling at workspace level:

    4. Cost Alert Thresholds — Recommended Azure Monitor cost alerts:

    5. Data Retention Cost Optimization:
       - Hot tier (Log Analytics interactive): 730 days for real-time queries
       - Archive tier (ADLS Gen2): Lower cost per GB for long-term SEC 17a-4 retention
       - Basic Logs option: Lower ingestion cost for high-volume tables (reduced query capability)
