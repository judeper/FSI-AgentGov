# Phase 2 Plan 01: Detection Core — BAP API Integration & Zone Evaluation

## Goal

Create the core detection engine that enumerates all Copilot Studio agents across Power Platform environments via BAP Admin APIs, retrieves sharing configuration per agent, and evaluates compliance against zone-specific sharing rules using `asard_zone_rules.check_agent_compliance()` from Phase 1.

This plan delivers **DET-01** (agent sharing detection script) and **DET-02** (zone-based sharing evaluation) from ROADMAP.md.

## Tasks

### Task 1: Create BAP API Client Module
**Acceptance criteria:**
- [ ] Module location: `scripts/bap_admin_client.py`
- [ ] `BAPAdminClient` class with MSAL authentication:
  - Constructor parameters: `tenant_id`, `client_id`, `client_secret` (optional for interactive auth)
  - Token acquisition for `https://api.bap.microsoft.com/.default` scope
  - Supports both interactive (PublicClientApplication) and service principal (ConfidentialClientApplication) flows
  - Follows `caa_client.py` pattern (environment variables: `BAP_TENANT_ID`, `BAP_CLIENT_ID`, `BAP_CLIENT_SECRET`)
- [ ] HTTP session with retry strategy (reuse `urllib3.Retry` pattern from `caa_client.py`):
  - 3 retries, exponential backoff (backoff_factor=1)
  - Status codes: 429, 500, 502, 503, 504
  - Allowed methods: GET (read-only API client)
- [ ] Core methods:
  - `list_environments() -> List[Dict]` — GET `/scopes/admin/environments?api-version=2016-11-01`
  - `list_agents(environment_id: str) -> List[Dict]` — GET `/scopes/admin/environments/{envId}/bots?api-version=2021-04-01`
  - `get_agent_permissions(environment_id: str, agent_id: str) -> List[Dict]` — GET `/scopes/admin/environments/{envId}/bots/{botId}/permissions?api-version=2021-04-01`
  - `test_connection() -> bool` — validate token and API access
- [ ] Error handling: Log API failures with environment/agent context, return empty list on failure (graceful degradation per environment)
- [ ] Docstring with usage example

**Files:**
- `scripts/bap_admin_client.py` — Create: BAP Admin API client module with MSAL auth and retry strategy

## Notes

- This plan creates the **detection workflow** — enumeration, evaluation, result collection
- **No Dataverse writes** in this plan — deferred to Plan 02-02 (Output & Persistence)
- **No console output formatting** in this plan — deferred to Plan 02-02
- **No CSV export** in this plan — deferred to Plan 02-02
- BAP Admin API requires **Power Platform Administrator** role (enforced by API, not script)
- Interactive auth uses device code flow (user-friendly for lab environments)
- Service principal auth requires app registration with `Power.Admin` delegated or application permission
- Zone 3 approved group validation is **warning-only** (empty policy table doesn't block scan)
- `--environment-filter` enables targeted scans for large tenants (e.g., `--environment-filter "Prod.*"`)
