# Phase 2 Plan 02: Output & Persistence — Dataverse, Console, CSV, Teams Notifications

## Goal

Persist detection results to Dataverse, format console output with per-agent compliance status and summary statistics, export results to CSV for audit trails, and provide optional Teams adaptive card notifications following the UASD pattern.

This plan delivers **DET-03** (detection output) from ROADMAP.md and completes Phase 2.

## Tasks

### Task 1: Implement Dataverse Upsert for Compliance Records
**Acceptance criteria:**
- [ ] Function: `upsert_compliance_record(caa_client: CAAClient, record: Dict) -> str`
- [ ] Uses alternate key for upsert: `fsi_agentsharingcompliance_agentkey` on (`fsi_agent_id`, `fsi_environment_id`)
- [ ] HTTP method: `PATCH` to `/fsi_agentsharingcompliances(fsi_agent_id='...',fsi_environment_id='...')`
- [ ] Record fields:
  - `fsi_agent_id` (str, required)
  - `fsi_agent_name` (str, required)
  - `fsi_environment_id` (str, required)
  - `fsi_environment_name` (str)
  - `fsi_sharing_principals_json` (str, JSON serialized)
  - `fsi_violation_type` (int, option set value: 0=Everyone, 1=Public, 2=UnapprovedGroup, 3=ExcessiveIndividual, 4=CrossTenant, or `None` if compliant)
  - `fsi_zone` (int, option set value from zone classification)
  - `fsi_compliance_status` (int, option set value: 0=Compliant, 1=NonCompliant, 2=Exception, 3=Error, required)
  - `fsi_last_checked` (str, ISO 8601 datetime, required)
  - `fsi_remediation_date` (str, ISO 8601 datetime, `None` if not remediated)
  - `fsi_scan_run_id` (str, scan run GUID)
  - `fsi_evidence_hash` (str, SHA-256 hash)
- [ ] Violation type mapping (from `asard_zone_rules.py` violation_type string to option set int):
  - "Everyone" → 0
  - "Public" → 1
  - "UnapprovedGroup" → 2
  - "ExcessiveIndividual" → 3
  - "CrossTenant" → 4
  - `None` (compliant) → `None`
- [ ] Compliance status mapping (from result dict to option set int):
  - `compliant=True` → 0 (Compliant)
  - `compliant=False` → 1 (NonCompliant)
  - `compliance_status="Error"` → 3 (Error)
  - Exception handling (Phase 4) → 2 (Exception)
- [ ] Response handling:
  - HTTP 204 No Content → existing record updated
  - HTTP 201 Created → new record created via upsert
  - HTTP 4xx/5xx → log error, raise exception (will be caught by caller)
- [ ] Retry strategy: Reuses `caa_client._session` with built-in retry (3 retries, exponential backoff)
- [ ] Error handling: If upsert fails, log error with agent_id/environment_id context, increment error counter, continue to next record (don't fail entire batch)

## Notes

- This plan completes **Phase 2 (Detection & Scanning)**
- Dataverse upsert is **idempotent** — same agent_id + environment_id updates existing record
- CSV export provides **audit trail** for remediation planning and compliance reporting
- Teams notification is **optional** (triggered by `--teams-webhook-url` CLI arg)
- Adaptive card template uses **placeholder syntax** (double-braces) for variable substitution
- Console output uses **ANSI codes** for color (optional, degrade gracefully if unsupported)
- CSV export **does NOT truncate** sharing_principals_json in this plan (1MB limit handling deferred to Phase 5 if needed)
- **No email notifications** in Phase 2 (deferred to Phase 5 deployment/configuration as optional enhancement)
- Phase 3 (Enforcement & Remediation) will query `fsi_agentsharingcompliances` for non-compliant agents (fsi_compliance_status=1)
- CSV evidence_hash provides **tamper detection** (compare hash on read with current agent permissions)
