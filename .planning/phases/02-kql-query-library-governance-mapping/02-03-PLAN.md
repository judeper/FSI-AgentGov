**SR 11-7 requires three monitoring components:**
1. Outcome Analysis - Comparing model outputs to actual outcomes
2. Performance Monitoring (Drift Detection) - Tracking accuracy/error rates over time
3. Process Verification - Confirming model operates as intended

**1. output-monitoring.kql** (GOV-02)

**Header block requirements:**
- Purpose: SR 11-7 outcome analysis - track agent recommendation distribution and quality metrics over time
- Parameters: {TimeRange:30d}
- Output Schema:
  - Date (datetime) - Aggregation date
  - AgentId (string) - Agent identifier
  - Topic (string) - Topic/intent category
  - TotalRecommendations (int) - Count of recommendations
  - AvgConfidence (real) - Average confidence score (if available)
  - DistinctUsers (int) - Unique users receiving recommendations
- Supports:
  - Control 2.6 (Primary) - SR 11-7 Ongoing Monitoring
- Regulatory Mapping:
  - SR 11-7 Section III - "ongoing monitoring to confirm that models are performing as intended"
- Notes: Outcome correlation with customer actions requires integration with downstream CRM (documented as future enhancement)
- Sample Output (include example showing topic distribution)

**Query implementation:**
```kql
let TimeRange = {TimeRange:30d};

customEvents
| where timestamp > ago(TimeRange)
| where name == "BotMessageSend"
| extend AgentId = tostring(customDimensions["recipientId"])
| extend Topic = coalesce(tostring(customDimensions["TopicName"]), "Unknown")
| extend UserIdHashed = hash_sha256(tostring(customDimensions["fromName"]))
| summarize
    TotalRecommendations = count(),
    DistinctUsers = dcount(UserIdHashed)
    by bin(timestamp, 1d), AgentId, Topic
| project Date=timestamp, AgentId, Topic, TotalRecommendations, DistinctUsers
| order by Date desc, TotalRecommendations desc
```

**2. drift-detection-baseline.kql** (GOV-02)

**Header block requirements:**
- Purpose: SR 11-7 drift detection - identify response pattern changes exceeding threshold
- Parameters:
  - {BaselineDays:90} - Baseline period (90 days recommended)
  - {MonitoringDays:7} - Recent monitoring period
  - {DriftThreshold:20} - Percentage threshold for investigation
- Output Schema:
  - Topic (string) - Topic/intent category
  - BaselineCount (int) - Baseline period message count
  - CurrentCount (int) - Current period message count
  - DriftPercent (real) - Percentage change from baseline
  - DriftDirection (string) - INCREASE/DECREASE
  - InvestigationRequired (bool) - True if exceeds threshold
- Supports:
  - Control 2.6 (Primary) - SR 11-7 Model Recalibration Trigger
- Regulatory Mapping:
  - SR 11-7 Section III - "prompt investigation of anomalies"
- Notes: 20% drift threshold is configurable; higher-risk agents should use lower threshold
- Sample Output (include example showing topic with HIGH drift)

**Query implementation (from RESEARCH.md verified pattern):**
```kql
let BaselineDays = {BaselineDays:90};
let MonitoringDays = {MonitoringDays:7};
let DriftThreshold = {DriftThreshold:20};

let BaselineStart = ago(todatetime(BaselineDays) + todatetime(MonitoringDays));
let BaselineEnd = ago(todatetime(MonitoringDays));

let Baseline = customEvents
| where timestamp between (BaselineStart .. BaselineEnd)
| where name == "BotMessageSend"
| extend Topic = coalesce(tostring(customDimensions["TopicName"]), "Unknown")
| summarize BaselineCount = count() by Topic;

let Current = customEvents
| where timestamp > ago(todatetime(MonitoringDays))
| where name == "BotMessageSend"
| extend Topic = coalesce(tostring(customDimensions["TopicName"]), "Unknown")
| summarize CurrentCount = count() by Topic;

Baseline
| join kind=fullouter Current on Topic
| extend Topic = coalesce(Topic, Topic1)
| extend BaselineCount = coalesce(BaselineCount, 0)
| extend CurrentCount = coalesce(CurrentCount, 0)
| extend DriftPercent = iff(BaselineCount > 0, abs(todouble(CurrentCount - BaselineCount)) / BaselineCount * 100, 100.0)
| extend DriftDirection = iff(CurrentCount > BaselineCount, "INCREASE", "DECREASE")
| extend InvestigationRequired = DriftPercent > DriftThreshold
| project Topic, BaselineCount, CurrentCount, DriftPercent, DriftDirection, InvestigationRequired
| order by DriftPercent desc
```
