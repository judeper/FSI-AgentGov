**1. agent-usage-analytics.kql** (KQL-01)
- Purpose: Agent session and message volume trends over 30-day period
- Parameters: TimeRange (default 30d)
- Output: Timestamp, AgentId, SessionCount, MessageCount, CompletionRate
- Supports: 3.2 (Primary), 2.9 (Supporting)
- Use: bin(timestamp, 1d) for daily aggregation
- Filter: where name in ("BotMessageReceived", "BotMessageSend")
- Exclude design mode: where customDimensions['DesignMode'] == "False"

**2. user-engagement-metrics.kql**
- Purpose: Distinct users and repeat session metrics with PII-safe hashing
- Parameters: TimeRange (default 30d)
- Output: Timestamp, AgentId, DistinctUsers, TotalSessions, SessionsPerUser
- Supports: 3.2 (Primary)
- Use: hash_sha256(UserIdRaw) for persistent correlation
- Calculate: SessionsPerUser = TotalSessions / DistinctUsers

**3. error-categorization-by-type.kql** (KQL-02)
- Purpose: Categorize errors into connector/knowledge/orchestration buckets
- Parameters: TimeRange (default 7d)
- Output: ErrorCategory, ErrorCode, ErrorCount, Percentage
- Supports: 3.4 (Primary - Incident Reporting)
- Parse errorCodeText from customDimensions
- Categorize errors:
  - "Connector" if errorCode contains "connector" or "API"
  - "Knowledge" if errorCode contains "knowledge" or "search"
  - "Orchestration" for all others

**4. error-trend-analysis.kql**
- Purpose: Error rate trend over time for anomaly detection
- Parameters: TimeRange (default 7d)
- Output: Timestamp, ErrorCount, TotalMessages, ErrorRate
- Supports: 3.4 (Supporting)
- Calculate: ErrorRate = ErrorCount / TotalMessages
- Use: bin(timestamp, 1h) for hourly granularity

**5. latency-distribution.kql** (KQL-03)
- Purpose: P50/P95/P99 response time distribution
- Parameters: TimeRange (default 7d), AgentId (optional filter)
- Output: Timestamp, AgentId, P50, P95, P99, Count
- Supports: 2.9 (Primary - Performance Monitoring)
- Use: percentile(DurationMs, 50), percentile(DurationMs, 95), percentile(DurationMs, 99)
- Extract DurationMs from customDimensions["duration"]

**6. slow-query-detection.kql**
- Purpose: Identify responses exceeding latency threshold
- Parameters: TimeRange (default 7d), ThresholdMs (default 5000)
- Output: Timestamp, AgentId, SessionId, DurationMs, Topic
- Supports: 2.9 (Supporting)
- Filter: where DurationMs > ThresholdMs
- Order: by DurationMs desc

**Follow patterns exactly from RESEARCH.md:**
- Early filtering: where timestamp > ago(TimeRange) immediately after table
- Explicit binning: bin(timestamp, interval) required
- Standardized column names: Timestamp, AgentId, SessionId, MetricValue
