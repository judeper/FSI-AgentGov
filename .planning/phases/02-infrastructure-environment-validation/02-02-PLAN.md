**Write-ValidationResult.ps1:**
Helper function to write a single validation result record to fsi_auditvalidationhistory via Dataverse Web API.

Requirements:
- #Requires -Version 7.0
- Comment-based help
- Function Write-ValidationResult with parameters:
  - -DataverseUrl (mandatory, string)
  - -AccessToken (mandatory, string)
  - -RunId (mandatory, string — GUID linking all records in a run)
  - -Scope (mandatory, ValidateSet "Tenant", "Environment")
  - -Severity (mandatory, ValidateSet "Passed", "Warning", "GracePeriod", "Failed", "Error")
  - -ValidationType (mandatory, string — e.g., "UnifiedAuditLog", "EnvironmentAudit")
  - -RawValue (mandatory, string — actual config values checked)
  - -Reason (mandatory, string — human-readable explanation)
  - -Zone (optional, ValidateSet "Unclassified", "Zone1", "Zone2", "Zone3")
  - -EnvironmentId (optional, string)
  - -EnvironmentName (optional, string)
  - -RemediationHint (optional, string)
  - -CheckCount (optional, int)
- Map string parameters to option set integer values:
  - Scope: Tenant=100000000, Environment=100000001
  - Severity: Passed=1, Warning=2, GracePeriod=3, Failed=4, Error=5
  - Zone: Unclassified=0, Zone1=1, Zone2=2, Zone3=3
- Build JSON body with fsi_ prefixed field names
- fsi_name = "TENANT-{timestamp}" for tenant scope, "ENV-{EnvironmentName}-{timestamp}" for environment scope
- fsi_timestamp = current UTC ISO 8601 datetime

- Headers: Authorization Bearer, Content-Type application/json, OData-MaxVersion 4.0, OData-Version 4.0
- Return the created record ID on success, throw on failure with detailed error (status code, response body)
- This function only creates records (append-only) — no update or delete operations

**Invoke-EnvironmentDiscovery.ps1 (EVAL-04):**
Main environment discovery script that enumerates Power Platform environments, syncs to Dataverse registry, and returns the set of environments to validate.

Requirements:
- #Requires -Version 7.0
- #Requires -Modules @{ModuleName="Microsoft.PowerApps.Administration.PowerShell"; ModuleVersion="2.0"}
- Comment-based help with examples
- Dot-source Connect-PowerPlatform.ps1 from private/ directory
- Parameters:
  - -TenantId (mandatory)
  - -DataverseUrl (mandatory)
  - -ClientId (optional), -ClientSecret (optional SecureString), -CertificateThumbprint (optional), -Interactive (switch)
  - -IncludeTrialDev (switch) — override to include Trial/Developer environments globally
  - -OutputPath (optional) — write discovery results JSON to file

**Discovery flow (3 phases):**

Phase A: Enumerate environments
- Call Get-AdminPowerAppEnvironment to get all environments
- For each environment, extract: EnvironmentName (GUID), DisplayName, EnvironmentType (Production, Sandbox, Developer, Trial, Default), LinkedEnvironmentMetadata.InstanceUrl
- NOTE: This cmdlet requires Power Platform Administrator or Global Administrator role (document in comment per Pitfall 4 from research)

Phase B: Sync to Dataverse registry
- For each discovered environment:
  1. Query fsi_environmentregistries?$filter=fsi_environmentid eq '{envId}' to check if registered
  2. If NOT registered (new environment):
     - POST new record with fsi_zone=0 (Unclassified), fsi_status=1 (Active), fsi_discoveredon=now, fsi_overrideinclude=false
     - Add to $newEnvironments list for alerting
     - Write-Warning "New environment discovered: {DisplayName} - requires zone classification"
  3. If registered but status changed (e.g., environment type changed):
     - PATCH to update fsi_environmenttype
- Query all registered environments to check for deprovisioned ones:
  - If a registered Active environment is NOT in the API discovery results, PATCH fsi_status=2 (Inactive)
  - DO NOT delete the registry record (history preservation per user decision)
  - Write-Warning "Environment {name} no longer found - marked Inactive"

Phase C: Filter and return validation set
- Start with all Active registry entries
- Exclude environments where:
  - fsi_environmenttype is Trial(4) or Developer(3) AND fsi_overrideinclude is false
  - UNLESS -IncludeTrialDev switch is set (include all types)
- Exclude environments where fsi_zone is Unclassified(0) — these need admin zone assignment first
  - Write-Warning "Skipping {name}: zone is Unclassified. Assign zone before validation."
- Return array of hashtables with: EnvironmentId, DisplayName, Zone (int), EnvironmentUrl, EnvironmentType

**Output object:**
Return PSCustomObject with:
- Timestamp (UTC ISO 8601)
- TotalDiscovered (count from API)
- NewEnvironments (array of names)
- InactivatedEnvironments (array of names)
- SkippedUnclassified (array of names)
- SkippedTrialDev (array of names)
- ValidationSet (array of environment hashtables to validate)

If -OutputPath provided, export full result as JSON.

Use regulatory-safe language in all comments and Write-Warning messages. No "ensures", "guarantees", "will prevent".
