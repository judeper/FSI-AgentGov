# Plan 01-01: Application Insights Telemetry Schema Documentation

**Phase:** 1 — Telemetry Research & KQL Query Library
**Requirement:** TEL-01
**Wave:** 1 (no dependencies)

## Objective

Create a comprehensive Application Insights telemetry schema reference document for Copilot Studio, documenting all event types, customDimensions properties, channel identifiers, session tracking, and telemetry prerequisites. This document is the foundation that all KQL queries and workbook visualizations build upon.

## Must-Haves Addressed

- **MH-1:** Application Insights telemetry schema reference document — customEvents event types, customDimensions properties, channel identifiers, session_Id
- **MH-5:** Schema validation baseline for query verification (provides the reference schema that queries are validated against)

## Context

Prior v13 research (`.planning/phases/01-workbook-template-kql/01-RESEARCH.md`, Sections 4.1–4.7) provides the validated schema. This plan transforms that research into a publishable reference document with proper FSI framework formatting.

## Tasks

### Task 1: Create Telemetry Schema Reference Document

**File:** `docs/playbooks/advanced-implementations/agent-usage-workbook/telemetry-schema.md`
**Action:** Create

Write a structured reference document covering:

1. **Header:** Title, breadcrumb, scope statement
2. **Overview:** What Application Insights telemetry Copilot Studio emits, why it matters for FSI governance
3. **Tables Overview:** Which Application Insights tables receive Copilot Studio data (customEvents, exceptions, dependencies, pageViews) and which do NOT (traces, requests)
4. **customEvents Schema:**
   - Event types table: BotMessageReceived, BotMessageSend, TopicStart, TopicEnd, Action, GenerativeAnswers — with descriptions and when fired
   - customDimensions properties table: type, channelId, fromId, fromName, recipientId, recipientName, text, designMode, TopicName, Kind, locale, session_Id — with data types, descriptions, always-present flag
5. **Channel Identifiers:** msteams, directline, webchat, sharepoint, telephony — with FSI relevance notes
6. **Session and Conversation Tracking:** session_Id usage, conversation start/end inference, resolution inference, escalation inference, unique user counting
7. **Sensitive Properties:** Two-setting matrix (Log activities + Log sensitive activity properties + Allow conversation transcripts), what each enables, privacy implications for FSI
8. **Telemetry Limitations:** What is NOT available — token costs, CSAT, hallucination detection, grounding accuracy, RAI filter details, precise latency
9. **Prerequisites Checklist:** Required configuration for telemetry to flow (App Insights resource, connection string, log activities setting, tenant-level transcript setting)
10. **Regulatory Context:** How this telemetry supports FINRA 4511 (recordkeeping), SEC 17a-3/4 (record retention), SOX 404 (internal controls)

**Language rules:**
- Use hedged language per FSI framework standards
- Include implementation caveats
- Use canonical role names from role-catalog.md

**Source data:** `.planning/phases/01-workbook-template-kql/01-RESEARCH.md` Sections 4.1–4.7, 6.1–6.3
