# Plan 01-02: KQL Query Library for All Workbook Tabs

**Phase:** 1 — Telemetry Research & KQL Query Library
**Requirement:** TEL-02
**Wave:** 1 (no dependencies — parallel with Plan 01-01)

## Objective

Design and document the complete KQL query library powering all 3 workbook tabs (~23 parameterized queries). Queries are parameterized by time range, agent ID, and channel. Each query includes regulatory context comments, designMode filtering, and visualization type annotations. This library is the direct input for Phase 2 workbook JSON construction.

## Must-Haves Addressed

- **MH-2:** KQL query library: Usage/Business Value tab (~8 queries), parameterized
- **MH-3:** KQL query library: Performance/Errors tab (~8 queries), parameterized
- **MH-4:** KQL query library: Operational Health tab (~7 queries), parameterized
- **MH-5:** All queries validated against known schema (customEvents, dependencies, exceptions tables)

## Context

Prior v13 research (`.planning/phases/01-workbook-template-kql/01-RESEARCH.md`, Section 7) provides draft KQL patterns for key queries. This plan refines those drafts into a complete, validated query library with:
- Full parameterization for workbook integration
- Consistent designMode filtering
- Regulatory reference comments
- Visualization type annotations
- Schema validation against documented Copilot Studio telemetry

### Task 2: Schema Validation Checklist

**File:** `.planning/phases/01-telemetry-research-kql-design/schema-validation.md`

```markdown
| Query | Tables Used | Fields Referenced | Schema Valid | Notes |
|-------|-----------|-------------------|-------------|-------|
| Q01 | customEvents | timestamp, session_Id, designMode, recipientName, channelId | ✅ | — |
| Q02 | customEvents | timestamp, fromId, designMode, recipientName, channelId | ✅ | — |
| ... | ... | ... | ... | ... |
```

Validation criteria (from v13 research Section 8.3):
1. **Table validation** — All queries reference valid Application Insights tables
2. **Field validation** — All customDimensions.* fields match documented Copilot Studio schema
3. **Syntax validation** — KQL syntax is valid (proper pipe chains, function calls, operators)
4. **Parameter validation** — All {ParameterName} references match declared global parameters
5. **Visualization validation** — Visualization types match data shapes (timechart with time-binned data, piechart with categorical, etc.)
