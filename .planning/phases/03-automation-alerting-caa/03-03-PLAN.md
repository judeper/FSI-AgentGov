# Plan 03-03: Power Automate Daily Compliance Scan Flow

## Objective

Create a Power Automate flow definition (JSON) that runs daily, triggers CA policy compliance validation via Azure Automation, writes results to Dataverse immutable history, and routes severity-classified alerts to Teams and email.

## Requirements Covered

- **AUT-01**: Power Automate daily compliance scan flow executing Test-PolicyCompliance logic against all tracked environments and writing results to immutable validation history

## Must-Haves Covered

| # | Must-Have | How |
|---|----------|-----|
| 1 | Daily compliance scan flow with Azure Automation and Dataverse persistence | Flow triggers daily at 06:00 UTC, creates Azure Automation job running Start-CAAValidationRunbook, parses JSON output, writes validation history to Dataverse (audit-first), routes alerts via Teams adaptive card and email |

## Tasks

### Task 1: Create flow JSON scaffold
**File:** `src/caa-daily-compliance-flow.json`
- Follow CMM/FUS flow JSON structure (Logic App schema)
- Flow display name: `CAA - Daily Compliance Scan`
- Connection references:
  - `fsi_cr_dataverse_conditionalaccessautomation`
  - `fsi_cr_office365_conditionalaccessautomation`
  - `fsi_cr_teams_conditionalaccessautomation`

### Task 2: Configure trigger and variables
- Recurrence trigger: Daily at 06:00 UTC
- Initialize variables:
  - `DataverseUrl` (String) — Dataverse environment URL
  - `TenantId` (String) — Entra ID tenant
  - `ClientId` (String) — Registered service principal
  - `CertificateThumbprint` (String) — Certificate for Graph auth
  - `SubscriptionId` (String) — Azure subscription for Automation account
  - `ResourceGroup` (String) — Resource group containing Automation account
  - `AutomationAccount` (String) — Azure Automation account name
  - `TeamsGroupId` (String) — from `fsi_CAA_TeamsGroupId` env var
  - `TeamsChannelId` (String) — from `fsi_CAA_TeamsChannelId` env var
  - `ComplianceDistributionList` (String) — email DL for alert routing

### Task 3: Scope_Try — Azure Automation job execution
- **Create_Automation_Job**: `PUT /subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.Automation/automationAccounts/{account}/jobs/{jobId}`
  - Runbook name: `Start-CAAValidationRunbook`
  - Parameters: TenantId, ClientId, CertificateThumbprint, ConfigPath, DataverseUrl
- **Wait_Loop**: Do Until job status is `Completed`, `Failed`, or `Suspended`
  - Delay: 30 seconds per iteration
  - Timeout: 2 hours maximum
  - `GET /subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.Automation/automationAccounts/{account}/jobs/{jobId}`
- **Check_Job_Failure**: If status = `Failed` or `Suspended` → branch to CRITICAL alert
- **Get_Job_Output**: `GET .../jobs/{jobId}/output`

### Task 4: Parse Results
- Parse JSON action with schema matching runbook output (Plan 03-01, Task 5):
  - `CheckedAt`, `TenantId`, `TotalPolicies`, `PassedCount`, `FailedCount`
  - `WarningCount`, `DriftCount`, `OverallSeverity`, `OverallStatus`
  - `ComplianceRate`, `AlertRequired`, `AlertSeverity`
  - `ZoneSummary[]`, `Violations[]`, `DriftItems[]`

### Task 5: Verify Dataverse validation history record
- **Note:** The runbook (Plan 03-01, Task 6) writes the `fsi_CAPolicyValidationHistory` record during execution (audit-first, crash-safe). The flow does NOT duplicate this write.
- Query `fsi_CAPolicyValidationHistory` to confirm the runbook's record was created:
  - Filter: `fsi_validation_time ge @{body('Parse_Results')?['CheckedAt']}`
  - If record missing (runbook crashed before write): create fallback record with parsed results
- Connection: `fsi_cr_dataverse_conditionalaccessautomation`

### Task 6: Alert routing — Teams adaptive card
- Condition: `AlertRequired` equals `true`
- Post adaptive card to Teams channel:
  - Group ID: `@{variables('TeamsGroupId')}`
  - Channel ID: `@{variables('TeamsChannelId')}`
  - Card body: `adaptive-card-caa-alert.json` template with variable substitution from parsed results
  - Connection: `fsi_cr_teams_conditionalaccessautomation`

### Task 7: Alert routing — Email
- Condition: `AlertRequired` equals `true`
- Send email via Office 365:
  - To: `@{variables('ComplianceDistributionList')}`
  - Subject: `[${AlertSeverity}] CA Policy Compliance Alert — ${OverallStatus}`
  - Body: HTML summary of violations, zone status, compliance rate
  - Connection: `fsi_cr_office365_conditionalaccessautomation`

### Task 8: Scope_Catch — Error handling
- Runs on `Scope_Try` failure
- Send CRITICAL error email:
  - Subject: `[CRITICAL] CAA Daily Compliance Scan — Flow Failure`
  - Body: Error details from failed actions
  - To: `@{variables('ComplianceDistributionList')}`
