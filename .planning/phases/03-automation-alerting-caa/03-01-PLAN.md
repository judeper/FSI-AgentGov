# Plan 03-01: Azure Automation Runbook Wrapper

## Objective

Create an Azure Automation runbook that wraps Test-PolicyCompliance.ps1 for unattended daily execution with certificate-based auth, Dataverse baseline integration, multi-dimensional drift detection, and structured JSON output compatible with the Power Automate flow's Parse_Results action.

## Requirements Covered

- **AUT-01** (partial): Runbook provides the execution engine for the daily compliance scan flow
- **AUT-02**: Drift detection comparing deployed CA policies against stored Dataverse baselines

## Must-Haves Covered

| # | Must-Have | How |
|---|----------|-----|
| 1 | Daily compliance scan execution engine | Runbook executes Test-PolicyCompliance logic with cert-based auth, outputs structured JSON for flow consumption |
| 2 | Multi-dimensional drift detection against Dataverse baselines | Reads active baselines via `Get-CAAActiveBaseline`, runs `Compare-CAAPolicyBaseline` across 5 dimensions, writes violations via `Write-CAAViolation` |

## Tasks

### Task 1: Create runbook script scaffold
**File:** `scripts/Start-CAAValidationRunbook.ps1`
- `#Requires -Version 7.0 -Modules Microsoft.Graph.Identity.SignIns`
- Certificate-based authentication (`Connect-MgGraph -CertificateThumbprint`)
- Parameters: `TenantId` (M), `ClientId` (M), `CertificateThumbprint` (M), `ConfigPath` (M), `DataverseUrl` (M), `Zone` (O, int — filter to single zone), `Scope` (O, string — `Full` [default] or `Targeted` for provisioning-triggered scans)
- When `-Zone` is provided, filter compliance checks to policies for that zone only
- When `-Scope Targeted`, reduce timeout expectations and tag validation history as provisioning-triggered
- Import CAAClient module via `Import-Module` using relative path
- Dot-source private helpers: `. "$PSScriptRoot/private/Compare-PolicyBaseline.ps1"`, `. "$PSScriptRoot/private/Get-PolicyBaseline.ps1"`
- Structured try/catch with JSON error output on failure

### Task 2: Connect to Dataverse and read operational parameters
- Call `Connect-CAADataverse` with MSAL certificate-based auth
- Read environment variables: `GracePeriodHours`, `BaselineMaxAgeDays`, `DriftSeverityEscalation`, `IncludeReportOnlyPolicies`
- Read `TeamsGroupId` and `TeamsChannelId` for alert routing metadata

### Task 3: Execute compliance checks
- Invoke `Test-PolicyCompliance` logic (6 checks):
  1. Policy existence check against expected templates
  2. Policy state check (enabled vs report-only vs disabled)
  3. Break-glass exclusion verification
  4. MFA/grant control verification
  5. Zone coverage completeness
  6. Drift analysis against Dataverse baselines
- Collect per-policy results with pass/fail/warning status

### Task 4: Drift detection against Dataverse baselines
- Dot-source `Compare-PolicyBaseline.ps1` from `private/` (provides `Compare-CAAPolicyBaseline`)
- Query `Get-CAAActiveBaseline` for all active policy baselines (or zone-filtered baselines when `-Zone` specified)
- For each deployed policy, run `Compare-CAAPolicyBaseline` across 5 dimensions:
  - State (enabled/disabled/reportOnly)
  - Conditions (users, applications, platforms, locations)
  - Grant controls (MFA, compliant device, block)
  - Session controls (sign-in frequency, persistent browser)
  - Additions/removals (new or deleted policies)
- Classify violations by type: `PolicyDisabled`, `ConditionWeakened`, `GrantControlRemoved`, `SessionControlWeakened`, `PolicyMissing`, `BreakGlassExclusionMissing`
- Apply zone severity escalation: Zone 3 violations +1 (capped at 5/Error=CRITICAL)
- Write each violation to Dataverse via `Write-CAAViolation`
