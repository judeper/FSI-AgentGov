# Plan 01-02: DECClient.psm1 Shared Module (AUTH-02)

## Goal

Create `DECClient.psm1` shared module following the established `AAMClient`/`CMMClient`/`FUSClient` pattern from v6-v8 solutions. The module provides centralized authentication helpers for three data sources (Purview Audit, Purview DLP, Application Insights), connection management with token caching and refresh, reusable extraction functions, and environment variable handling with `DEC_` prefix.

## Context

- **Pattern source:** v6 `AAMClient.psm1`, v7 `CMMClient.psm1`, v8 `FUSClient.psm1`
- **Unique challenge:** DEC connects to 3 services (ExchangeOnline, App Insights, Dataverse) vs. single-service v6-v8 clients
- **Depends on:** Plan 01-01 (Entra ID auth pattern for App Insights)
- **Phase 2 interface:** Module defines stubs for `Write-DECDenyEvent`, `Write-DECCorrelation`, `Write-DECValidationHistory` that Phase 2 implements
- **Env var prefix:** `DEC_` (e.g., `DEC_AppInsightsAppId`, `DEC_KeyVaultName`, `DEC_TenantId`)

## Tasks

### Task 1: Create Module Manifest and Structure

**What:** Set up DECClient.psm1 scaffold following Tier 2 solution directory pattern.

**Acceptance criteria:**
- [ ] Create `deny-event-correlation-report/scripts/private/DECClient.psm1`
- [ ] Define module-level variables: `$script:ExoConnection`, `$script:AiToken`, `$script:AiTokenExpiry`, `$script:DvConnection`
- [ ] Define exported functions list matching the module interface from research
- [ ] Reuse `Connect-EnvironmentDataverse.ps1` and `Get-ZoneClassification.ps1` patterns from v6-v8

### Task 2: Implement Connect-DECServices (Master Connection)

**What:** Single entry point that authenticates to all required services based on operation context.

**Acceptance criteria:**
- [ ] Accept parameters: `-TenantId`, `-ClientId`, `-KeyVaultName`, `-Services` (array: 'ExchangeOnline', 'AppInsights', 'Dataverse')
- [ ] Call service-specific connection functions based on `-Services` parameter
- [ ] Return `[PSCustomObject]@{ ExchangeOnline = $bool; AppInsights = $bool; Dataverse = $bool; Timestamp = ... }`
- [ ] Log connection status via `-Verbose`
- [ ] Support `-DryRun` to validate credentials without establishing connections

### Task 3: Implement Connect-DECExchangeOnline

**What:** ExchangeOnline connection for Purview Audit and DLP queries, with credentials from Key Vault.

**Acceptance criteria:**
- [ ] Retrieve ExchangeOnline credentials from Key Vault using service principal
- [ ] Call `Connect-ExchangeOnline` with certificate-based or app-only authentication
- [ ] Store connection state in `$script:ExoConnection`
- [ ] Support reconnection on token expiry
- [ ] Handle `Connect-ExchangeOnline` failures with structured error response

### Task 4: Implement Connect-DECAppInsights

**What:** Entra ID bearer token acquisition for App Insights REST API, inheriting pattern from Plan 01-01.

**Acceptance criteria:**
- [ ] Authenticate via `Connect-AzAccount -ServicePrincipal` (reuse logic from Plan 01-01)
- [ ] Obtain token via `Get-AzAccessToken -ResourceUrl "https://api.applicationinsights.io"`
- [ ] Cache token and expiry in `$script:AiToken`, `$script:AiTokenExpiry`
- [ ] Implement `Test-DECTokenValid` private function checking expiry with 5-minute buffer
- [ ] Auto-refresh token when expired before API calls

### Task 5: Implement Invoke-DECAppInsightsQuery

**What:** REST API wrapper for executing KQL queries against App Insights with bearer token auth.

**Acceptance criteria:**
- [ ] Accept parameters: `-AppInsightsAppId`, `-Query`, `-Timespan` (ISO 8601 duration)
- [ ] Check token validity; refresh if expired
- [ ] Execute `Invoke-RestMethod` against `https://api.applicationinsights.io/v1/apps/{appId}/query`
- [ ] Parse response `tables[0].rows` into PowerShell objects with column headers
- [ ] Implement retry logic (3 attempts, exponential backoff) for transient failures (429, 503)
- [ ] Return structured result: `[PSCustomObject]@{ Status; RowCount; Data; Query; Duration }`

### Task 6: Implement Get-DECEnvironmentVariable

**What:** Read `DEC_`-prefixed environment variables from Dataverse (or local fallback for testing).

**Acceptance criteria:**
- [ ] Define Dataverse query path for `environmentvariabledefinition` / `environmentvariablevalue` tables with `DEC_` prefix (**implementation deferred to Phase 2** when `Connect-DECDataverse` is functional)
- [ ] Implement local fallback as Phase 1 default: read from `$env:DEC_*` environment variables
- [ ] Cache values for session lifetime (avoid redundant queries)
- [ ] Return `[hashtable]` of key-value pairs
- [ ] Required variables: `DEC_AppInsightsAppId`, `DEC_KeyVaultName`, `DEC_TenantId`, `DEC_ClientId`

### Task 7: Define Phase 2 Stub Functions
