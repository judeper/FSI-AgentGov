# Plan 01-01: Entra ID Authentication Migration (AUTH-01)

## Goal

Migrate `Export-RaiTelemetry.ps1` from deprecated x-api-key authentication to Entra ID bearer token authentication using `Connect-AzAccount` + `Get-AzAccessToken`, before the March 31, 2026 deprecation deadline. Validate that all existing KQL queries work with the new authentication method.

## Context

- **Deadline:** x-api-key deprecated March 31, 2026 (~49 days)
- **Current auth:** `$headers = @{ "x-api-key" = $ApiKey }` → REST call to `api.applicationinsights.io`
- **Target auth:** Service principal with Monitoring Reader role, bearer token via `Get-AzAccessToken`
- **Pattern source:** Documented in `docs/reference/faq.md`; follows v4-v8 Entra ID patterns
- **KQL queries:** Auth-agnostic — same queries work with bearer token; validation is a confirmation step

## Tasks

### Task 1: Update Export-RaiTelemetry.ps1 Parameters

**What:** Replace `$ApiKey` parameter with Entra ID service principal parameters.

**Acceptance criteria:**
- [ ] Remove `-ApiKey` parameter
- [ ] Add `-TenantId`, `-ClientId`, `-KeyVaultName`, `-SecretName` parameters
- [ ] Add `[CmdletBinding()]` with `[ValidateNotNullOrEmpty()]` on all parameters
- [ ] Add `#Requires -Version 7.0` and `#Requires -Modules @{ ModuleName="Az.Accounts"; ModuleVersion="3.0.0" }, @{ ModuleName="Az.KeyVault"; ModuleVersion="5.0.0" }`
- [ ] Preserve existing `-AppInsightsAppId`, `-DaysBack`, `-OutputPath` parameters

### Task 2: Implement Entra ID Authentication Flow

**What:** Replace x-api-key header construction with Connect-AzAccount + Get-AzAccessToken.

**Acceptance criteria:**
- [ ] Retrieve client secret from Key Vault: `$secret = Get-AzKeyVaultSecret -VaultName $KeyVaultName -Name $SecretName`
- [ ] Build PSCredential: `$credential = [PSCredential]::new($ClientId, $secret.SecretValue)`
- [ ] Authenticate: `Connect-AzAccount -ServicePrincipal -TenantId $TenantId -Credential $credential`
- [ ] Obtain bearer token: `$token = (Get-AzAccessToken -ResourceUrl "https://api.applicationinsights.io").Token`
- [ ] Set headers: `$headers = @{ "Authorization" = "Bearer $token" }`
- [ ] Token refresh function for queries exceeding 1 hour

### Task 3: Add Structured Error Handling

**What:** Add try/catch with structured error objects following v4-v8 pattern.

**Acceptance criteria:**
- [ ] Wrap authentication in try/catch with specific error messages for Key Vault access failure, service principal auth failure, and token acquisition failure
- [ ] Return `[PSCustomObject]@{ Status = 'Error'; ErrorType = '...'; Message = '...'; Timestamp = (Get-Date -Format 'o') }` on failure
- [ ] Add `-Verbose` output for authentication flow steps
- [ ] Preserve existing extraction logic; only auth mechanism changes

### Task 4: Validate KQL Queries with Bearer Token Auth

**What:** Confirm all 3 existing KQL queries execute correctly via bearer token authentication.

**Acceptance criteria:**

- [ ] Verify response format unchanged (JSON with `tables[0].rows`)
- [ ] Note any API version parameters that may need updating
