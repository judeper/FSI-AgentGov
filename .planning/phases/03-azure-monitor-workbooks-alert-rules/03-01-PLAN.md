Create ARM template (API version 2018-06-17-preview) for the Operational Health workbook.

**Parameters section:**
- `workbookId` (string, default: fixed GUID like "a1b2c3d4-0001-4000-8000-000000000001" for idempotency -- DO NOT use newGuid())
- `workbookDisplayName` (string, default: "Agent Operational Health")
- `applicationInsightsId` (string, no default -- resource ID of App Insights)
- `workbookSourceId` (string, default: "Azure Monitor")

**Workbook structure in serializedData:**

The workbook uses Notebook/1.0 format with these items:

1. **Global Parameters step (type 9):**
   - TimeRange parameter (type 4 = time range picker, default 86400000ms = 24 hours per user decision)
   - Zone parameter (type 2 = dropdown, isGlobal: true, values: All Zones/Zone 1 - Personal/Zone 2 - Team/Zone 3 - Enterprise, default: "all")
   - Selectable time ranges: 1h, 4h, 24h (default), 48h, 3d, 7d

2. **Overview Tab (type 12 = group, name "Overview"):**
   - KQL metric tile (type 10): Agent count, active sessions, overall error rate, avg latency -- uses summarize on customEvents filtered by TimeRange and Zone
   - KQL time chart (type 2 = markdown or type 3 = query): Error rate trend over time -- adapted from error-trend-analysis.kql with zone filter
   - KQL bar chart: Success rate by agent -- from agent-usage-analytics.kql pattern with zone filter added

3. **Availability Tab (type 12 = group, name "Availability"):**
   - KQL grid: Agent availability by zone showing AgentId, SessionCount, MessageCount, CompletionRate, Zone -- adapted from agent-usage-analytics.kql
   - AgentId column formatted as link (formatter 7) for drill-down to agent detail
   - Drill-down step: When agent clicked, show sessions for that agent (pass AgentId as parameter)

4. **Error Rates Tab (type 12 = group, name "Error Rates"):**
   - KQL grid: Error categorization by type -- adapted from error-categorization-by-type.kql with zone filter
   - KQL time chart: Error rate over time by category
   - Conditional formatting: Error rates > 5% highlighted red, > 2% yellow

5. **Latency Tab (type 12 = group, name "Latency"):**
   - KQL line chart: P50/P95/P99 over time -- from latency-distribution.kql with zone filter
   - KQL grid: Slow queries exceeding threshold -- from slow-query-detection.kql pattern
   - Conditional formatting: P95 > 2000ms highlighted yellow, P99 > 5000ms highlighted red

- Add zone filter to all queries: `| where "{Zone}" == "all" or tostring(customDimensions['Zone']) == "{Zone}"`

- Filter on physical columns (timestamp, name) BEFORE extend operations per research pitfall #3
- Hash user IDs with hash_sha256() per Phase 2 convention

**ARM template metadata:**
- Include `description` field documenting this is the Operational Health workbook for WKBK-01
- Include `version` as "1.0.0"

**Important:** The serializedData field is double-escaped JSON string. Build the workbook items as a proper JSON structure first, then serialize it. Each KQL query within the items must have newlines represented as `\n`.

Reference the existing diagnostic-settings.json ARM template pattern for consistent ARM template structure (schema, contentVersion, parameters, resources, outputs).
