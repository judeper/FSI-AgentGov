# Plan 03-02: Teams Adaptive Card Alerting with Anomaly Detection

## Objective

Create the adaptive card template for Teams alert delivery that visualizes deny event alerts with severity context, anomaly data, and actionable buttons. The card supports all 3 alert types (VolumeAnomaly, NewAgent, ZoneCritical) with type-specific content sections.

## Context

Plan 03-03 defines the severity classification and alert evaluation engine that produces structured alert data. Plan 03-01's Power Automate flow uses this adaptive card template when routing Critical/High severity alerts to Teams. The card must present enough context for a compliance officer to understand the alert and take action without leaving Teams.

**Requirement:** ORC-02 — Teams adaptive card alerting for high-severity deny patterns

**Dependency:** Plan 03-03 must complete first — the card template binds to the alert data structure defined there.

## Tasks

### Task 1: Create adaptive-card-deny-alert.json

Create the Adaptive Card schema (v1.5) template with Power Automate expression placeholders.

**Card schema structure:**

```json
{
  "$schema": "http://adaptivecards.io/schemas/adaptive-card.json",
  "type": "AdaptiveCard",
  "version": "1.5",
  "body": [
    // Header: Alert type + severity badge
    // Context: Agent ID, Zone, Timestamp
    // Metrics: Event count, baseline average, deviation
    // Trend: 7-day trend direction and visualization
    // Details: Type-specific alert details
  ],
  "actions": [
    // View in Dashboard
    // Acknowledge Alert
  ]
}
```

**Template variables (Power Automate expression syntax):**

| Variable | Source | Description |
|----------|--------|-------------|
| `${alertType}` | `AlertResult.Alerts[].AlertType` | VolumeAnomaly, NewAgent, or ZoneCritical |
| `${severity}` | `AlertResult.Alerts[].Severity` | Critical, High, Warning, Info |
| `${severityColor}` | Derived from severity | attention (Critical), warning (High), accent (Warning), default (Info) |
| `${agentId}` | `AlertResult.Alerts[].AgentId` | Copilot Studio agent identifier |
| `${zone}` | `AlertResult.Alerts[].Zone` | Zone 1, Zone 2, or Zone 3 |
| `${zoneName}` | Derived from zone | Personal Productivity, Team Collaboration, Enterprise Managed |
| `${eventCount}` | Correlation event_count | Today's deny event count for this agent/zone |
| `${baselineAvg}` | Correlation trend_7day.Average | 7-day average event count |
| `${baselineStdDev}` | Correlation trend_7day.StdDev | 7-day standard deviation |
| `${deviationSigma}` | Computed | Number of σ above baseline (eventCount - avg) / stddev |
| `${trendDirection}` | Correlation trend_7day.Direction | Increasing, Decreasing, or Stable |
| `${alertMessage}` | Write-DECAlert AlertMessage | Human-readable alert description |
| `${timestamp}` | Alert timestamp | ISO 8601 alert generation time |
| `${dashboardUrl}` | Environment config | Link to Compliance Dashboard |
| `${correlationDate}` | Evaluation date | Date being evaluated (YYYY-MM-DD) |

### Task 2: Create Alert Type Display Variants

Within the single template file, include conditional visibility sections (using `$when` Adaptive Card expressions) for each alert type:

```json
{
  "type": "Container",
  "$when": "${alertType == 'VolumeAnomaly'}",
  "items": [ /* Volume anomaly-specific metrics */ ]
},
{
  "type": "Container",
  "$when": "${alertType == 'NewAgent'}",
  "items": [ /* New agent-specific metrics */ ]
},
{
  "type": "Container",
  "$when": "${alertType == 'ZoneCritical'}",
  "items": [ /* Zone critical-specific metrics */ ]
}
```

**Acceptance criteria:**
- [x] Single template file handles all 3 alert types
- [x] Conditional visibility shows type-appropriate content
- [x] No empty sections when conditions are not met
