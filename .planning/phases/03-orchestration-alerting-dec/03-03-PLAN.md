# Plan 03-03: Alert Severity Classification and Threshold Configuration

## Objective

Add alert infrastructure to DECClient.psm1 and create the alert evaluation engine that classifies deny event correlations into severity levels and persists alerts to the `fsi_denyalert` Dataverse table. This is the foundation for Power Automate flow routing (Plan 03-01) and Teams adaptive card delivery (Plan 03-02).

## Context

Phase 2 completed the correlation engine (`Invoke-DenyEventCorrelation.ps1`) which produces daily `fsi_denycorrelation` summaries with 7-day trend data including `Average`, `StdDev`, and `Direction`. The `fsi_denyalert` table was created in Phase 2 schema but no alert records are written yet. This plan implements the alert evaluation logic that transforms correlation results into actionable alerts.

**Requirement:** ORC-03 — Alert severity classification matching cross-solution standard

### Task 1: Add Write-DECAlert to DECClient.psm1

Add a function that persists alert records to the `fsi_denyalert` Dataverse table.

**Parameters:**
```powershell
param(
    [Parameter(Mandatory)] [ValidateSet('VolumeAnomaly','NewAgent','ZoneCritical','RoutineDeny')]
    [string]$AlertType,
    [Parameter(Mandatory)] [ValidateSet('Critical','High','Warning','Info')]
    [string]$AlertSeverity,
    [string]$AgentId,
    [ValidateSet('1','2','3')] [string]$Zone,

```

**Implementation pattern:** Follow `Write-DECCorrelation` pattern — connection validation → auto-reconnect → severity option set mapping → OData POST to `fsi_denyalerts` → retry loop with exponential backoff.

**Severity mapping:**
- Critical → `fsi_acv_severity` value 4 (Failed)
- High → `fsi_acv_severity` value 4 (Failed)
- Warning → `fsi_acv_severity` value 2 (Warning)
- Info → `fsi_acv_severity` value 1 (Passed)

**Zone mapping:** Reuse existing `864340000-864340002` values.

**Return object:**
```powershell
[PSCustomObject]@{
    Status    = 'Success'
    AlertId   = $responseId
    AlertType = $AlertType
    Severity  = $AlertSeverity
    Timestamp = (Get-Date -Format 'o')
}
```

**Acceptance criteria:**

### Task 3: Add Get-DECAlertThresholds to DECClient.psm1

Add a function that reads alert threshold configuration from Dataverse environment variables.

**Implementation:**
```powershell
function Get-DECAlertThresholds {
    [CmdletBinding()]
    param()

    $sigma = Get-DECEnvironmentVariable -Name 'fsi_DEC_AnomalyThresholdSigma'
    $teamsGroupId = Get-DECEnvironmentVariable -Name 'fsi_DEC_TeamsGroupId'
    $teamsChannelId = Get-DECEnvironmentVariable -Name 'fsi_DEC_TeamsChannelId'

    [PSCustomObject]@{
        AnomalyThresholdSigma = if ($sigma) { [double]$sigma } else { 2.0 }
        TeamsGroupId          = $teamsGroupId
        TeamsChannelId        = $teamsChannelId
        TeamsConfigured       = [bool]($teamsGroupId -and $teamsChannelId)
        MinHistoryDays        = 3  # Minimum days of history before anomaly detection activates
    }
}
```

**Acceptance criteria:**
- [x] Reads sigma threshold from Dataverse (defaults to 2.0)
- [x] Reads Teams group/channel IDs
- [x] Reports whether Teams alerting is configured
- [x] Returns `MinHistoryDays` for cold-start protection

### Task 4: Create Invoke-DECAlertEvaluation.ps1

Create the main alert evaluation engine script that runs after the correlation engine completes.

**Script structure:**
```
#Requires -Version 7.0
#Requires -Modules Az.Accounts, Az.KeyVault
[CmdletBinding()] param(...)

1. Connect to Dataverse (reuses existing connection if available)
2. Read alert thresholds via Get-DECAlertThresholds
3. Query today's correlations via Read-DECCorrelations
4. For each correlation:
   a. Check ZoneCritical: Zone 3 + filter_category ∈ [Jailbreak, XPIA] → Critical alert
   b. Check VolumeAnomaly: event_count > average + (sigma × stddev) → High alert
   c. Check NewAgent: No prior correlations for this AgentId → High alert
   d. Classify remaining: Zone 1 RAI → Warning, routine DLP → Info
5. Write alerts to fsi_denyalert via Write-DECAlert
6. Write validation history via Write-DECValidationHistory
7. Return structured alert summary
```

**Parameters:**
```powershell
param(
    [Parameter(Mandatory)] [string]$TenantId,
    [Parameter(Mandatory)] [string]$ClientId,
    [Parameter(Mandatory)] [string]$KeyVaultName,
    [string]$EnvironmentUrl,
    [datetime]$EvaluationDate = (Get-Date).Date.AddDays(-1),
    [switch]$DryRun
)
```

**Return object:**
```powershell
[PSCustomObject]@{
    Status              = 'Success'
    EvaluationDate      = '2026-02-10'
    CorrelationsEvaluated = 15
    AlertsGenerated     = 3
    AlertsByType        = @{ VolumeAnomaly = 1; NewAgent = 1; ZoneCritical = 1 }
    AlertsBySeverity    = @{ Critical = 1; High = 2; Warning = 0; Info = 0 }
    Alerts              = @(...)   # Array of Write-DECAlert results
    Duration            = '00:00:05'
    Timestamp           = '2026-02-10T14:30:00Z'
}
```

**Cold-start protection:** If fewer than `MinHistoryDays` (3) of correlation data exist for an (AgentId, Zone), skip anomaly detection for that group and log a Verbose message.

**Acceptance criteria:**
- [x] Evaluates all 3 alert types: VolumeAnomaly, NewAgent, ZoneCritical
- [x] Severity classification matches cross-solution standard
- [x] Cold-start protection prevents false positives on first deployment
- [x] Persists all alerts to fsi_denyalert via Write-DECAlert
- [x] Writes validation history for audit trail
- [x] Returns structured summary with alert counts by type and severity
- [x] Follows framework script standards (#Requires, [CmdletBinding()], comment-based help, $ErrorActionPreference = 'Stop', stopwatch)

### Task 5: Update Invoke-DailyDenyReport.ps1 — Add Alert Evaluation Step

Add Section 4 (after correlation, before blob upload) that invokes `Invoke-DECAlertEvaluation.ps1` when `-WriteToDataverse` is specified.

**Insert after the existing correlation step (Section 3):**

```powershell
# =========================================================================
# 4. Evaluate alerts (when writing to Dataverse)
# =========================================================================
$alertResult = $null
if ($WriteToDataverse) {
    Write-Verbose "Step 4: Evaluating deny event alerts..."
    Write-Host "Evaluating deny event alerts for $dateStamp..."

    try {
        $alertParams = @{
            TenantId     = $TenantId
            ClientId     = $ClientId
            KeyVaultName = $KeyVaultName
        }
        if ($DataverseEnvironmentUrl) {
            $alertParams['EnvironmentUrl'] = $DataverseEnvironmentUrl
        }
        $alertParams['EvaluationDate'] = (Get-Date).AddDays(-$DaysBack)

        $alertResult = & "$PSScriptRoot\Invoke-DECAlertEvaluation.ps1" @alertParams
        $results['AlertEvaluation'] = $alertResult
        Write-Host "  Alerts: $($alertResult.Status) ($($alertResult.AlertsGenerated) alerts generated)"
    }
    catch {
        $results['AlertEvaluation'] = New-ErrorResult -ErrorType 'AlertEvaluationFailure' `
            -Message "Alert evaluation failed: $_"
        Write-Warning "Alert evaluation failed: $_"
    }
}
```

**Also update:**
- Step numbering in Verbose messages (adjust blob upload to Step 5)
- Final summary output to include alert count
- Return object to include `AlertResult` and `AlertsGenerated` properties

**Acceptance criteria:**
- [x] Alert evaluation runs after correlation step
- [x] Gated on `-WriteToDataverse` flag (same as correlation)
- [x] Error in alert evaluation does not block blob upload or report completion
