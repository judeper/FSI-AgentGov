## Objective

Create the deny event correlation engine that produces daily summaries grouping events by agent, zone, and time window with severity distribution and 7-day trend indicators. Implement zone-based retention rules via Dataverse bulk delete jobs. Complete the remaining DECClient.psm1 stubs.

### Task 5: Create Invoke-DenyEventCorrelation.ps1

**File:** `maintainers-local/solutions-staging/deny-event-correlation-report/scripts/Invoke-DenyEventCorrelation.ps1`

New script implementing the daily correlation engine. Must use `Read-DECDenyEvents` (Task 3) and `Read-DECCorrelations` (Task 4) helpers, and `Write-DECCorrelation` (Task 1) for Dataverse writes.

**Parameters:**
- `-TenantId` (Mandatory)
- `-ClientId` (Mandatory)
- `-KeyVaultName` (Mandatory)
- `-EnvironmentUrl` (falls back to env var)
- `-CorrelationDate` (defaults to yesterday, `[datetime]`)
- `-TimeWindowHours` (default 24, `[ValidateRange(1, 168)]`)
- `-DryRun` switch

**Logic flow:**
1. Import DECClient.psm1
2. Connect to Dataverse via `Connect-DECDataverse`
3. Query deny events via `Read-DECDenyEvents -StartDate $windowStart -EndDate $windowEnd`
4. Group events by `(fsi_agent_id, fsi_zone)` combination
5. For each group, calculate:
   - `event_count` — total deny events
   - `severity_distribution` — count per severity level (Warning, High, Critical, etc.)
   - Source type distribution — count per source (RAI, Audit, DLP)
6. Query prior 7 days of correlations via `Read-DECCorrelations -StartDate (date-7) -EndDate $date -AgentId $agent -Zone $zone`
7. Compute trend:
   - 7-day event count array
   - Average daily count
   - Standard deviation
   - Trend direction: Increasing, Decreasing, Stable
8. Write correlation summary via `Write-DECCorrelation` (redesigned Task 1):
   - `-CorrelationDate` = correlation date
   - `-AgentId` = group agent
   - `-Zone` = group zone
   - `-EventCount` = total events in window
   - `-SeverityDistribution` = hashtable of severity counts
   - `-Trend7Day` = hashtable with daily counts, average, stddev, direction
   - `-TimeWindowStart` / `-TimeWindowEnd` = window bounds
   - `-CorrelationDetails` = full metadata (source breakdown, etc.)
9. Write validation history: `Write-DECValidationHistory -ValidationType 'CorrelationCheck'`
10. Return summary: `[PSCustomObject]@{ Status; CorrelationDate; GroupsProcessed; EventsCorrelated; TrendSummary; Duration }`

**Script standards:**
- `#Requires -Version 7.0`
- `#Requires -Modules @{ ModuleName="Az.Accounts"; ModuleVersion="3.0.0" }, @{ ModuleName="Az.KeyVault"; ModuleVersion="5.0.0" }`
- `[CmdletBinding()]` with full comment-based help
- `$ErrorActionPreference = 'Stop'`
- `[System.Diagnostics.Stopwatch]` duration tracking
- `-Verbose` progress logging at each phase

**Acceptance criteria:**
- [ ] Uses `Read-DECDenyEvents` helper (not inline OData) for event queries
- [ ] Uses `Read-DECCorrelations` helper for trend lookups
- [ ] Uses `Write-DECCorrelation` (redesigned) for summary writes — no inline OData POSTs
- [ ] Groups by agent + zone correctly
- [ ] Calculates severity distribution per group
- [ ] Computes 7-day trend with daily counts, average, stddev, direction
- [ ] Writes validation history record
- [ ] `-DryRun` logs correlation results without writing
- [ ] Structured error handling with try/catch
- [ ] Comment-based help with `.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`, `.NOTES`

### Task 6: Implement Zone-Based Retention via Bulk Delete Jobs

**File:** `maintainers-local/solutions-staging/deny-event-correlation-report/scripts/Set-DECRetentionRules.ps1`

New PowerShell script that creates 3 Dataverse bulk delete jobs:

**Parameters:**
- `-TenantId` (Mandatory)
- `-ClientId` (Mandatory)
- `-KeyVaultName` (Mandatory)
- `-EnvironmentUrl` (falls back to env var)
- `-Zone1RetentionDays` (default 90)
- `-Zone2RetentionDays` (default 365)
- `-Zone3RetentionDays` (default 730)
- `-DryRun` switch

**Logic:**
1. Connect to Dataverse via `Connect-DECDataverse`
2. For each zone (1, 2, 3):
   a. Build FetchXML query targeting `fsi_denyevent` records where:
      - `fsi_zone` = zone value (1, 2, or 3)
      - `fsi_event_timestamp` < (UtcNow - retention days)
   b. Create recurring bulk delete job via Dataverse Web API `BulkDeleteRequest`:
      - Name: `DEC Zone {N} Retention ({days}d)`
      - Recurrence: Daily at 02:00 UTC
      - FetchXML: constructed filter
   c. Also apply retention to `fsi_denycorrelation` records (same zone/date logic)
3. Log job creation details
4. Optionally read environment variables for retention days: `fsi_DEC_Zone{N}RetentionDays`

**Script standards:**
- `#Requires -Version 7.0`
- `[CmdletBinding()]` with comment-based help
- `-DryRun` logs FetchXML and job config without creating
- Idempotent: check if jobs already exist by name before creating

**Acceptance criteria:**
- [ ] 3 bulk delete jobs created for `fsi_denyevent` (one per zone)
- [ ] 3 bulk delete jobs created for `fsi_denycorrelation` (one per zone)
- [ ] Retention days: Zone 1=90d, Zone 2=365d, Zone 3=730d (SEC 17a-4)
- [ ] Recurring daily at 02:00 UTC
- [ ] `-DryRun` logs without creating
- [ ] Idempotent (check-before-create)
- [ ] Comment-based help with regulatory reference to SEC 17a-4
