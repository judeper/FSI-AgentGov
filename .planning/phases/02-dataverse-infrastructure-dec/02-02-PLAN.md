# Plan 02-02: Deny Event Ingestion — Script Updates to Write to fsi_denyevent (DVS-02)

## Objective

Implement the `Connect-DECDataverse` and `Write-DECDenyEvent` stubs in DECClient.psm1, then update all three extraction scripts to write normalized deny events to the `fsi_denyevent` Dataverse table with source type, agent ID, deny reason, zone, severity, and timestamp.

## Must-Haves Covered

| # | Must-Have | How |
|---|----------|-----|
| 2 | Extraction scripts write normalized deny events to `fsi_denyevent` via `Write-DECDenyEvent` | Tasks 1-2 implement stubs; Tasks 3-5 update extraction scripts; Task 6 implements batch ingestion |

## Tasks

### Task 1: Implement Connect-DECDataverse in DECClient.psm1

**File:** `maintainers-local/solutions-staging/deny-event-correlation-report/scripts/private/DECClient.psm1`

Replace the `throw "Not implemented"` stub with working implementation:

- Retrieve client secret from Azure Key Vault via `Get-AzKeyVaultSecret -VaultName $KeyVaultName -Name $SecretName`
- Authenticate to Dataverse via `Connect-AzAccount -ServicePrincipal` (or MSAL token acquisition)
- Obtain Dataverse API token via `Get-AzAccessToken -ResourceUrl $EnvironmentUrl`
- Store connection state in `$script:DvConnection` with metadata (EnvironmentUrl, TenantId, ClientId, Token, TokenExpiry, Timestamp)
- Cache connection; skip re-auth when token valid; `-Force` triggers refresh
- Fall back to `DEC_DataverseUrl` environment variable if `-EnvironmentUrl` not provided
- Return `[PSCustomObject]@{ Status; EnvironmentUrl; TokenExpiry; Timestamp }` on success
- Return structured error via `New-DECErrorResult` on failure

**Acceptance criteria:**
- [ ] Stub `throw` replaced with working Key Vault + Dataverse auth
- [ ] Connection cached in `$script:DvConnection`
- [ ] Token expiry checked with 5-minute buffer (matching App Insights pattern)
- [ ] `-Force` triggers reconnection
- [ ] Falls back to `DEC_DataverseUrl` env var
- [ ] Error handling returns `New-DECErrorResult` on failure

### Task 2: Implement Write-DECDenyEvent in DECClient.psm1

**File:** `maintainers-local/solutions-staging/deny-event-correlation-report/scripts/private/DECClient.psm1`

Replace the `throw "Not implemented"` stub with working implementation:

- Validate `$script:DvConnection` exists and token is valid; auto-reconnect if expired
- Construct OData entity payload from parameters:
  ```json
  {
    "fsi_agent_id": "$AgentId",
    "fsi_session_id": "$SessionId",
    "fsi_filter_reason": "$FilterReason",
    "fsi_filter_category": "$FilterCategory",
    "fsi_filter_severity": <int from severity map>,
    "fsi_event_timestamp": "$EventTimestamp (ISO 8601)",
    "fsi_zone": <int from zone map>,
    "fsi_source_type": "$SourceType",
    "fsi_details_json": "<JSON serialized AdditionalProperties>"
  }
  ```
- Add new `-SourceType` parameter: `[ValidateSet('RaiTelemetry','PurviewAudit','PurviewDlp')]`
- POST to `{EnvironmentUrl}/api/data/v9.2/fsi_denyevents`
- Include `Authorization: Bearer $token` and `Content-Type: application/json` headers
- Return `[PSCustomObject]@{ Status='Success'; DenyEventId; AgentId; SourceType; Timestamp }` on success
- Retry logic: 3 attempts with exponential backoff for HTTP 429/503
- Return `New-DECErrorResult` on failure

**Acceptance criteria:**
- [ ] Stub `throw` replaced with working Dataverse Web API POST
- [ ] All stub parameters mapped to OData entity properties
- [ ] New `-SourceType` parameter added (required)
- [ ] Severity and zone picklist values mapped to integers (matching ACV option sets)
- [ ] Retry logic with exponential backoff for 429/503
- [ ] Auto-reconnect if token expired

### Task 3: Update Export-CopilotDenyEvents.ps1 for Dataverse Ingestion

     - `-SourceType 'PurviewAudit'`
  4. Track ingestion count and errors
- CSV/JSON export remains the default path (backward compatible)
- Add `-Verbose` progress logging for Dataverse writes

**Acceptance criteria:**
- [ ] `-WriteToDataverse` switch parameter added
- [ ] Purview Audit fields mapped to Write-DECDenyEvent parameters
- [ ] Source type set to `'PurviewAudit'`
- [ ] Ingestion count and errors tracked and reported
