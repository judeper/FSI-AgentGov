    - `-ConfigPath` [string] Mandatory — Tenant config JSON (same format as Deploy-StepUpPolicies)
    - `-BaselinePath` [string] default "$PSScriptRoot\..\templates\session-baselines" — Directory containing zone baselines

    - Cyan box banner: "Session Security Configurator - Compliance Validation" + "FSI-AgentGov Control 1.23"
    - Dot-source all private helpers: Connect-GraphSession, Compare-SessionBaseline, Test-BreakGlassExclusion
    - Build $authParams hashtable (ACV pattern)
    - Initialize $results object:
      ```powershell
      $results = @{
          Timestamp = (Get-Date -Format "o")
          Zone = $Zone
          ZoneName = $zoneName
          Validators = @{}
          OverallStatus = "Unknown"
          Reason = ""
      }
      ```
    - Load baseline JSON for specified zone

    **Validator 1: Session Controls (SCM-03)**
    Region block header: "VALIDATOR 1: Session Controls"
    - Query CA policies with SSC prefix: `Get-MgIdentityConditionalAccessPolicy -Filter "startswith(displayName, 'SSC-')"`
    - Filter policies for the specified zone (by includeGroups matching config)
    - For each matching policy, call `Compare-SessionBaseline` against zone baseline
    - Check: signInFrequency matches zone requirement (8h/4h/1h)
    - Check: persistentBrowser mode is "never"
    - Check: policy state (report-only vs enabled)
    - Return structured result:
      ```powershell
      @{
          OverallStatus = "Passed|Failed|Warning"
          Confidence = "HIGH|MEDIUM"
          Reason = "..."
          PoliciesChecked = $count
          Mismatches = @(...)
          Timestamp = Get-Date -Format "o"
      }
      ```
    - Warning status: policy exists but in report-only (not yet enforced)
    - Failed status: policy missing, wrong frequency, or mismatched controls
    - Passed status: all session controls match baseline and policy is enabled

    **Validator 2: Authentication Strength (SCM-05)**
    Region block header: "VALIDATOR 2: Authentication Strength"
    - Query authentication strength policies: `Get-MgIdentityConditionalAccessAuthenticationStrengthPolicy`
    - For Zone 1: verify standard MFA is in use (no custom requirement)
    - For Zone 2: verify passwordless MFA policy exists and is referenced by SSC policy
      - Check policy contains: FIDO2, Windows Hello for Business, or Microsoft Authenticator passwordless
    - For Zone 3: verify phishing-resistant MFA policy exists and is referenced by SSC policy
      - Check policy contains: FIDO2 security key or certificate-based authentication ONLY (no push notification methods)
    - Compare against baseline.authenticationStrength field
    - Return structured result with status, methods found, and compliance assessment

    **Validator 3: PIM Settings (SCM-06)**
    Region block header: "VALIDATOR 3: PIM Role Settings"
    - Skip if `-SkipPimValidation` (requires RoleManagement.Read.All permission)
    - Query PIM role settings for AI-related admin roles using:
      `Get-MgPolicyRoleManagementPolicyAssignment` and `Get-MgPolicyRoleManagementPolicy`
    - Target roles from Control 1.23: Power Platform Admin, Copilot Admin, Global Admin
    - For each role, validate against zone baseline pimSettings:
      - maxActivationHours: Zone 1=8h, Zone 2=4h, Zone 3=2h
      - requireApproval: Zone 1=false, Zone 2=false, Zone 3=true
      - requireAuthContext: Zone 2=true, Zone 3=true
    - Return structured result with per-role compliance status
    - If PIM not configured or roles not assigned: return Warning (not Failed)

    **Validator 4: Break-Glass Exclusions**
    Region block header: "VALIDATOR 4: Break-Glass Exclusions"
    - For each SSC CA policy found in the tenant:
      - Call Test-BreakGlassExclusion with policy and config
    - Passed: ALL SSC policies exclude all break-glass accounts
    - Failed: ANY SSC policy missing break-glass exclusion
    - This is a critical safety validator — Failed here should make OverallStatus = Failed regardless of other validators

    **Validator 5: Policy Conflict Audit (optional, Success Criteria 5)**
    Region block header: "VALIDATOR 5: Policy Conflict Audit"
    - Only runs if `-IncludeConflictAudit`
    - Query ALL CA policies (not just SSC-prefixed)
    - For each SSC policy, find overlapping policies:
      a. Same user group targeting (includeGroups intersection)
      b. Different signInFrequency values
      c. Both have sessionControls defined
    - For each conflict: record policy names, conflicting values, and impact assessment
    - Return structured result with conflicts array
    - Status: "Passed" (no conflicts) or "Warning" (conflicts found — informational, does not fail overall)

    **Overall Status Computation (ACV pattern exactly):**
    - Collect statuses from all validators
    - If any Error or Failed: OverallStatus = "Failed"
    - If any Warning: OverallStatus = "Warning"
    - If all Passed: OverallStatus = "Passed"

    **Summary Display (ACV box format):**
    - Cyan box with zone, timestamp, overall status
    - Per-validator status line with color coding
    - Summary reason text

    **JSON Output:**
    - If -OutputPath specified, write results to JSON file (ACV pattern)
    - Return $results object
