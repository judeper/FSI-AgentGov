    - Function `Test-BreakGlassExclusion` with params: `-PolicyTemplate` (hashtable), `-Config` (object with breakGlassAccounts array)
    - Check 1: Verify break-glass account IDs exist in `$PolicyTemplate.conditions.users.excludeUsers`
    - Check 2: If not in excludeUsers, check `$PolicyTemplate.conditions.users.excludeGroups` by resolving group membership with `Get-MgGroupMember`
    - Return `$true` if ALL break-glass accounts are excluded (either directly or via group)
    - Return `$false` with `Write-Error` messages listing which accounts are NOT excluded
    - Use color-coded output: Green checkmark for pass, Red for fail
    - Follow the exact code pattern from 01-RESEARCH.md "Break-Glass Exclusion Validation" section
    - Add `-DryRun` param: when true, skip Graph API calls for group membership resolution, assume direct user exclusion only

    **Compare-SessionBaseline.ps1** — Follow ACV's `private/Compare-ValidationBaseline.ps1` pattern:
    - Function `Compare-SessionBaseline` with params: `-Policy` (object from Graph API), `-Baseline` (object loaded from baseline JSON)
    - Normalize signInFrequency to minutes for comparison (hours * 60)
    - Compare: signInFrequency value, persistentBrowser mode, authentication strength ID
    - Return structured result: `@{ Status = "Passed|Failed"; Mismatches = @() }`
    - Each mismatch entry: `@{ Property = "signInFrequency"; Expected = "240min"; Actual = "480min" }`
    - Handle missing properties gracefully (some policies may not have persistentBrowser)
    - Follow the exact code pattern from 01-RESEARCH.md "Validating Session Controls Against Baseline" section
