### Task 1: Script scaffold and parameters

**Action:** Create `scripts/governance/Set-InactivityTimeout.ps1` with full param block.

**Details:**
- `#Requires -Version 7.0`
- Comment-based help (`.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`, `.NOTES`)
- `[CmdletBinding(SupportsShouldProcess)]`
- Parameters:
  - `-EnvironmentName` [string] — Mandatory, ValidateNotNullOrEmpty. Canonical Power Platform Environment Name.

  - `-WarningDuration` [int] — ValidateRange(1, 30), default 5.
  - `-DataverseUrl` [string] — Optional. Dataverse environment URL for audit record writing.
  - `-OutputFormat` [string] — ValidateSet('Table', 'JSON', 'Object'), default 'Object'.
  - `-OutputPath` [string] — Optional. File path for output.
  - `-IncludeEvidence` [switch] — Adds SHA-256 hash to result.
- `$ErrorActionPreference = 'Stop'`
- FSI governance banner (58-char wide box drawing, Cyan)

**Acceptance criteria:**
- [ ] `#Requires -Version 7.0` present

- [ ] Banner matches existing governance scripts

### Task 2: Helper functions (auth + API)

**Action:** Add `Get-BapApiToken`, `Invoke-BapApi` (extended with `-Body`), `Get-DataverseToken`, `Invoke-DataverseApi` helper functions.

**Details:**
- `Get-BapApiToken`: `Get-AzAccessToken -ResourceUrl "https://api.bap.microsoft.com"`, throws on failure.
- `Invoke-BapApi`: Accepts `-Uri`, `-Token`, `-Method` (GET/PATCH), `-Body` (hashtable, optional). Converts body to JSON. Throws on failure (not soft-fail) for mutation operations.
- `Get-DataverseToken`: Conditional — only defined if needed. `Get-AzAccessToken -ResourceUrl $ResourceUrl`, throws on failure.
- `Invoke-DataverseApi`: Accepts `-Uri`, `-Token`, `-Method` (GET/POST), `-Body`. OData 4.0 headers. Returns representation.

**Pattern source:** `Test-AgentAuthConfiguration.ps1` (Get-BapApiToken/Invoke-BapApi), `Import-ApprovedSecurityGroups.ps1` (Invoke-DataverseApi).

**Acceptance criteria:**
- [ ] `Invoke-BapApi` accepts `-Body` parameter for PATCH
- [ ] Auth uses `Get-AzAccessToken -ResourceUrl "https://api.bap.microsoft.com"`
- [ ] Error messages include specific remediation guidance

### Task 3: Core remediation logic (GET-PATCH-GET)

**Action:** Implement the main execution flow.

**Details:**
1. **Authenticate:** Call `Get-BapApiToken`.
2. **GET current settings:** `GET /providers/Microsoft.BusinessAppPlatform/scopes/admin/environments/{EnvironmentName}/settings/privacy?api-version=2021-04-01`. Extract `InactivityTimeoutEnabled`, `InactivityTimeoutInMinutes`, `InactivityWarningInMinutes` from `properties`.
3. **WhatIf check:** If `ShouldProcess` returns false, Write-Verbose current vs target values and return early.
4. **PATCH:** Send `{ "properties": { "InactivityTimeoutEnabled": true, "InactivityTimeoutInMinutes": $TimeoutDuration, "InactivityWarningInMinutes": $WarningDuration } }`.
5. **Verify:** Re-GET settings, compare to target values, set `$verified` flag.
6. Error handling per HTTP status code (401/403/404/429) with descriptive messages.

**Acceptance criteria:**
- [ ] GET-PATCH-GET sequence implemented
- [ ] `-WhatIf` shows preview without PATCHing
- [ ] Error handling for 401, 403, 404, 429
- [ ] Verified flag set correctly after re-GET

### Task 4: Optional Dataverse audit record

**Action:** When `-DataverseUrl` is provided, write a compliance record to `fsi_inactivitytimeout_compliance`.

**Details:**
- Acquire Dataverse token via `Get-DataverseToken`.
- POST to `${DataverseUrl}api/data/v9.2/fsi_inactivitytimeout_compliances` with payload:
  - `fsi_environmentid`: EnvironmentName
  - `fsi_environmentname`: display name (from GET response metadata if available)
  - `fsi_inactivitytimeoutenabled`: true
  - `fsi_timeoutduration`: TimeoutDuration
  - `fsi_compliancestatus`: Compliant (remediated)
  - `fsi_lastscandate`: UTC now (ISO 8601)
  - `fsi_notes`: "Remediated by Set-InactivityTimeout.ps1. Before: Enabled=X, Duration=Y. After: Enabled=True, Duration=$TimeoutDuration, Warning=$WarningDuration."
- On failure, Write-Warning but do not throw — main remediation already succeeded.

**Acceptance criteria:**
- [ ] Dataverse write only attempted when `-DataverseUrl` provided
- [ ] Audit record contains before/after values
- [ ] Failure does not block script result

### Task 5: Result object and output

**Action:** Build result object, apply SHA-256 hash, format output.

**Details:**
- Result shape:
  ```
  Metadata: { Timestamp, ScriptVersion, EnvironmentName, DurationSeconds, IntegrityHash }
  Applied: bool
  PreviousConfig: { InactivityTimeoutEnabled, InactivityTimeoutInMinutes, InactivityWarningInMinutes }
  NewConfig: { InactivityTimeoutEnabled, InactivityTimeoutInMinutes, InactivityWarningInMinutes }
  Verified: bool
  AuditRecord: string (Dataverse record ID or null)
  ```
- If `-IncludeEvidence`: compute SHA-256 hash of result JSON, set IntegrityHash.
- Output formatting: Table (Format-Table), JSON (ConvertTo-Json -Depth 10), Object (passthrough).
- If `-OutputPath`: write JSON to file.
- Console summary (Cyan lines, applied status, environment name, before/after).

**Acceptance criteria:**
- [ ] Result includes Metadata, Applied, PreviousConfig, NewConfig, Verified, AuditRecord
- [ ] SHA-256 hash computed when `-IncludeEvidence` specified
- [ ] All three OutputFormat options work
- [ ] Console summary printed
