# Plan 03-01: Runbook Wrapper, Baseline Capture, and CMMClient Drift Detection Enhancements

## Goal

Create the PowerShell runbook wrapper for automated daily content moderation validation and the operator-initiated baseline capture script. These scripts bridge Phase 1 validation scripts and Phase 2 Dataverse infrastructure into an automated daily workflow. The runbook enables non-interactive execution with structured JSON output that Power Automate can parse and route. The baseline capture gives operators the ability to snapshot current per-agent moderation levels as the approved baseline for future drift detection.

**Key difference from AAM (v6):** CMM drift detection operates at the **agent level** (50-500 agents) rather than the environment level (10-50 environments). This requires a batch baseline query optimization — a single OData request for all active baselines with in-memory hashtable lookups — rather than per-entity Dataverse queries.

## Tasks

### Task 1: Complete Save-CMMBaseline and Enhance Get-ModerationBaseline in CMMClient.psm1

Modify `content-moderation-monitor/scripts/private/CMMClient.psm1` to complete the `Save-CMMBaseline` stub and enhance `Get-ModerationBaseline`.

**Save-CMMBaseline completion:**

The current stub writes a new baseline record but does NOT deactivate prior active baselines for the same agent. Add deactivation logic:

```powershell
function Save-CMMBaseline {
    [CmdletBinding(SupportsShouldProcess)]
    param(
        [Parameter(Mandatory)][string]$EnvironmentGuid,
        [Parameter(Mandatory)][string]$EnvironmentName,
        [Parameter(Mandatory)][string]$Zone,
        [Parameter(Mandatory)][string]$AgentId,
        [Parameter(Mandatory)][string]$AgentName,
        [Parameter(Mandatory)][string]$ModerationLevel,
        [string]$CapturedBy,
        [string]$RawJson
    )
```

Logic:
1. Query `fsi_moderationbaselines` for active baseline: `$filter=fsi_is_active eq true and fsi_agent_id eq '{AgentId}'`
2. If found, PATCH `fsi_is_active = false` (deactivate previous baseline)
3. POST new baseline record with all fields and `fsi_is_active = true`
4. Set `fsi_name` to `"{AgentName}-{Zone}-{timestamp}"`
5. All mutations gated by `ShouldProcess` (-WhatIf support)
6. Wrap in try/catch — failure logged with Write-Warning, never throws

**Get-ModerationBaseline enhancement:**

Add `-AgentId` and `-ActiveOnly` parameters:

```powershell
function Get-ModerationBaseline {
    [CmdletBinding()]
    param(
        [string]$EnvironmentId,
        [string]$AgentId,
        [switch]$ActiveOnly
    )
```

Logic:
- When `-AgentId` provided: `$filter += " and fsi_agent_id eq '{AgentId}'"`
- When `-ActiveOnly` provided: `$filter += " and fsi_is_active eq true"`
- Enables batch query: `Get-ModerationBaseline -ActiveOnly` returns ALL active baselines for hashtable construction
- Enables per-agent query: `Get-ModerationBaseline -AgentId $id -ActiveOnly` returns single active baseline

**Acceptance Criteria:**
- [ ] Save-CMMBaseline deactivates existing active baseline before saving new one
- [ ] Save-CMMBaseline supports -WhatIf via ShouldProcess
- [ ] Get-ModerationBaseline supports -AgentId filter for per-agent queries
- [ ] Get-ModerationBaseline supports -ActiveOnly switch for active-only queries
- [ ] Both functions handle connection failures gracefully (Write-Warning, not throw)
- [ ] CMMClient.psm1 imports without errors after modifications

### Task 2: Create Start-ModerationValidationRunbook.ps1

Create `content-moderation-monitor/scripts/Start-ModerationValidationRunbook.ps1` following the proven AAM `Start-AccessValidationRunbook.ps1` pattern.

**Parameters:**

| Parameter | Type | Required | Default | Purpose |
|-----------|------|----------|---------|---------|
| `-TenantId` | string | Yes | — | Azure AD tenant GUID |
| `-ClientId` | string | Yes | — | App registration client ID |
| `-CertificateThumbprint` | string | Yes | — | Certificate for auth |
| `-DataverseUrl` | string | Yes | — | Dataverse environment URL |
| `-ExcludeSandbox` | switch | No | $false | Exclude sandbox environments |
| `-ExcludeTrial` | switch | No | $false | Exclude trial environments |
| `-GracePeriodHours` | int | No | 48 | Grace period for new environments |

**Script structure:**

```
1. #Requires -Version 7.0
2. #Requires -Modules MSAL.PS
3. Certificate-based authentication (Connect-CMMDataverse)
4. Read operational params from Dataverse env vars:
   - fsi_CMM_GracePeriodHours → $GracePeriodHours override
   - fsi_CMM_IncludeSandbox → $ExcludeSandbox override
   - fsi_CMM_IncludeDrafts → $IncludeDrafts
   - fsi_CMM_BaselineAgeThresholdDays → $BaselineAgeThresholdDays
5. Run Test-ContentModerationCompliance with -PersistResults -DataverseUrl -DataverseToken -OutputFormat Object
6. Batch-query ALL active baselines from fsi_moderationbaselines in single OData request
7. Build hashtable keyed by AgentId for O(1) lookup
8. Per-agent drift detection:
   a. Look up agent in baseline hashtable
   b. If found: compare current ModerationLevel to baseline level
   c. Classify drift direction: Weakened/Strengthened/Changed
   d. If not found: IsFirstRun=true for that agent
9. Build enriched ZoneSummary with { Total, Compliant, Violations } per zone
10. Determine AlertRequired and AlertSeverity:
    - AlertRequired = (violations > 0) OR (HasDrift with weakened direction)
    - AlertSeverity = highest severity from violations or "Critical" for Zone 3 weakened drift
11. Build output JSON object:
    - RunType: "ModerationValidation"
    - Timestamp: ISO 8601
    - TotalAgents: from scan result
    - TotalEnvironments: from scan result
    - OverallStatus: Passed/Warning/Failed
    - Reason: human-readable summary
    - ZoneSummary: { Zone1: {Total, Compliant, Violations}, Zone2: {...}, Zone3: {...} }
    - Violations: array of violation objects (AgentId, AgentName, EnvironmentId, EnvironmentName, Zone, ExpectedModerationLevel, ActualModerationLevel, Severity, RegulatoryContext)
    - Drift: { HasDrift, IsFirstRun, DriftedAgents, Details[] }
    - AlertRequired: boolean
    - AlertSeverity: string
12. Output as JSON to pipeline (ConvertTo-Json -Depth 10)
13. Error catch → emit error JSON with AlertRequired=true, AlertSeverity="Error"
```

**Drift direction classification (moderation level ordering):**
```
High (rank 1) → Medium (rank 2) → Low (rank 3)
currentRank > baselineRank → Weakened (less restrictive — alert required)
currentRank < baselineRank → Strengthened (more restrictive — informational)
```

**Batch baseline optimization:**
```powershell
# Single query for ALL active baselines (not per-agent):
$allBaselines = Get-ModerationBaseline -ActiveOnly
$baselineMap = @{}
foreach ($b in $allBaselines) {
    $baselineMap[$b.AgentId] = $b
}
# Then O(1) lookup per agent during drift detection:
$baseline = $baselineMap[$agent.AgentId]
```

**Acceptance Criteria:**
- [ ] Script runs non-interactively with certificate-based auth
- [ ] Reads operational parameters from Dataverse environment variables (with fallback defaults)
- [ ] Calls Test-ContentModerationCompliance with -PersistResults for Dataverse writes
- [ ] Batch-queries all active baselines in single OData request (performance optimization)
- [ ] Drift detection compares current moderation level to active baseline per agent
- [ ] Drift direction correctly classified (Weakened/Strengthened/Changed)
- [ ] Outputs structured JSON only (no Write-Host) with all required properties
- [ ] AlertRequired is true when violations detected OR weakened drift detected
- [ ] AlertSeverity reflects the highest severity across all violations
- [ ] Fail-open on Dataverse errors (Write-Warning, continue with defaults)
- [ ] ZoneSummary uses enriched format: `{ Total, Compliant, Violations }` per zone

### Task 3: Create Invoke-ModerationBaselineCapture.ps1

Create `content-moderation-monitor/scripts/Invoke-ModerationBaselineCapture.ps1` following the AAM `Invoke-AccessBaselineCapture.ps1` pattern.

**Parameters:**

| Parameter | Type | Required | Default | Purpose |
|-----------|------|----------|---------|---------|
| `-TenantId` | string | Yes | — | Azure AD tenant GUID |
| `-ClientId` | string | Yes | — | App registration client ID |
| `-CertificateThumbprint` | string | No | — | Certificate auth (optional, can use interactive) |
| `-DataverseUrl` | string | Yes | — | Dataverse environment URL |
| `-Zone` | int | No | — | Filter to specific zone (1, 2, or 3) |
| `-EnvironmentGuid` | string | No | — | Capture agents in single environment |
| `-AgentId` | string | No | — | Capture baseline for single agent |
| `-ExcludeSandbox` | switch | No | $false | Exclude sandbox environments |
| `-IncludeDrafts` | switch | No | $false | Include draft agents |
| `-CapturedBy` | string | No | current UPN | Identity of the capturing operator |
| `-Interactive` | switch | No | $false | Use interactive auth instead of certificate |

**Script structure:**

```
1. #Requires -Version 5.1
2. Parameter validation:
   - CertificateThumbprint required unless -Interactive
   - -Zone, -EnvironmentGuid, -AgentId are mutually exclusive filters
3. MSAL token acquisition (interactive or certificate)
4. Connect-CMMDataverse
5. Call Get-AgentModerationSettings to capture live moderation levels for all agents
6. Apply filters:
   - If -Zone: filter agents to those in matching zone
   - If -EnvironmentGuid: filter to agents in that environment
   - If -AgentId: filter to single agent
7. WhatIf preview (formatted console output showing what would be captured)
8. For each agent:
   a. Build raw JSON (full agent metadata)
   b. Call Save-CMMBaseline (handles active baseline rotation)
   c. Track zone breakdown
   d. Report: "Baseline captured for {AgentName} in {EnvironmentName} (Zone {Zone})"
9. Emit structured JSON result:
   - CapturedOn: ISO 8601
   - CapturedBy: operator identity
   - TotalCaptured: count
   - ZoneBreakdown: { Zone1: count, Zone2: count, Zone3: count }
   - Agents: [ { AgentId, AgentName, EnvironmentName, Zone, ModerationLevel } ]
```

**Acceptance Criteria:**
- [ ] Captures live agent moderation levels for all (or filtered) agents
- [ ] Calls Save-CMMBaseline for each agent (handles active baseline rotation)
- [ ] Supports -Zone filter for zone-specific captures
- [ ] Supports -EnvironmentGuid for environment-specific captures
- [ ] Supports -AgentId for single-agent captures
- [ ] Supports -WhatIf (ShouldProcess propagated to Save-CMMBaseline)
- [ ] Supports both interactive and certificate-based authentication
- [ ] Outputs structured JSON capture summary with zone breakdown
