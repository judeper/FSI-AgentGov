## Tasks

### Task 1: Verify and Refine Drift Detection Logic

Review `Start-ModerationValidationRunbook.ps1` drift detection implementation and verify:

1. **Moderation level comparison correctness:**
   - Level ranking: High=1, Medium=2, Low=3
   - `currentRank > baselineRank` → **Weakened** (level decreased, e.g., High→Medium or High→Low) → alert required
   - `currentRank < baselineRank` → **Strengthened** (level increased, e.g., Low→High) → informational
   - `currentRank == baselineRank` → no drift for that agent
   - Unknown levels → treated as Changed with Warning severity

2. **Batch baseline query optimization:**
   - Verify single OData request: `Get-ModerationBaseline -ActiveOnly`
   - Verify hashtable construction: `$baselineMap[$agent.AgentId] = $baseline`
   - Verify O(1) lookup during per-agent drift detection loop
   - Confirm no per-agent Dataverse queries in the drift detection path

3. **Edge cases:**
   - Agent has no active baseline → `IsFirstRun=true` for that agent, skip drift detection
   - Baseline exists but agent no longer in scan results → skip (agent may have been deleted/unpublished)
   - All agents are first-run → `Drift.HasDrift=false, Drift.IsFirstRun=true, Drift.DriftedAgents=0`
   - Dataverse query failure on baseline fetch → fail open (`HasDrift=false, IsFirstRun=true`, Write-Warning)
   - Agent with Unknown moderation level → include in violations but classify drift as "Changed" not "Weakened"

4. **Fix any structural mismatches** between:
   - Runbook output JSON keys and Parse_Results schema in `moderation-validation-flow.json`
   - Drift object structure and adaptive card drift section `${variableName}` placeholders
   - ZoneSummary keys (`Zone1`, `Zone2`, `Zone3`) and adaptive card zone summary section
   - Violation object properties and adaptive card violation FactSet entries
