# Plan 02-03: Wire Phase 1 PowerShell Scripts to Dataverse

## Goal

Connect the Phase 1 PowerShell validation pipeline to the Dataverse infrastructure from Plans 02-01 and 02-02. When operators provide `-DataverseUrl`, the orchestrator reads operational parameters from Dataverse environment variables, persists validation results, and writes individual violations — while gracefully falling back to standalone mode when Dataverse is unavailable.

### Task 2: Wire Dataverse connection and parameter reading

At the top of the orchestrator's `begin` block, add Dataverse connection logic:

```powershell
# Dataverse integration
$dataverseConnected = $false
if ($DataverseUrl) {
    try {
        Import-Module "$PSScriptRoot\private\CMMClient.psm1" -Force
        
        if ($DataverseToken) {
            Connect-CMMDataverse -DataverseUrl $DataverseUrl -AccessToken $DataverseToken
        } else {
            Connect-CMMDataverse -DataverseUrl $DataverseUrl
        }
        
        $connection = Get-CMMConnection
        if ($connection.IsConnected) {
            $dataverseConnected = $true
            Write-Verbose "Connected to Dataverse: $DataverseUrl"
            
            # Read operational parameters from Dataverse env vars
            # Read operational parameters from Dataverse env vars
            # Rule: explicit parameter values always override Dataverse values
            $dvGracePeriod = Get-CMMEnvironmentVariable -Name 'GracePeriodHours' -DefaultValue $null
            if (-not $PSBoundParameters.ContainsKey('GracePeriodHours') -and $null -ne $dvGracePeriod) {
                $GracePeriodHours = [int]$dvGracePeriod
                Write-Verbose "GracePeriodHours from Dataverse: $GracePeriodHours"
            }
            
            $dvIncludeDrafts = Get-CMMEnvironmentVariable -Name 'IncludeDrafts' -DefaultValue $null
            if (-not $PSBoundParameters.ContainsKey('IncludeDrafts') -and $null -ne $dvIncludeDrafts -and $dvIncludeDrafts -eq 'true') {
                $IncludeDrafts = [switch]::Present
                Write-Verbose "IncludeDrafts from Dataverse: true"
            }
            
            $dvIncludeSandbox = Get-CMMEnvironmentVariable -Name 'IncludeSandbox' -DefaultValue $null
            if (-not $PSBoundParameters.ContainsKey('ExcludeSandbox') -and $null -ne $dvIncludeSandbox -and $dvIncludeSandbox -eq 'true') {
                $ExcludeSandbox = $false
                Write-Verbose "IncludeSandbox from Dataverse: true (ExcludeSandbox overridden)"
            }
        }
    } catch {
        Write-Warning "Dataverse connection failed: $($_.Exception.Message). Continuing in standalone mode."
    }
}
```

**Key rules:**
1. Explicit parameter values always override Dataverse env vars (operator intent wins)
2. Dataverse values only fill in when the parameter was not explicitly set
3. Connection failure = warning + continue standalone, never abort
4. CMMClient.psm1 is imported only when `-DataverseUrl` is provided

**Acceptance Criteria:**
- [ ] Dataverse connection established when `-DataverseUrl` provided
- [ ] `Get-CMMEnvironmentVariable` reads GracePeriodHours, IncludeDrafts, IncludeSandbox
- [ ] Explicit parameter values override Dataverse env var values
- [ ] Connection failure logs warning and continues in standalone mode
- [ ] No CMMClient import when `-DataverseUrl` is omitted

### Task 3: Wire result persistence

After the validation pipeline completes, add Dataverse persistence logic:

```powershell
# Persist results to Dataverse
if ($PersistResults -and $dataverseConnected) {
    $runId = [guid]::NewGuid().ToString()
    
    # Write validation summary
    $validationSummary = @{
        OverallStatus      = $scanResult.OverallStatus
        TotalAgents        = $scanResult.TotalAgents
        CompliantCount     = $scanResult.CompliantCount
        ViolationCount     = $scanResult.ViolationCount
        EnvironmentsScanned = $scanResult.EnvironmentsScanned
    }
    
    if ($PSCmdlet.ShouldProcess("Dataverse validation history", "Write scan results")) {
        try {
            Write-ModerationValidationHistory -ValidationResult $validationSummary -RunId $runId
            Write-Verbose "Validation history written with RunId: $runId"
        } catch {
            Write-Warning "Failed to write validation history: $($_.Exception.Message)"
        }
    }
    
    # Write individual violations
    foreach ($violation in $scanResult.Violations) {
        if ($PSCmdlet.ShouldProcess("$($violation.AgentName) in $($violation.EnvironmentDisplayName)", "Write violation")) {
            try {
                $violationData = @{
                    EnvironmentId          = $violation.EnvironmentId
                    EnvironmentDisplayName = $violation.EnvironmentDisplayName
                    AgentId                = $violation.AgentId
                    AgentName              = $violation.AgentName
                    Zone                   = $violation.Zone
                    ExpectedLevel          = $violation.ExpectedModerationLevel
                    ActualLevel            = $violation.CurrentModerationLevel
                    Severity               = $violation.Severity
                    RegulatoryContext      = $violation.RegulatoryContext
                }
                Write-ModerationViolation -Violation $violationData -RunId $runId
            } catch {
                Write-Warning "Failed to write violation for $($violation.AgentName): $($_.Exception.Message)"
            }
        }
    }
    
    Write-Output "Results persisted to Dataverse (RunId: $runId, Violations: $($scanResult.Violations.Count))"
} elseif ($PersistResults -and -not $dataverseConnected) {
    Write-Warning "PersistResults requested but Dataverse not connected. Results not persisted."
}
```

**Key rules:**
1. RunId (GUID) correlates all records from one scan
2. ShouldProcess gates every write operation (WhatIf compatibility)
3. Each violation write is independently try/caught (one failure doesn't block others)
4. Summary output confirms persistence with RunId

**Acceptance Criteria:**
- [ ] RunId generated as GUID for each scan execution
- [ ] `Write-ModerationValidationHistory` called with summary + RunId
- [ ] `Write-ModerationViolation` called for each violation with RunId
- [ ] ShouldProcess wraps each write operation
- [ ] Individual violation failures don't abort remaining writes
- [ ] `-PersistResults` without `-DataverseUrl` produces warning
