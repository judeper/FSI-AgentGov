Create Compare-ValidationBaseline.ps1 in the private/ directory. This function queries Dataverse validation history to determine if the current validation result represents a regression (drift) from the last known good baseline.

**Function signature:**
```powershell
function Compare-ValidationBaseline {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory)][string]$DataverseUrl,
        [Parameter(Mandatory)][string]$DataverseToken,
        [Parameter(Mandatory)][string]$Scope,           # "Tenant" or "Environment"
        [Parameter(Mandatory)][string]$CurrentStatus,    # Passed/Warning/GracePeriod/Failed/Error
        [string]$ValidationType,                          # UnifiedAuditLog, MailboxAudit, PurviewRetention, Orchestrator
        [string]$EnvironmentId                            # Required for Environment scope
    )
}
```

**Logic:**
1. Map status strings to severity values: Passed=1, Warning=2, GracePeriod=3, Failed=4, Error=5
2. Build OData query for fsi_auditvalidationhistory table:
   - For Tenant scope: Filter by `fsi_scope eq 100000000` (Tenant option set value) and `fsi_severity eq 1` (Passed) and optionally `fsi_validationtype eq '{ValidationType}'`
   - For Environment scope: Filter by `fsi_scope eq 100000001` (Environment option set value) and `fsi_severity eq 1` (Passed) and `fsi_environmentid eq '{EnvironmentId}'` and `fsi_validationtype eq 'Orchestrator'`
   - Sort by `createdon desc`, top 1
3. Execute Dataverse Web API GET request: `$DataverseUrl/api/data/v9.2/fsi_auditvalidationhistories?$filter=...&$orderby=createdon desc&$top=1`
4. Compare current severity against baseline severity:
   - If no baseline exists (first run), this IS drift (alert should fire for any non-Passed result)
   - If current severity > baseline severity (numerically), drift detected (regression)
   - If current severity <= baseline severity, no drift (steady or improving)
5. Return PSCustomObject:
   ```
   DriftDetected   : $true/$false
   CurrentStatus   : "Failed"
   CurrentSeverity : 4
   BaselineStatus  : "Passed"
   BaselineSeverity: 1
   BaselineDate    : "2026-02-06T06:00:00Z" (or $null if first run)
   IsFirstRun      : $true/$false
   ```

**Key details:**
- Use `Invoke-RestMethod` with `-Headers @{ Authorization = "Bearer $DataverseToken"; "OData-MaxVersion" = "4.0"; "OData-Version" = "4.0" }`
- Wrap the query in try-catch. On error, return DriftDetected=$true with error note (fail open to alert, never silently suppress)
- Use Dataverse schema names (fsi_severity, fsi_scope, fsi_validationtype, fsi_environmentid) NOT display names
- Option set numeric values for Scope: Tenant=100000000, Environment=100000001
- Add comment-based help (.SYNOPSIS, .DESCRIPTION, .PARAMETER, .OUTPUTS, .EXAMPLE)
- Require PowerShell 7.0 (#Requires -Version 7.0)
- Follow established patterns from Write-ValidationResult.ps1 for Dataverse API calling conventions (headers, error handling)

Create two runbook wrapper scripts that adapt the existing orchestrators for Azure Automation execution context. These are the scripts imported into Azure Automation as runbooks and triggered by Power Automate.

**Start-TenantValidationRunbook.ps1:**

Parameters:
```powershell
param(
    [Parameter(Mandatory)][ValidateSet("Zone1","Zone2","Zone3")][string]$Zone,
    [Parameter(Mandatory)][string]$DataverseUrl,
    [string]$TenantId,
    [string]$ClientId,
    [string]$CertificateThumbprint,
    [switch]$SkipCanaryValidation,
    [int]$CanaryWaitSeconds = 300
)
```

Logic:
1. `#Requires -Version 7.0` and `#Requires -Modules @{ModuleName='ExchangeOnlineManagement'; RequiredVersion='3.0.0'}, @{ModuleName='MSAL.PS'; RequiredVersion='4.37.0'}`
2. Set `$ErrorActionPreference = "Stop"`
3. Dot-source helper scripts from `$PSScriptRoot` (same directory): `Invoke-TenantAuditValidation.ps1`, `private/Compare-ValidationBaseline.ps1`
4. Build parameter hashtable for Invoke-TenantAuditValidation (Zone, TenantId, ClientId, CertificateThumbprint, SkipCanaryValidation, CanaryWaitSeconds) — do NOT pass -Interactive or -OutputPath
5. Invoke `$validationResults = Invoke-TenantAuditValidation @params`
6. Run drift detection for overall status:
   ```powershell
   $driftResult = Compare-ValidationBaseline -DataverseUrl $DataverseUrl -DataverseToken $dataverseToken -Scope "Tenant" -CurrentStatus $validationResults.OverallStatus
   ```
   Note: Acquire Dataverse token using MSAL.PS (same pattern as Connect-PowerPlatform.ps1: `Get-MsalToken -ClientId $ClientId -TenantId $TenantId -ClientCertificate (Get-Item "Cert:\CurrentUser\My\$CertificateThumbprint") -Scopes "$DataverseUrl/.default"`)
7. Also run per-validator drift detection for each key in $validationResults.Validators (UnifiedAuditLog, MailboxAudit, PurviewRetention)
8. Build output object:
   ```powershell
   $output = [PSCustomObject]@{
       RunType           = "TenantValidation"
       Timestamp         = $validationResults.Timestamp
       Zone              = $validationResults.Zone
       OverallStatus     = $validationResults.OverallStatus
       Reason            = $validationResults.Reason
       Validators        = $validationResults.Validators
       Drift             = @{
           Overall       = $driftResult
           PerValidator  = $perValidatorDrift  # hashtable of validator name -> drift result
       }
       AlertRequired     = ($driftResult.DriftDetected -and $validationResults.OverallStatus -ne "Passed")
       AlertSeverity     = $validationResults.OverallStatus  # Used by flow to route Critical/High to Teams
   }
   ```
9. Convert to JSON and write to output stream: `$output | ConvertTo-Json -Depth 10`
   - This is the ONLY Write-Output in the runbook. Azure Automation captures this as job output.
   - Do NOT use Write-Host (goes to verbose stream, not retrievable by Power Automate)
10. Wrap everything in try-catch. On catch, output error JSON:
    ```powershell
    [PSCustomObject]@{
        RunType       = "TenantValidation"
        Timestamp     = (Get-Date -Format "o")
        OverallStatus = "Error"
        Reason        = $_.Exception.Message
        AlertRequired = $true
        AlertSeverity = "Error"
    } | ConvertTo-Json -Depth 5
    ```

**Start-EnvironmentValidationRunbook.ps1:**

Parameters:
```powershell
param(
    [Parameter(Mandatory)][string]$TenantId,
    [Parameter(Mandatory)][string]$DataverseUrl,
    [string]$ClientId,
    [string]$CertificateThumbprint,
    [string]$ClientSecret,
    [switch]$IncludeTrialDev,
    [int]$GracePeriodHours = 24,
    [switch]$SkipDiscovery
)
```

Logic:
1. `#Requires -Version 7.0` and `#Requires -Modules @{ModuleName='Microsoft.PowerApps.Administration.PowerShell'; RequiredVersion='2.0.0'}, @{ModuleName='MSAL.PS'; RequiredVersion='4.37.0'}`
2. Same pattern as tenant runbook but calls `Invoke-EnvironmentAuditValidation`
3. Dot-source: `Invoke-EnvironmentAuditValidation.ps1`, `private/Compare-ValidationBaseline.ps1`
4. Build parameters (TenantId, DataverseUrl, ClientId, CertificateThumbprint, ClientSecret, IncludeTrialDev, GracePeriodHours, SkipDiscovery) — do NOT pass -Interactive or -OutputPath
5. Invoke `$validationResults = Invoke-EnvironmentAuditValidation @params`
6. Run drift detection for each environment in `$validationResults.PerEnvironmentResults`:
   ```powershell
   foreach ($envResult in $validationResults.PerEnvironmentResults) {
       $envDrift = Compare-ValidationBaseline -DataverseUrl $DataverseUrl -DataverseToken $dataverseToken -Scope "Environment" -CurrentStatus $envResult.OverallStatus -EnvironmentId $envResult.EnvironmentId
       $envResult | Add-Member -NotePropertyName "Drift" -NotePropertyValue $envDrift
       $envResult | Add-Member -NotePropertyName "AlertRequired" -NotePropertyValue ($envDrift.DriftDetected -and $envResult.OverallStatus -ne "Passed")
   }
   ```
7. Build output object with per-environment drift info:
   ```powershell
   $output = [PSCustomObject]@{
       RunType                 = "EnvironmentValidation"
       RunId                   = $validationResults.RunId
       Timestamp               = $validationResults.Timestamp
       TotalEnvironments       = $validationResults.TotalEnvironments
       OverallStatus           = $validationResults.OverallStatus
       PerEnvironmentResults   = $validationResults.PerEnvironmentResults  # Now includes Drift and AlertRequired per env
       NewEnvironments         = $validationResults.NewEnvironments
       SkippedUnclassified     = $validationResults.SkippedUnclassified
       SkippedTrialDev         = $validationResults.SkippedTrialDev
       AlertsRequired          = @($validationResults.PerEnvironmentResults | Where-Object { $_.AlertRequired })
   }
   ```
8. JSON output: `$output | ConvertTo-Json -Depth 10`
9. Same try-catch error output pattern as tenant runbook

**Key patterns for BOTH runbooks:**
- Comment-based help at top (.SYNOPSIS, .DESCRIPTION, .PARAMETER, .NOTES mentioning Azure Automation context)
- In .NOTES, document: "This script is designed to run as an Azure Automation runbook. Import into Azure Automation Account and configure with certificate-based authentication."
- Do NOT use emojis in output (Azure Automation output encoding issues)
- Do NOT use Write-Host (not captured by Get Job Output action)
- Use Write-Verbose for diagnostic info (viewable in Automation Account job logs)
- Ensure only ONE ConvertTo-Json output at the end (or in catch block) — multiple outputs cause Parse JSON failures in Power Automate
