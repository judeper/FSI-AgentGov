# Plan 03-01: Script Core + Zone Policy Validation + Admin Exclusion Groups

## Objective

Create `Test-ZoneAgentAccess.ps1` with PowerShell 7.0 conventions, Microsoft Graph API integration for reading M365 Admin Center agent access settings, zone-policy compliance validation, admin exclusion group verification, and deployment group configuration checks.

## Tasks

### Task 1: Script Scaffolding and Parameters

**Action:** Create `scripts/governance/Test-ZoneAgentAccess.ps1` with comment-based help, `#Requires` directives, and parameter block.

**Details:**
- Comment-based help with `.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`, `.OUTPUTS`, `.NOTES`
- `.SYNOPSIS`: "Validates M365 Admin Center agent access settings against zone-based governance policies."
- `.DESCRIPTION`: Explain the 4 check areas (agent access policy, admin exclusion group, deployment groups, web search control). Reference Control 3.8 zone-based requirements table.
- `#Requires -Version 7.0`
- Parameters (matching established convention):
  - `$OutputFormat` — ValidateSet('Table', 'JSON', 'Object'), default 'Table'
  - `$OutputPath` — optional file path for JSON export
  - `$ZoneMapping` — hashtable mapping deployment group names or context identifiers to zone numbers
  - `$IncludeEvidence` — switch for SHA-256 integrity hashing
  - `$BaselinePath` — for drift detection (wired up in Plan 02)
  - `$ExpectedExclusionGroupName` — string, default 'CopilotForM365AdminExclude'
- `[CmdletBinding(SupportsShouldProcess)]`
- `$ErrorActionPreference = 'Stop'`
- Banner: cyan box drawing — "FSI Agent Governance — Zone Agent Access Check"
- WhatIf preview

**Acceptance criteria:**
- Script loads without parse errors in PowerShell 7.0+
- All parameters have validation attributes
- Help text is complete with at least 3 examples

### Task 2: Helper Functions

**Action:** Implement helper functions for Graph API access and result building.

**Details:**
- `Get-GraphApiToken` — acquires OAuth token for Microsoft Graph via `Get-AzAccessToken` (same pattern as BAP token in Test-AgentAuthConfiguration.ps1 but for `https://graph.microsoft.com`)
- `Invoke-GraphApi` — wrapper around `Invoke-RestMethod` with Bearer auth, error handling
- `Get-ZoneForContext` — returns zone number from `$ZoneMapping` hashtable (default Zone 1). Generalization of Get-EnvironmentZone for non-environment contexts
- `New-AccessCheckResult` — creates standardized PSCustomObject:
  - `CheckId` (ZAV-01 through ZAV-04)
  - `CheckNumber` (1-4)
  - `Setting` (human-readable name)
  - `CheckGroup` (AgentAccess/ExclusionGroup/DeploymentGroup/WebSearch)
  - `Status` (Pass/Fail/Skip/Warning)
  - `Expected` (what zone policy requires)
  - `Actual` (current configuration value)
  - `Context` (zone identifier, tenant, or deployment group name)
  - `Zone` (governance zone number)
  - `Message` (additional context)
  - `EvidenceHash` ($null, populated when -IncludeEvidence specified)
- `Get-EvidenceHash` — SHA-256 hash computation (same implementation as existing scripts)

**Acceptance criteria:**
- `Get-GraphApiToken` returns token or throws descriptive error
- `Invoke-GraphApi` handles 401/403/404 gracefully
- `New-AccessCheckResult` produces consistent objects

### Task 3: Check 1 — Agent Access Control Policy (ZAV-01)

**Action:** Implement agent access control settings verification per zone.

**Details:**
- Attempt to read agent access configuration via Graph API beta endpoint: `https://graph.microsoft.com/beta/admin/microsoft365/copilot/settings`
- If API unavailable (beta endpoint), fall back to Skip status with manual verification guidance
- Extract agent access policy setting (expected values: AllAgents, OrgAndMicrosoftVerified, OrgOnly)
- Zone logic:
  - Zone 1: Pass if any setting (AllAgents is acceptable)
  - Zone 2: Pass if OrgAndMicrosoftVerified or OrgOnly; Warning if AllAgents
  - Zone 3: Pass if OrgOnly; Fail if broader (OrgAndMicrosoftVerified or AllAgents)
- Since this is a tenant-level setting, evaluate per zone represented in $ZoneMapping
- Error handling: try/catch, Skip status on API failure with manual verification message

**Acceptance criteria:**
- Correctly evaluates agent access policy against zone requirements
- Graceful fallback when API unavailable
- Results show zone-specific pass/fail for each mapped zone

### Task 4: Check 2 — Admin Exclusion Group (ZAV-02)

**Action:** Validate CopilotForM365AdminExclude Entra group exists and is populated.

**Details:**
- Query Microsoft Graph: `GET /v1.0/groups?$filter=displayName eq '{$ExpectedExclusionGroupName}'`
- Check 2a: Group exists
  - Zone 1: Pass (not required) — informational check
  - Zone 2/3: Fail if group does not exist
- Check 2b: Group has members
  - Query: `GET /v1.0/groups/{id}/members/$count` with ConsistencyLevel=eventual
  - Zone 1: Pass (members optional)
  - Zone 2: Warning if empty (should have compliance-sensitive roles)
  - Zone 3: Fail if empty (must have traders, restricted persons)
- Check 2c: Group type is Security
  - Verify `securityEnabled` is true and `mailEnabled` is false
  - All zones: Fail if not a security group
- Compute evidence hash over group properties JSON

**Acceptance criteria:**
- Detects missing exclusion group
- Reports member count
- Validates group type
- Zone-appropriate pass/fail logic

### Task 5: Check 3 — Deployment Group Configuration (ZAV-02 continued)
