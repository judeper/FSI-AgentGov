# Plan 03-02: Drift Detection + Teams Notification Support

## Objective

Extend `Test-ZoneAgentAccess.ps1` with drift detection that compares current scan results against a previous baseline, and create an adaptive card template for Teams webhook notifications when zone access policy drift is detected.

## Tasks

### Task 1: Baseline Loading and Comparison Logic

**Action:** Add drift detection functions and wire up `$BaselinePath` parameter.

**Details:**
- `Import-AccessBaseline` function:
  - Loads previous scan JSON from `$BaselinePath`
  - Returns `$null` if file doesn't exist (first scan = no baseline)
  - Validates JSON structure matches expected schema (Checks + Metadata)
  - Same pattern as `Import-AuthBaseline` in `Test-AgentAuthConfiguration.ps1`

- `Compare-AccessBaseline` function:
  - Accepts current checks array and previous baseline object
  - Builds lookup by composite key: `"$CheckId|$Context|$Zone"`
  - Detects drift types:
    - `PolicyChanged` — agent access policy setting changed (e.g., AllAgents → OrgOnly)
    - `StatusChanged` — check result changed (Pass→Fail, Fail→Pass)
    - `NewCheck` — check exists in current but not baseline (new zone added)
    - `GroupMembershipChanged` — exclusion group member count changed
  - Returns array of drift objects:
    ```
    CheckId, Context, Zone, DriftType, PreviousValue, CurrentValue,
    PreviousStatus, CurrentStatus, DetectedAt
    ```

- Wire up in main script flow:
  1. After all checks complete
  2. If `$BaselinePath` provided and file exists, load and compare
  3. Add `Drifts` property to results object
  4. Include drift count in console summary
  5. Auto-save current results as new baseline

**Acceptance criteria:**
- First scan (no baseline) produces empty drift array with informational message
- Subsequent scan with changes produces accurate drift records
- Composite key handles multiple zones for same check

### Task 2: SHA-256 Evidence Hashing Integration

**Action:** Ensure per-check evidence hashing and overall integrity hash work correctly.

**Details:**
- Per-check evidence hash: computed in New-AccessCheckResult when EvidenceJson provided
- Overall integrity hash: computed after results aggregation when -IncludeEvidence specified
- Pattern identical to Test-AgentAuthConfiguration.ps1:
  ```powershell
  if ($IncludeEvidence) {
      $resultsJson = $results | ConvertTo-Json -Depth 10 -Compress
      $hashBytes = [System.Security.Cryptography.SHA256]::Create().ComputeHash(
          [System.Text.Encoding]::UTF8.GetBytes($resultsJson)
      )
      $results.Metadata.IntegrityHash = [BitConverter]::ToString($hashBytes) -replace '-'
  }
  ```

**Acceptance criteria:**
- Each check result has `EvidenceHash` when evidence available
- Overall `IntegrityHash` computed when `-IncludeEvidence` specified
- Hash format: uppercase hex without dashes

### Task 3: Teams Adaptive Card Template

**Action:** Create `src/adaptive-card-zone-access-alert.json` for Teams webhook notifications.

**Details:**
- Follow established pattern from `src/adaptive-card-uasd-alert.json`
- Adaptive Card schema version 1.4
- Template variables:
  - `${OverallStatus}` — Passed/GapsFound
  - `${SeverityStyle}` — good/attention/warning based on status
  - `${SeverityBadge}` — emoji badge
  - `${SeverityColor}` — color mapping
  - `${ScannedAt}` — scan timestamp
  - `${TotalChecks}`, `${PassedCount}`, `${FailedCount}`, `${WarningCount}`
  - `${DriftCount}` — number of drifts detected
  - `${Findings}` — array of check results for detail table
- Sections:
  1. Header with alert title and severity
  2. Summary metrics (checks, pass, fail, drift)
  3. Findings table showing failed/warning checks
  4. Action buttons: "View in M365 Admin Center", "View Full Report"
- Card title: "[ALERT] Zone Agent Access Policy — ${OverallStatus}"

**Acceptance criteria:**
- Valid Adaptive Card JSON
- Template variables match script output schema
- Follows established pattern from UASD alert card
