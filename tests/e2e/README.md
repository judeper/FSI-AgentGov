# E2E Test Suite

End-to-end tests for the FSI-AgentGov assessment SPA, driven by [Playwright](https://playwright.dev/). The suite boots the documentation site via `mkdocs build` + `python -m http.server`, then exercises the assessment flow with persona-driven fixtures.

## Quickstart

```bash
# 1. Install JS dependencies (Playwright + axe + helpers)
npm install

# 2. One-time browser binary download (Chromium only at this phase)
npx playwright install chromium

# 3. Run the smoke set (fast, gating)
npm run test:e2e:smoke

# 4. Run the full suite
npm run test:e2e

# 5. Headed/debug mode for local development
npm run test:e2e:headed
```

The Playwright config (`playwright.config.mjs`) launches its own web server on `127.0.0.1:8765` (override via `PW_PORT`). On Windows the launcher uses `cmd /C`; on macOS/Linux it uses `bash -c`. If `python` is not on PATH on Windows, substitute `py -3` in the `webServer.command`.

## Persona Fixtures

Persona JSON lives in `tests/e2e/fixtures/personas/`. Use `loadPersona(name)` from `_harness.mjs`. The current set is intentionally minimal — full state is regenerated by `scripts/update-personas.mjs` (lands with the smoke-set PR).

| Persona | When to use |
|---------|-------------|
| `minimal-ciso` | Zone 1-only smoke flow; small surface area, fast |
| `full-cco` | All 3 zones, all 78 controls — regression for scoring + completeness |
| `consultant-multi` | Multi-assessment switching, save/restore, isolation between clients |
| `edge-empty` | Scoped but no responses; verifies empty-state UI and exports |
| `edge-malicious` | XSS, formula-injection, unicode bidi/zero-width — sanitizer regression |

## Snapshot Update Workflow

Visual + DOM snapshots live in `tests/e2e/__snapshots__/` and are tracked in git. **Baselines are Linux-only** to avoid font/anti-aliasing churn between contributor OSes. Snapshots are regenerated exclusively via the manual `e2e-snapshots` GitHub Actions workflow (`workflow_dispatch`); local `--update-snapshots` runs are for debugging and must not be committed from non-Linux hosts.

If a snapshot legitimately needs to change, dispatch the workflow against your branch, review the resulting commit, and merge alongside the change that caused it. Snapshot diffs (`*-diff.png`, `*-actual.png`) are gitignored.

## Supported Browser Baseline

Chromium pinned via `@playwright/test@1.59.1` is the only browser exercised in this phase. Firefox and WebKit projects will be added in a later PR per Theme 5. The browser binary is downloaded by `npx playwright install chromium`; CI uses the pinned `mcr.microsoft.com/playwright` container.

We deliberately do **not** test against system Chrome/Edge — the bundled Chromium revision is what we gate on.

## Selector Policy

All specs MUST follow this priority order when locating SPA elements:

1. **Role + accessible name** — `page.getByRole('button', { name: 'View Results' })`, `page.getByLabel('Organization Name')`. Doubles as light a11y coverage and survives CSS churn.
2. **Existing structural hooks the SPA already emits** — `[data-control-id]` on each Phase 1 card, `#assessment-app` for the SPA root, `#ag-print-styles` for the injected print stylesheet, `#ag-select-institution-type` for the labelled scoping select.
3. **Add a `data-testid` only when no labelled affordance exists.** Add it to the render function in `docs/javascripts/assessment-app.js` (additive only — never refactor logic to add a hook). Document the new hook in this README.

Forbidden: `nth-child` chains, brittle `:has-text()` matches on long bodies of copy, full DOM `xpath` walks. The harness uses one bounded `xpath=ancestor::` walk to expand collapsed pillars on Phase 1; copy that pattern only when no role-based alternative exists.

The harness (`tests/e2e/_harness.mjs`) implements `seedScoping` and `clickThroughPhase1` against this policy. Subsequent regression specs should reuse those helpers rather than re-deriving selectors.

## Allowlist Policy

The Content Security Policy allowlist for the assessment SPA is declared in `tests/e2e/fixtures/csp-allowed.json`. Each loosening (an entry beyond `'self'`) must include a `reason` and `expiresISO` so the allowlist can be reviewed and pruned over time.

To add a loosening, edit `csp-allowed.json` and open a PR that explains why the directive cannot be met from `'self'`. The CSP regression spec (lands with the smoke set) reads this file as the source of truth — anything observed in the SPA but not in the allowlist fails the test.

### Axe rule exclusions

The `19-a11y-axe-baseline.spec.mjs` smoke gate runs under WCAG 2.1 A + AA tags and asserts zero `serious` or `critical` violations. It explicitly disables the following rules:

| Rule | Reason | Re-enable when |
|------|--------|----------------|
| `color-contrast` | mkdocs-material theme contrast is out of scope for this PR; many findings are inherited from the documentation theme rather than SPA code. | A dedicated theme-contrast pass lands. |

Full violations JSON (including non-blocking `minor`/`moderate` findings) is written to `test-results/axe/<screen>.json` on every run and uploaded as a CI artifact on failure.

## Declared Untestable Items

The following are explicitly out of scope for this suite:

- **Edge-specific download filename behavior** — Playwright drives Chromium only at this phase; Edge's `Save As` dialog interception is not testable headlessly.
- **OS-native print-to-PDF** — covered by the in-app PDF export path instead.
- **Real OAuth/SSO** — the SPA is fully client-side; no live identity provider is exercised.
- **Service worker offline mode in CI** — flaky under containerized network shaping; covered by manual smoke before each release.

## Tag Conventions

Specs use Playwright `--grep` tags in their titles:

- `@smoke` — fast, deterministic, gating on every PR. Must run in under 60 s total.
- `@slow` — full-persona walkthroughs, regression of all 78 controls. Nightly + pre-release.
- `@flaky-known` — quarantined while a fix is in flight. Tracked via a linked issue in the spec docstring; never gating.

## CI Gating

The `e2e-smoke` job is a **Required Status Check** on the `main` branch. It runs `npm run test:e2e:smoke` against the Playwright-pinned Chromium in the official container. The full `e2e` job runs nightly and on `release/*` branches.

Retry strategy: 2 retries in CI (`retries: isCI ? 2 : 0`). A flaky test that passes on retry is reported but does not fail the job. Persistent failures upload Playwright traces, screenshots, and videos to the `playwright-report/` artifact on the workflow run.

To rerun a failed check, use the GitHub UI's "Re-run failed jobs" action; the trace artifact is the first thing to inspect.

## Maintenance Runbook

- **`FRAMEWORK_VERSION` bump** — regenerate persona fixtures via `node scripts/update-personas.mjs` (lands with smoke-set PR), commit the diff alongside the version bump, and re-run `npm run test:e2e` locally before merging.
- **CSP allowlist review** — quarterly. Open `csp-allowed.json`, drop any loosening whose `expiresISO` is in the past, and verify the SPA still loads cleanly.
- **Snapshot baselines** — refresh via the `e2e-snapshots` workflow whenever an intentional UI change is merged. Stale snapshots block PRs.
- **Persona drift** — if the SPA's scoping shape changes (new field on the welcome screen), update each persona JSON's `scoping` block and bump the regen script.
