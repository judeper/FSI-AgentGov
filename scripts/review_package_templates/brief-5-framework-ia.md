# Brief 5 — Framework & Information Architecture (global navigation)

{{PROVENANCE}}

## Your task
Review the **framework/conceptual layer AND the whole site's information architecture**
(how everything is organised and navigated) and propose improvements. This is the
**structure** lens — distinct from Brief 7 (UX & Adoption), which owns experience,
engagement, and "is it worth using". Some overlap is fine; focus on organisation.

## Where it is in the package
- `00-SITE-MAP.md` — **your primary artifact**: the full navigation tree / IA.
- `area-5-framework-and-ia.md` — the framework docs (executive summary, governance
  fundamentals, zones & tiers, lifecycle, regulatory framework, operating model, cadence,
  adoption roadmap).
- The whole `_rendered-site/` to navigate the real structure.
- Context: `00-START-HERE.md`.

## Lens for this area (plus the shared rubric)
- **Top-level IA** — are the primary sections (Getting Started, Framework, Controls,
  Playbooks, Assessment, Reference, Downloads) the right buckets, ordered well, labelled
  clearly for the audience?
- **Depth & findability** — is anything buried? Too many nav levels? Orphan pages?
- **The 3-layer model** (Framework → Controls → Playbooks) — is it legible to a user, or
  only to the authors? Do the layers connect (cross-links, "next step")?
- **Conceptual clarity** — do the framework docs explain the *why* before the *how*, at the
  right altitude for an admin (not a developer)?
- **Navigation mechanics** — search, breadcrumbs, in-page TOC, cross-references.

Use `briefs/REVIEWER-RUBRIC.md`; return findings in `briefs/RESPONSE-TEMPLATE.md`
(ID prefix `IA-`). Cite specific nav nodes/pages. No repository access needed.
