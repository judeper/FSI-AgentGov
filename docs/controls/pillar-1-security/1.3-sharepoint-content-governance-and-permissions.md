# Control 1.3: SharePoint Content Governance and Permissions

**Control ID:** 1.3<br>
**Pillar:** Security<br>
**Regulatory Reference:** GLBA 501(b), SEC Reg S-P, FINRA 4511, SOX 302/404<br>
**Last UI Verified:** January 2026<br>
**Governance Levels:** Baseline / Recommended / Regulated<br>
**Last Verified:** 2026-02-03

---

## Objective

Ensure AI agents only access authorized SharePoint content through proper permission governance, sensitivity labels, and access controls to prevent inadvertent exposure of sensitive customer information.

---

## Why This Matters for FSI

- **GLBA 501(b):** Requires safeguards for customer NPI stored in SharePoint
- **SEC Reg S-P (2024 Amendments):** Mandates privacy safeguards for customer records in document libraries; 2024 amendments require written incident response plans, service provider oversight, and 30-day breach notification for unauthorized access to customer information
- **FINRA 4511:** Requires books and records with appropriate access controls and audit trails
- **FINRA 25-07:** Extends supervisory obligations to AI workflows; requires logging and auditability of AI-retrieved content from SharePoint knowledge sources
- **SOX 302/404:** Requires segregation of duties for financial document access
- **NIST SP 800-53 AC-3/AC-6:** Access enforcement and least privilege map directly to SharePoint permission governance
- **Oversharing Prevention:** Stops accidental exposure of sensitive data through AI responses

## Control Description

SharePoint is a primary knowledge source for Copilot Studio agents and the default grounding source for Microsoft 365 Copilot (Business Chat). This control establishes governance over SharePoint content to ensure agents access only authorized data. Note that Microsoft 365 Copilot accesses all SharePoint content the user has permissions to, regardless of explicit knowledge source configuration, creating a broader governance surface than Copilot Studio agents with explicit knowledge sources. Copilot Studio agents use the requesting user's Microsoft Entra ID authentication and responses are security-trimmed per user permissions. The control implements:

1. **Tenant-Level Sharing Controls** - Restrict external sharing organization-wide
2. **Site-Level Permissions** - Configure least-privilege access for agent knowledge sources
3. **Sensitivity Labels** - Apply classification labels to sites and document libraries
4. **SharePoint Advanced Management (SAM) controls** - Restricted Access Control (RAC) for hard access limitation, Restricted Content Discovery (RCD) for search/Copilot discovery suppression, and Data Access Governance reports for oversharing analysis
5. **Access Reviews** - Periodic recertification of permissions

Properly configured SharePoint governance restricts agents from accessing or returning sensitive customer information beyond their authorized scope.

---

## Key Configuration Points

- Configure tenant-level sharing to "Only people in your organization" for FSI
- Remove "Everyone" and "Everyone except external users" groups from agent knowledge sites
- Apply sensitivity labels to sites (container labels for privacy and sharing controls) and configure library default labels (for file-level protection)
- Enable SharePoint Advanced Management controls: RAC for access restriction, RCD for Copilot/search discovery suppression, and Data Access Governance reports for oversharing analysis — see [Control 4.1](../pillar-4-sharepoint/4.1-sharepoint-information-access-governance-iag-restricted-content-discovery.md)
- Note: SAM features require either a Microsoft 365 Copilot license or standalone SharePoint Advanced Management license
- Configure quarterly access reviews for agent knowledge site permissions
- Create dedicated sites for agent knowledge with restricted permissions

## Zone-Specific Requirements

| Zone | Requirement | Rationale |
|------|-------------|-----------|
| **Zone 1** (Personal) | Site owner discretion; annual access reviews; labels recommended | Low risk, personal data scope |
| **Zone 2** (Team) | Partner domains only; semi-annual reviews; labels required (Internal+) | Shared data requires accountability |
| **Zone 3** (Enterprise) | No external sharing; quarterly reviews; labels required (Confidential+); RAC and RCD enabled; agent-retrieved content retained per FINRA 4511/SEC 17a-4 (minimum 6 years); e-discovery hold awareness for knowledge sites | Customer-facing, regulatory examination risk |

## Verification Criteria

Confirm control effectiveness by verifying:

1. Tenant-level sharing is restricted to "Only people in your organization" (or more restrictive)
2. Agent knowledge sites have no "Everyone" or "Everyone except external users" groups
3. Sensitivity labels are applied to all agent data source libraries
4. Agent cannot retrieve content from excluded/unauthorized sites
5. Access reviews are scheduled and notifications are being sent
