## Objective

Configure Sensitive Information Types (SITs) for automatic detection and classification of financial data including customer NPI (SSN, account numbers), regulatory identifiers (CRD, CUSIP), and material non-public information (MNPI) to enable DLP policies and AI data governance.

## Control Description

This control establishes Sensitive Information Types and adjacent classification primitives as the foundation of data classification in Microsoft 365. Microsoft Purview treats these as **distinct detection paths**, not a single feature, and FSI deployments must reason about them separately:

1. **Built-in pattern SITs** — Microsoft-provided regex/checksum/proximity detectors (e.g., U.S. Social Security Number, Credit Card Number with Luhn, U.S. Bank Account Number, ABA Routing Number, ITIN, CUSIP). Verify names and availability in the current catalog; do not assume EIN is a built-in detector. Entitlement depends on the consuming feature.
2. **Custom pattern SITs** — Organization-specific detectors built from primary elements, supporting elements, regex (with optional validators / checksums), keyword lists or dictionaries, proximity, and Low / Medium / High confidence levels. Examples relevant to FSI include internal account-number formats, **FINRA CRD Number (custom — no checksum exists)**, and **MNPI indicator** keyword-dictionary SITs.
3. **Named Entity Recognition (NER) SITs** — Bundled and unbundled named-entity detectors (e.g., "All full names", "All physical addresses", medical conditions). NER is used inside DLP, sensitivity labels, retention, eDiscovery, and DSPM-for-AI signals. Requires Microsoft 365 E5 / E5 Compliance entitlement.
4. **Trainable classifiers** — ML-based complement to pattern SITs. Useful where regex cannot reasonably express intent (e.g., MNPI, source code, customer complaints). See the FSI governance gate below before relying on a trainable classifier as a primary control.
5. **Exact Data Match (EDM)** — Detection against a one-way salted hash of customer master data uploaded via the EDM Upload Agent. Required where deterministic match against actual customer records is needed (e.g., specific account numbers, beneficiary records).
6. **Keyword dictionaries** — Reusable term lists referenced by SITs (e.g., competitor names, restricted entities, project codenames).

These primitives are then consumed by DLP (including DLP for Microsoft 365 Copilot), sensitivity labels, retention policies, Communication Compliance, eDiscovery, and **DSPM for AI** to deliver the protections required under FINRA 4511, SEC Reg S-P, GLBA 501(b), and FINRA RN 24-09.

### Trainable Classifier — FSI Governance Gate

Before relying on a trainable classifier (built-in or custom) as a primary detection control:

- Confirm the classifier is **GA**, not Preview, for the targeted workload.
- Sample and document training-data provenance, quality, and review per **OCC Bulletin 2026-13 (formerly OCC 2011-12)** / **Fed SR 26-2 (formerly SR 11-7)** model-risk expectations.
- Do **not** use a trainable classifier as the **sole** evidence for record-classification under SEC 17a-4 / FINRA 4511 — pair with a deterministic SIT or sensitivity label so the auditable record has a reproducible match.
- Re-validate accuracy on a defined cadence (recommended quarterly for Zone 3) and capture the validation in the SIT/classifier evidence file.
- Custom trainable classifiers are **English-only** at GA — confirm regional language coverage before scoping multilingual customer datasets.

### Copilot / Agent Integration

SITs do not protect Microsoft 365 Copilot or agent grounding directly — they are the **detection primitive** that feeds the policies that do:

1. **DLP for Microsoft 365 Copilot** — The **Microsoft 365 Copilot and Copilot Chat** location uses built-in/custom SIT conditions on typed prompt text to restrict prompt processing (preview, rollout dependent) or external web searches. It does not inspect grounding files or file uploads for those SIT conditions. Required for FINRA RN 24-09 / Rule 3110 governance of AI data inputs. Verify feature availability at deployment.
2. **Sensitivity labels** — SIT-driven auto-labeling can label source files/emails. A separate Copilot-location DLP rule with a **Sensitivity labels** condition excludes labeled content from processing; the label alone does not have an "exclude from Copilot" switch. Excluded items can remain in citations.
3. **DSPM for AI** — Surfaces "sensitive data shared with Copilot" telemetry using the same SITs. Tuning a SIT in this control directly affects DSPM-for-AI signal quality. Note that Microsoft is consolidating the classic AI Hub experience into a unified DSPM experience — reference the capability generically rather than hard-coding a portal name.
4. **Agent grounding (Microsoft Copilot Studio, Microsoft 365 Agents)** — Verify the particular agent, host, identity, and data path. A governed Power Platform environment does not establish automatic inheritance of every Microsoft 365 Copilot DLP protection; connector/data policies and supported Purview integration require separate testing.

A SIT false negative (e.g., SSN not detected) can result in customer NPI surfaced through Copilot output. Treat such failures as **reportable events** — see the Incident Handling cross-reference in Related Controls and the §1 FSI Incident Handling section of the troubleshooting playbook.

## Key Configuration Points

- Review available financial / PII SITs in **Purview > Information Protection > Classifiers > Sensitive info types**: SSN, Credit Card Number, U.S. Bank Account Number, ABA Routing Number, ITIN, CUSIP, and entitled named-entity SITs. Confirm any EIN detector's actual publisher/definition; built-in SITs do not need a separate enable switch.
- **Endpoint DLP prerequisite for bundled SITs:** To use a **bundled** SIT (such as the bundled NER SITs above) in an **endpoint DLP** policy, first enable **Advanced classification scanning and protection** in Purview endpoint DLP settings. This requirement is specific to the bundled-SIT + endpoint-DLP combination ([Microsoft Learn — Learn about SITs](https://learn.microsoft.com/en-us/purview/sit-sensitive-information-type-learn-about)); without it, bundled-SIT matches are not evaluated on onboarded devices, which can cause silent endpoint-DLP non-enforcement.
- Create custom pattern SITs for internal account-number formats — use scoped regex with appropriate boundaries (not positional `^`/`$` anchors), supporting evidence, and proximity. Microsoft maps ≤65 to Low, 66–75 to Medium, and 76–100 to High; the available patterns/evidence remain SIT-specific.
- Create the **FINRA CRD Number** SIT as a custom SIT — CRD numbers have no published checksum, so confidence tuning relies entirely on regex precision and keyword proximity. Set initial confidence to **Medium**, monitor false positives weekly during pilot, and never rely on CRD detection alone for blocking actions.
- Build the **MNPI indicator** SIT from a curated keyword dictionary plus deal-codename / project-name supporting elements; pair it with a trainable classifier only after the FSI Governance Gate above is met.
- Configure **EDM** for high-value customer master data: define schema, hash/upload with the EDM Upload Agent, schedule the firm's refresh cadence, verify `/GetDataStore` and `/GetSession`, then test a known synthetic match. Do not use an assumed rule-package **Active** state as proof of upload/indexing. The [schema guide](https://learn.microsoft.com/en-us/purview/sit-get-started-exact-data-match-create-schema) specifies at most ten searchable fields in its wizard, but still describes five in its manual XML steps; verify the selected workflow rather than asserting 32.
- Set DLP / label confidence (Low / Medium / High) per use case and validated patterns. High is not available for every SIT: the U.S. Bank Account Number definition has Medium only, no ABA requirement, and no checksum.
- Test every SIT in **Test pane → Content Explorer → DLP simulation → DLP-for-Copilot simulation** before promoting to enforce. Capture seeded synthetic test data and the resulting matches as evidence (do not seed real customer NPI into test corpora).
- Maintain a **false-positive / false-negative review cadence** (recommended monthly for Zone 3) and route findings into the SIT evidence file.

## Zone-Specific Requirements


!!! info "Zone cross-reference"
    **Baseline** = Zone 1 (Personal Productivity) · **Recommended** = Zone 2 (Team Collaboration) · **Regulated** = Zone 3 (Enterprise Managed). Zone requirements below correspond to the Governance Level in the control header.

| Zone | Requirement | Rationale |
|------|-------------|-----------|
| **Zone 1** (Personal) | Built-in SITs only; alert-only DLP; **High** confidence threshold | Low risk, awareness-focused |
| **Zone 2** (Team) | Built-in + foundational custom SITs; alert and educate; **Medium–High** confidence | Team data requires classification |
| **Zone 3** (Enterprise) | Full SIT library + EDM + NER (where licensed) + governed trainable classifiers; **block** on **High** confidence; **alert** on **Medium**; DLP-for-Copilot and DSPM-for-AI integration required | Customer-facing data requires comprehensive detection and AI-grounding controls |

## Verification Criteria

Confirm control effectiveness by verifying:

1. In-scope financial & PII SITs appear in **Purview > Information Protection > Classifiers > Sensitive info types** with the expected publisher; any custom EIN detector is identified as custom.
2. Custom SITs (e.g., FINRA CRD, internal account formats, MNPI keyword-dictionary SIT) appear with the documented publisher and confidence levels.
3. Seeded synthetic test document is detected in **Content Explorer** within the documented telemetry window (typically up to 24 hours; verify against your tenant baseline rather than assuming a fixed SLA).
4. Test DLP rule fires on the seeded SIT match across Exchange, SharePoint, OneDrive, and Teams workloads.
5. **DLP-for-Copilot policy** separately restricts supported typed-prompt SIT matches and excludes labeled grounding files/emails through a sensitivity-label rule. Capture both positive and negative runtime tests; uploaded-file contents and arbitrary agent connectors are not covered by the prompt SIT condition.
6. **DSPM for AI** dashboard registers the SIT detection under "Sensitive data shared with Copilot" telemetry within the documented window.
7. EDM upload/session completion is captured; refresh meets the agreed cadence (typically daily); the specific EDM SIT, not only its primary SIT, detects the synthetic record after the documented test-readiness window.
8. NER-backed SITs (e.g., "All full names") return matches on a seeded NER test document (E5 license required).
9. False-positive / false-negative review log maintained on a defined cadence (recommended monthly for Zone 3); findings routed back into SIT tuning and DLP policy adjustments.
10. Trainable classifiers in use have current model-risk validation evidence per OCC Bulletin 2026-13 (formerly OCC 2011-12) / Fed SR 26-2 (formerly SR 11-7) if they drive a primary control.
